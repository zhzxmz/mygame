# World State Design Specification V1

> **文档性质**：**设计规范（Design Specification）**。本文档只定义**规则与边界**，不含任何代码、不含任何接口/类型草案，不接入 Runtime，不实现生成逻辑。
> 落地形态（类型、接口、参数结构、阶段划分）必须由后续独立的**实现规范**（例如 `WorldState_Implementation.md`）定义。
>
> **适用范围**：世界状态层（World State）——一个区域"**拥有哪些环境参数**"以及"**这些参数从哪来、如何决定其它系统能做什么**"。
>
> **一句话定位**：
> Geology 规范回答"**这个坐标为什么是这种地形/材料**"；
> 本文档回答"**这个区域处于什么世界状态，因此什么被允许出现**"。
>
> **上游规范（本文档不得与其冲突）**：
> * `Specifications/World/VoxelWorld_Core.md` —— 世界真值（Voxel Data）、体素状态集合（冻结为 Air/Grass/Dirt/Stone）、Chunk 数据契约；
> * `Specifications/World/WorldGeneration_Core.md` —— 生成契约（Seed + ChunkCoordinate → VoxelChunk、确定性、Chunk 计算独立、Stage 划分）；
> * `Specifications/World/WorldGeneration_Geology.md` —— 地质规则（密度优先级链、地层、洞穴、矿藏属性层、群系接口）；
> * `Specifications/World/WorldGeneration_Geology_Implementation.md` —— 地质访问层（世界坐标采样、新增而非替换）；
> * `Specifications/World/WorldGeneration_Geology_Runtime_Implementation.md` —— 地质生成器落地（V1 群系只影响地表材料）；
> * `Specifications/World/VoxelWorld_Runtime.md`、`VoxelWorld_Runtime_Core.md`、`VoxelWorld_Runtime_Interface.md` —— 调度 / 生命周期 / 抽象边界；
> * `Specifications/World/VoxelWorld_Mesh.md`、`VoxelWorld_View.md`、`VoxelWorld_Mining.md`、`VoxelWorld_Architecture.md`；
> * `Specifications/ArchitectureDecisionWorldSpaceEntity.txt`（ADR-001）—— World / Space / Entity 的概念边界。
>
> **冲突时的优先级**：**真值**以 `VoxelWorld_Core.md` 为准；**生成契约与 stage 划分**以 `WorldGeneration_Core.md` 为准；
> **具体地质规则（层/洞/矿/群系接口）**以 `WorldGeneration_Geology*.md` 为准；
> **调度**以 `VoxelWorld_Runtime*.md` 为准；**环境参数与力量（魔力/圣/腐化）的规则**以本文档为准。
>
> **零修改前提（硬性）**：本文档的所有内容都必须能在**不修改** VoxelCore、WorldGeneration 既有实现、
> 地质层 9 个实现文件、Mesh、View、Runtime Core、Streaming、Bootstrap 的前提下落地为**新增层 / 新增文件**。
> 任何"必须改 VoxelType、必须改 VoxelCore、必须改被冻结的地质实现"的世界状态想法，一律不得进入 V1。
>
> **V1 状态**：本文档定义环境参数与世界状态的设计规则，不直接实现代码或生成世界数据。运行时接线状态应查看 `Specifications/World/WorldParameter_Source_Contract.md` 的实现对应表及当前代码。

> **架构冲突提醒（必须先处理）**：本文件的早期上游列表引用 `VoxelWorld_Core.md`，其中冻结了离散 `Air/Grass/Dirt/Stone` 类型；而 `WorldGeneration_Geology.md` 使用连续 `Density` / `Material` 规则。两套表示不能未经解释就同时作为同一地形实现的最高权威。涉及地形真值、材料表示或 Voxel 输出的实现任务，必须先核对当前地形代码和对应实现契约；不得仅凭本文件旧上游列表恢复离散类型假设。旧 `VoxelWorld_Architecture.md` 已标记为历史概念文档，当前地形高层架构入口为 `Specifications/World/Terrain_Editing_Architecture.md`。

## 1. 世界状态模型

### 1.1 世界状态不是物体

世界状态描述的是"**这片区域的环境是什么样**"，**不是**"这片区域里有什么东西"。

| 世界状态（本文档） | 物体 / 对象（不属于本文档） |
|---|---|
| `MagicDensity` 高 | 一棵魔法树、一只魔法生物、一块魔法水晶 |
| `CorruptionInfluence` 高 | 一具腐化尸体、一个祭坛、一片腐化植被 |
| `Fertility` 高 | 一株作物、一群动物 |
| `Ocean = true` | 一条鱼、一艘船、一处珊瑚 |

**核心纪律：世界状态只产生"资格 / 条件"，不产生对象。**

```
MagicDensity 高
      ↓  （允许）
允许魔法植物出现
      ↓  （允许）
允许魔法生物生存
      ↓  （允许）
允许魔法资源生成
```

* 上面每一条都是**资格声明（eligibility）**，不是生成指令；
* 真正的"生成/放置/生物行为/资源产出"属于**未来的 Entity / Vegetation / 资源系统**（ADR-001：Entity 不属于 Chunk 所有权体系）；
* 因此本文档**不定义任何 Entity、不定义任何生成数量、不定义任何生成时机**。

### 1.2 Region（区域）的定义

**定义**：Region 是**一段可查询的空间范围**，其成员资格由世界状态的判定结果决定，而不是由存储容器决定。

```
Region(R) = { 世界坐标 p | Classify(WorldState(p)) == R }
```

硬性规则：

| # | 规则 | 理由 |
|---|---|---|
| **R1** | Region **不是**容器、**不是**存档单位、**不是**跨帧存活的状态 | 与 `WorldGeneration_Geology.md` §2.1 一致：世界是连续函数，Chunk 只是采样窗口 |
| **R2** | Region **必须可从任意世界坐标独立求值**（不需要先加载邻域，不需要遍历全世界） | 保持 Chunk 计算独立（`WorldGeneration_Core.md` §6）与流式局部性 |
| **R3** | Region 的边界**不得依赖 Chunk 划分、加载顺序、帧序、时间** | 与地质规范 §2.3（F1–F4）同一条纪律 |
| **R4** | Region **不得**被用来反向定义世界状态 | 见 §1.5（倒因为果禁令） |
| **R5** | 区域是**水平范围优先**的概念：区域参数以列为基本单位；能量参数允许是三维场（§3） | 与既有"列高度 + 体素属性层"模型一致 |

> **关系澄清**：Chunk 是**管理单位**（ADR-001），Region 是**状态分类结果**。
> 两者互不隶属：一个 Region 可以跨多个 Chunk，一个 Chunk 可以包含多个 Region。

### 1.3 V1 环境参数总表

**第一版包含 8 个参数，分两层。**

#### Physical（物理环境）

| 参数 | 类型 / 定义域 | 维度 | 连续性 | V1 来源 |
|---|---|---|---|---|
| **Temperature** | 标量 `[0,1]` | 列 `(x,z)` | 连续 | 由世界规则（纬度/海拔衰减/噪声）确定，列属性 |
| **Moisture** | 标量 `[0,1]` | 列 `(x,z)` | 连续 | 列属性（不是三维噪声） |
| **Elevation** | 世界坐标高度 `y`（体素单位） | 列 `(x,z)` | 规则连续 | **必须复用既有 `SurfaceHeight`（`HeightFunction`）**，不得另立高度场 |
| **Fertility** | 标量 `[0,1]` | 列 `(x,z)` | 连续 | 由 `SoilDepth` / `Moisture` / `Temperature` 派生的**属性** |
| **Ocean** | 布尔 | 列 `(x,z)` | 阈值阶跃（边界唯一） | **派生**：`Elevation < SeaLevel`，不是独立噪声 |

#### Energy（世界力量）

| 参数 | 类型 / 定义域 | 维度 | 连续性 | V1 来源 |
|---|---|---|---|---|
| **MagicDensity** | 标量 `[0,1]` | 体 `(x,y,z)` | 连续（含边界） | 静态场：`Base + Σ SourcesContribution`（§3） |
| **HolyInfluence** | 标量 `[0,1]` | 体 `(x,y,z)` | 连续（含边界） | 静态场：圣性来源叠加（§4） |
| **CorruptionInfluence** | 标量 `[0,1]` | 体 `(x,y,z)` | 连续（含边界） | 静态场：腐化来源叠加（§4） |

**通用规则**

1. **全部归一化到 `[0,1]`**（`Elevation` 例外，它是世界坐标高度）；越界一律**钳制（clamp）**，不得溢出；
2. **全部是世界坐标纯函数**：`f(Seed, 参数, 世界坐标)` ⇒ 结果唯一（`WorldGeneration_Core.md` §2）；
3. **不得存在隐藏全局状态**：所有影响结果的量必须是显式参数；
4. 三维能量场在需要"列判定"时，**以地表点取值**：`Energy@surface(x,z) = Energy(x, SurfaceHeight(x,z), z)`（唯一允许的降维方式）；
5. **属性语义**：`Fertility` 与三个 Energy 参数在 V1 中是**属性层（attribute layer）**，
   **不改变** `Density` / `Material` / `CaveDensity` / `DepositZone`（与地质规范 §6.1「矿藏是属性层」同一纪律）。

### 1.4 "参数高"意味着什么

| 参数状态 | 允许（资格声明） | 不允许（本文档明令禁止） |
|---|---|---|
| `MagicDensity` 高 | 魔法植物 **可以**存在；魔法生物 **可以**生存；魔法资源 **可以**生成 | 直接生成魔法树 / 生成魔法生物 / 把体素变成"魔法方块" |
| `CorruptionInfluence` 高 | 腐化生态 **可以**出现；腐化遗迹 **可以**归因 | 传播腐化 / 改变体素类型 / 杀死或转化对象 |
| `HolyInfluence` 高 | 圣性生态 **可以**出现；圣物地点 **可以**归因 | 净化腐化 / 改变已生成世界 / 影响调度 |
| `Fertility` 高 | 植被 **可以**繁茂；文明 **可以**选择农业 | 直接生成植被 / 改变土壤深度（V1） |
| `Ocean = true` | 海洋群系成立；陆地遗迹 **被排除** | 直接生成水方块 / 生成海洋生物 |

### 1.5 禁止倒因为果（本规范的核心纪律）

**禁止**：

```
"因为这里是魔法森林，所以魔力高"
"因为这里有腐化植被，所以腐化高"
"因为这里有一座圣殿，所以圣性高"
```

**必须**：

```
魔力源  →  魔力环境  →  特殊生态
（原因）    （世界状态）    （结果）
```

| # | 禁令 | 理由 |
|---|---|---|
| **C1** | 不得用**生物群系 / 生态 / 遗迹 / 对象**的存在反推环境参数 | 循环解释不可验证、不可复现、顺序依赖 |
| **C2** | 不得用"结果"作为"原因"的输入（含隐式双向依赖） | 违反世界坐标纯函数（§1.3 规则 2） |
| **C3** | 不得在参数求值过程中读取"已生成内容" | 会引入加载顺序依赖（地质规范 §2.3 F3） |
| **C4** | 每个"特殊生态允许"的判定都必须能**完整回溯到某个原因**（附录 C） | 可解释性是硬性验收项（WS8） |

## 2. 魔力系统设计

### 2.1 因果方向（唯一允许的方向）

```
MagicSource（魔力源，世界事实）
      ↓
MagicDensity（魔力环境，世界状态参数）
      ↓
特殊生态的"资格"（魔法植物 / 魔法生物 / 魔法资源）
      ↓
对象（由未来 Entity / Vegetation / 资源系统生成）
```

**只有从上往下的箭头存在。反向箭头一律禁止（§1.5）。**

### 2.2 MagicDensity 的可能来源（6 类）

| 类型 | 含义 | 典型位置语义 | 强度/半径倾向 |
|---|---|---|---|
| **AncientMagicSite** | 远古魔力场址 | 地形自然形成的世界位置 | 大半径、低强度 |
| **MagicCrystalDeposit** | 魔法水晶矿脉 | 与既有 `DepositZone`（属性层）对应的资源区域 | 中半径、中强度 |
| **AncientBattle** | 古战场残留 | 历史事件位置（§6） | 中/大半径、中强度 |
| **PowerfulCreatureDeath** | 强大生物死亡 | 历史事件位置（§6） | 小半径、高强度 |
| **MagicSeal** | 封印 | 人工/远古构造位置 | 小半径、极高强度 |
| **ArtificialMagicDevice** | 人造魔法装置 | 文明活动范围（§6） | 小/中半径、可变强度 |

**规则**

1. 上述 6 类是**规则的枚举**，不是实现清单；V1 只设计，不生成任何源（§8）；
2. 每类源的世界分布必须是**确定性纯函数**（Seed + 世界规则 + 显式参数），不得运行时随机；
3. 源本身**不是 Entity**：它没有生命周期、没有行为、不需要存档对象化；
4. 若未来某个源需要表现为**可见对象**（例如魔法水晶），那是 **Entity 系统**的事，
   且该 Entity 通过**空间位置**关联到源记录（ADR-001），**不得**把源的场值写进 Voxel 数据。

### 2.3 MagicSource 的属性

每个魔力源具有且仅有以下 4 个必需属性：

| 属性 | 含义 | 要求 |
|---|---|---|
| **Position** | 源的世界坐标位置 | 世界坐标（三维）；不得是 Chunk 局部坐标，不得依赖 Chunk 编号 |
| **Strength** | 源强度 | 显式标量（≥ 0）；含义"在源中心处对场的贡献量" |
| **Radius** | 影响半径 | 显式世界单位（> 0）；半径之外贡献**恒为 0**（紧支撑，见 §3.5） |
| **Type** | 源类型 | §2.2 的枚举之一；决定语义与默认参数倾向 |

**硬性规则**

| # | 规则 |
|---|---|
| **MS1** | 不得有隐藏属性（不得存在"影响结果但未在参数中声明"的量） |
| **MS2** | 后续扩展必须**显式**（例：若未来引入衰减形状参数，必须成为显式参数并写回本文档） |
| **MS3** | 源的集合必须**可局部枚举**：给定任意世界坐标，必须在不需要"遍历全世界所有源"的前提下确定其场值 |
| **MS4** | 源的产生与查询都不得依赖加载顺序、帧序、时间、已加载 Chunk 集合 |

### 2.4 第一版不做动态扩散（边界）

| 做（V1 设计） | 不做（V1 明确禁止） |
|---|---|
| 源 → 场 → 资格的**静态**因果链 | 场随时间的扩散、渗透、衰减、增长 |
| 生成时一次性求值 | 每帧/每 tick 更新场值 |
| 显式的源与显式的参数 | 源之间的相互作用、源的分裂/合并/迁移 |

## 3. 魔力场规则

### 3.1 两个候选方案

**A. 动态扩散（Dynamic Diffusion）**
场值随时间演化：源持续注入、场向邻域扩散、存在梯度驱动、可能需要迭代求解或跨帧状态。

**B. 静态场计算（Static Field）**
场值只是坐标的函数：`MagicDensity(p) = Base + Σ 源贡献(p)`，**无时间维度**。

### 3.2 方案对比

| 维度 | A. 动态扩散 | B. 静态场 |
|---|---|---|
| 确定性 | 需要额外保证（依赖求解顺序/迭代次数/时间步） | **天然确定**（纯函数） |
| Chunk 独立计算 | 破坏：结果依赖邻域是否已模拟 | **保持**（任意坐标独立求值） |
| 是否需要跨帧状态 | 需要（且需要存档） | **不需要** |
| 与既有规范的一致性 | 与"世界坐标纯函数"冲突（地质规范 §2.1/§2.3） | 完全一致 |
| 世界模拟复杂度 | 高（世界级模拟） | **低**（局部叠加） |
| 可验证性 | 难以机械验证 | **可机械验证**（WS4–WS6） |

### 3.3 第一版选择：**B. 静态场**

**原因**：

1. **避免世界模拟复杂化**（首要原因）：动态场要求"世界级"的持续模拟，会把一个属性层变成一套模拟系统；
2. **确定性是第一性要求**（`WorldGeneration_Core.md` §2）：静态场是纯函数，不需要额外论证确定性；
3. **保持 Chunk 计算独立**：任意坐标可以独立求值 ⇒ 流式/生成/验证都不需要修改；
4. **零修改前提**：静态场不需要跨帧状态、不需要存档格式变更、不需要调度配合；
5. **可逆性**：未来若确实需要动态演化，可以在静态场（生成时初值）**之上**新增独立系统，而**不需要推翻**本文档。

### 3.4 场公式

```
MagicDensity(p) = clamp01( Base + Σ_i Contribution_i(p) )

p            世界坐标
Base         全局基底（显式参数，标量）
Source_i     §2.3 定义的魔力源（Position / Strength / Radius / Type）
```

**硬性规则**

| # | 规则 |
|---|---|
| **MF1** | 只有**加法叠加 + 钳制**，不得有源之间的乘性/条件性相互作用 |
| **MF2** | `Base` 与所有源的 4 个属性都是显式参数，不得隐式推导 |
| **MF3** | 贡献**只在生成时计算**（"生成时"= 世界状态求值时刻，按需、纯函数、可重复求值） |
| **MF4** | 不得存在"级联放大"（源不得因为附近场值高而增强） |
| **MF5** | 同一坐标重复求值必须恒等（可重复求值，无副作用） |

### 3.5 贡献函数的硬性要求

单个源的贡献 `Contribution(p)` 必须满足：

| # | 要求 | 说明 |
|---|---|---|
| **CF1** | **紧支撑** | `distance(p, Position) > Radius ⇒ Contribution = 0` |
| **CF2** | **单调不增** | 距离越远，贡献不得增大（越靠近源中心越强） |
| **CF3** | **边界连续** | 在 `distance → Radius` 时贡献连续趋于 0（不得出现跳变断层） |
| **CF4** | **无时间维度** | 不得依赖时间、帧序、加载顺序（§3.6） |
| **CF5** | **参数显式** | 衰减形状必须由显式参数决定；不得依赖平台相关的噪声实现 |
| **CF6** | **可局部计算** | 与 `MS3` 一致：给定坐标与邻近源集合即可求值 |

**反例保护（防止"恒真断言"）**：验收必须能证明场是**非平凡的**——
源中心附近的场值必须**显著高于** `Base`，且 `Radius` 之外必须**恒等于** `Base`（WS5）。

### 3.6 计算时机

```
生成时（世界状态求值）
      ↓
按世界坐标求值（纯函数、可重复）
      ↓
得到该区域的 8 个环境参数
      ↓
供群系判定（§5）与"资格"声明使用
```

| # | 规则 |
|---|---|
| **T1** | 场值**只在生成/查询时计算**，不存在"每帧更新"的场 |
| **T2** | 缓存（若未来需要）**必须只由 `(Seed, 参数, 世界坐标)` 索引**，且不得改变输出 |
| **T3** | 不得跨帧持有"世界状态对象"；Region 是查询结果，不是存活对象（R1） |
| **T4** | 求值不得产生副作用（不得写 Voxel、不得创建 Chunk、不得置脏） |

### 3.7 禁止事项

| # | 禁止 |
|---|---|
| **MX1** | 扩散方程 / 迭代求解 / 时间步进 |
| **MX2** | 依赖邻域是否已模拟/已加载 |
| **MX3** | 依赖 `UnityEngine.Random` / `System.Random` / `Time` / `DateTime` / `Guid`（继承地质规范 §8.2 D1–D6） |
| **MX4** | 让魔力影响 `Density` / `Material` / `CaveDensity` / 新增 `VoxelType`（V1 中它是**属性层**） |
| **MX5** | 让魔力影响加载/卸载/脏标记/并发/预算（调度与规则分离） |
| **MX6** | 让魔力直接生成任何对象（§1.4） |

## 4. 圣与恶系统

### 4.1 定位：世界力量，不是群系

`HolyInfluence` 与 `CorruptionInfluence` **不是普通 Biome**：

| 它们不是 | 它们是 |
|---|---|
| 群系标识（Biome 是离散分类，见 §5） | **连续的世界力量场**（标量 `[0,1]`） |
| 地表材料规则 | 影响**资格与归因**的环境状态 |
| 与地形一一对应 | 可与任意地形/群系**共存**（山脉可以是圣的，也可以是腐化的） |
| 由群系推导 | 由**来源**推导（与魔力同构，§2.1） |

### 4.2 CorruptionInfluence 的来源

| 来源 | 含义 |
|---|---|
| **墓地** | 集中埋葬/死亡之地 |
| **邪恶遗迹** | 腐化性质的远古构造 |
| **死亡事件** | 大规模死亡/灾难事件残留 |
| **污染区域** | 被污染或被破坏的区域 |

### 4.3 HolyInfluence 的来源

| 来源 | 含义 |
|---|---|
| **圣地** | 被长期尊崇/朝拜的地点 |
| **圣物** | 圣性物体的存在位置 |
| **圣生物聚集** | 圣性生物长期聚集的区域 |

**规则**：两类来源与魔力源同构——都具有 `Position / Strength / Radius / Type`（§2.3），
都使用与 §3.4/§3.5 相同的静态叠加与贡献函数要求；V1 只设计，不生成任何来源。

### 4.4 动态平衡（概念定义）

```
Balance(p) = HolyInfluence(p) − CorruptionInfluence(p)
```

* `Balance` 允许为负；
* 概念上表示"两种力量的**对比**"；
* **平衡是概念，不是模拟**：V1 中它只是**求值结果**，不存在"谁在侵蚀谁"的过程状态。

**V1 明确**：两种力量**互相独立计算**，不得互相读取（不得出现"因为腐化高所以圣性被压制"这类耦合）。

### 4.5 V1：生成时确定区域状态

| # | 规则 |
|---|---|
| **HP1** | V1 只定义"**生成时确定区域状态**"：区域的力量属性在求值时一次性确定 |
| **HP2** | V1 **不实现动态战争**：不存在传播、净化、侵蚀、转化、占领、随时间的胜负变化 |
| **HP3** | 两者**不强制互斥**：同一坐标可以同时具有较高的圣性与腐化（"争夺带"是合法状态） |
| **HP4** | 不得把"力量对比"写回 `Density` / `Material` / `VoxelType`（属性层纪律） |
| **HP5** | 允许共存的理由：未来若要实现动态战争，需要的是**新增系统**，而不是让 V1 提前承担模拟 |

### 4.6 派生状态（只读查询）

| 派生状态 | 条件（阈值显式） | 语义 |
|---|---|---|
| **Neutral** | `\|Balance\| ≤ ε` | 未定/中立 |
| **Holy 主导** | `Balance ≥ +θ` | 圣性占优 |
| **Corrupt 主导** | `Balance ≤ −θ` | 腐化占优 |
| **Contested** | `ε < \|Balance\| < θ` | 争夺带 |

> `ε`、`θ` 是**显式参数**；`Contested` **只是分类结果**，不代表任何战斗/事件正在发生。
> 派生状态只用于"资格"与"归因"（例如群系判定与遗迹归因），不得用于生成对象。

### 4.7 禁止事项

| # | 禁止 |
|---|---|
| **HX1** | 传播、扩散、侵蚀、净化、转化、随时间变化 |
| **HX2** | 圣与腐化互相读取或互相压制（V1 独立计算） |
| **HX3** | 影响 `Density` / `Material` / 洞穴 / 矿藏 / 新增 `VoxelType` |
| **HX4** | 影响加载/卸载/脏标记/调度 |
| **HX5** | 用"腐化植被/圣殿存在"反推力量值（§1.5） |
| **HX6** | 直接生成任何对象（含腐化生物、亡灵、圣物） |

## 5. 生物群系生成规则

### 5.1 Biome 不是随机选择

**禁止**：从群系列表中随机挑选、按 Chunk 挑选、按加载顺序挑选、用噪声"抽签"。

**必须**：

```
环境参数向量（§1.3 的 8 个参数）
      ↓  （显式规则表 + 显式阈值）
Biome（离散标识）
```

### 5.2 输入：环境参数向量

| 参与判定的参数 | 说明 |
|---|---|
| **Temperature** | 温度 |
| **Moisture** | 湿度 |
| **Elevation** | 海拔（含海洋判定） |
| **MagicDensity** | 魔力（地表点取值，§1.3 规则 4） |
| **CorruptionInfluence** | 腐化 |
|（同时可参与）**HolyInfluence**、**Fertility**、**Ocean** | 圣性 / 肥力 / 海洋标志 |

**规则**：群系判定**只能**读取环境参数与 `Seed`；不得读取任何已生成内容、对象、Chunk 状态。

### 5.3 判定程序（有序规则表，first-match-wins）

| 顺序 | 规则 | 结论 |
|---|---|---|
| 1 | `Ocean == true` | **海洋**（短路：不再参与后续判定） |
| 2 | `CorruptionInfluence` 高 **且** `Fertility` 低 | **腐化荒地** |
| 3 | `HolyInfluence` 高 **且** `Fertility` 高 | **圣洁森林** |
| 4 | `MagicDensity` 高 **且** `Temperature` 适宜 **且** `Moisture` 高 | **魔法森林** |
| 5 | `Temperature` 中等 **且** `Moisture` 高 | **普通森林** |
| 6 | （默认） | **显式默认群系**（由实现规范定义，不得留空、不得隐式推导） |

**硬性规则**

| # | 规则 |
|---|---|
| **B1** | 规则**顺序显式且固定**（顺序是规范的一部分：海洋优先，腐化/圣性优先于魔力与普通森林） |
| **B2** | 所有阈值**显式参数化**，不得硬编码魔法数字而不声明 |
| **B3** | 不得"因为某个群系名"反推参数（§1.5）；群系是**结果**，不是原因 |
| **B4** | 判定必须**可重复求值**（同坐标同结果），且不依赖加载顺序/时间/邻域 |
| **B5** | 判定结果必须是**离散标识**；两个相邻坐标结果不同时，其**参数**必须平滑过渡（§5.6） |

### 5.4 示例（规则示例，不是实现清单）

| 群系 | Temperature | Moisture | Elevation | Fertility | Ocean | MagicDensity | Corruption | HolyInfluence |
|---|---|---|---|---|---|---|---|---|
| **普通森林** | 中等 | 高 | 低–中 | 中等 | false | 低 | 低 | 低 |
| **魔法森林** | 适宜 | 高 | 低–中 | 中等 | false | **高** | 低 | 低 |
| **腐化荒地** | 任意 | 低 | 任意 | **低** | false | 任意 | **高** | 低 |
| **圣洁森林** | 适宜 | 中–高 | 低–中 | **高** | false | 低 | 低 | **高** |
| **海洋** | 任意 | 任意 | `< SeaLevel` | 任意 | **true** | 任意 | 任意 | 任意 |

> 表中"任意"表示**该参数不参与该群系的判定**（不得被隐式用作次要条件）。

### 5.5 海洋短路

`Ocean == true ⇒ 海洋群系`，并且：

* 海洋区域**不参与**魔力/腐化/圣性/肥力的群系判定（但参数本身仍然存在，仍可被未来系统查询）；
* 海洋区域的**陆地遗迹资格被排除**（§6.4），除非未来显式定义"水下遗迹"类型；
* `Ocean` 必须由 `Elevation` 与显式 `SeaLevel` 派生（§1.3），**不得**使用独立噪声。

### 5.6 连续性与过渡

| # | 要求 |
|---|---|
| **CT1** | 群系**参数**必须连续（不得出现逐点跳变），边界过渡带宽度由显式参数控制 |
| **CT2** | 群系**标识**是离散的，允许在阈值处发生切换；切换必须**只**由参数穿越阈值引起 |
| **CT3** | 不得出现"相邻 Chunk 规则不同"造成的断裂（继承地质规范 §2.3 F2） |
| **CT4** | 群系不得影响 `Density` / 高度 / 洞穴 / 调度的连续性（群系不是地形修正的唯一来源） |

### 5.7 V1 边界：群系只能影响什么

| 影响 | V1 边界 |
|---|---|
| **地表材料选择** | 只作用于地表层体素；取值只能是既有 4 种体素状态中的 `{Grass, Dirt, Stone}`（`Air` 不作地表材料） |
| **植被/生态条件声明** | 只提供**环境条件**（供未来 Entity / Vegetation 系统消费）；**不生成**任何植被/生物/对象 |
| **不影响** | 密度分布、地表高度、洞穴、矿藏、Chunk 划分、加载/卸载、脏标记、几何、Entity |

（该边界与 `WorldGeneration_Geology_Runtime_Implementation.md` §6.1/§6.2 完全一致，本规范**不放宽**它。）

### 5.8 与既有实现的退化兼容（硬性）

```
三个 Energy 参数均为 0（或能量层关闭）
且 Physical 扩展参数（Fertility / Ocean）关闭
⇒ 群系判定必须退化为既有的 (Temperature, Moisture) 二维判定
⇒ 并能复现既有 Stage C 的占位映射（冷干 ⇒ 裸岩地表 / 暖湿 ⇒ 草地地表）
```

**理由**：既有地质 Stage C/D/E 的验收不变量（GW1–GW10、GE1–GE9）不得被世界状态层破坏。
**含义**：世界状态层是**新增层**，必须**可关闭**，关闭后世界与今天逐体素一致（WS11）。

## 6. 世界历史与遗迹

### 6.1 遗迹不是随机装饰

**禁止**：随机撒点、按噪声放结构、"每隔 N 个 Chunk 放一个遗迹"。

**必须**：

```
历史事件
    ↓
文明活动范围
    ↓
遗迹位置
```

### 6.2 因果链定义

| 层 | 内容 | 属性 |
|---|---|---|
| **历史事件** | 发生过的世界级事件（战争、灾难、迁徙、建城、封印……） | 确定性、有位置、有类型、有时间序位 |
| **文明活动范围** | 文明因**环境偏好**而占据的空间范围 | 由环境参数（§1.3）+ 文明偏好（§6.3）确定 |
| **遗迹位置** | 在活动范围内、满足地形/环境条件的位置 | **确定性纯函数**，可解释 |

**规则**

| # | 规则 |
|---|---|
| **HR1** | 遗迹位置**必须可回溯**到"历史事件 → 文明活动范围 → 位置"这条链（WS8） |
| **HR2** | 遗迹位置必须是**确定性纯函数**（同 `Seed` 同结果），不得依赖加载顺序/时间 |
| **HR3** | 遗迹**不得**被随机撒点；密度必须由显式规则与显式参数决定 |
| **HR4** | 遗迹**不得**违反地形常识：`Ocean == true` 处不生成陆地遗迹（除非显式定义水下类型） |
| **HR5** | 遗迹**不得**改变既有密度规则（不是地形的一部分） |

### 6.3 文明偏好（示例：偏好是规则，不是生成指令）

| 文明 | 偏好环境（环境参数条件） | 典型活动范围 | 倾向遗迹 |
|---|---|---|---|
| **矮人** | 山脉（高 `Elevation`）、矿产丰富（`DepositZone ≠ None`）、低 `Moisture` | 山地 / 地下 | 工坊、矿道、要塞 |
| **精灵** | 森林群系（高 `Moisture`、中 `Temperature`） | 森林 | 圣所、林间遗迹 |
| **人类** | 低 `Elevation`、高 `Fertility`、`Ocean == false`、近水 | 平原 / 河谷 / 海岸 | 城镇、道路、农田 |
| **腐化势力** | 高 `CorruptionInfluence` | 腐化区 | 祭坛、墓地、邪恶遗迹 |

> 例：**"山脉附近生成矮人工坊"** 的正确读法是
> `高 Elevation + 矿产丰富 ⇒ 矮人活动范围 ⇒ 该范围内满足条件的点成为工坊遗迹候选`。

### 6.4 遗迹位置规则（设计）

| 输入 | 输出 |
|---|---|
| 历史事件（类型 / 位置 / 序位）、文明活动范围、环境参数（§1.3）、既有地形（`Elevation` / `Ocean`）、`Seed` | **遗迹候选**：位置 + 类型 + 归属文明 + 资格判定 |

**硬性**

1. 候选必须是**只读查询结果**，可重复求值；
2. 候选的产生**不得**写 Voxel、不得创建 Chunk、不得生成对象；
3. 同一 `(Seed, 参数, 坐标)` ⇒ 同一候选集合（WS8）；
4. 遗迹的**实际放置**（方块、结构、Entity、战利品、存档）属于未来 **Structure / Entity 系统**（ADR-001）。

### 6.5 V1 只设计规则

| 做（V1 设计） | 不做（V1） |
|---|---|
| 文明偏好规则、活动范围规则、遗迹资格规则 | 历史模拟、NPC 行为、战争、迁徙过程 |
| 只读查询的输入/输出定义 | 结构生成、方块放置、Entity 生成、存档 |

### 6.6 与 Entity / 结构系统的边界

| 问题 | 本文档（世界状态层） | 未来 Structure / Entity 系统 |
|---|---|---|
| 这个区域属于哪条历史因果链？ | ✅ 只读查询 | 只读消费 |
| 这里**适合**什么遗迹？ | ✅ 资格判定 | 只读消费 |
| 实际放置结构 / 方块 / 对象 | ❌ 不参与 | ✅ 拥有 |
| 遗迹对象的状态 / 生命周期 / 存档 | ❌ | ✅ |
| 遗迹的 Mesh / 渲染 / 碰撞 | ❌ | ✅（表现层） |

## 7. 世界大小讨论：无限世界 vs 有限大陆

> **本节只做设计分析，不实现任何内容（§7.6）。**

### 7.1 两个候选

* **A. 无限世界**：水平方向无边界（与今天的既有流式行为一致），地形、群系、区域随坐标无限延伸。
* **B. 有限大陆**：世界中存在**有限数量**的陆块（大陆），大陆之外是海洋（或世界边界）。

### 7.2 结合事件系统 / 历史 / 文明 / 遗迹的分析

| 维度 | A. 无限世界 | B. 有限大陆 |
|---|---|---|
| 生成可实现性 | 纯函数易实现 | 需要额外的大陆骨架函数（仍可纯函数化） |
| **事件系统** | 全局世界事件无法收敛：事件的影响范围与"世界"没有共同边界 | 事件有**明确舞台**，影响范围可与大陆边界对齐 |
| **历史** | "世界历史"退化为局部噪声：无限回廊上任何全局叙事都无意义 | 历史有**有界舞台**，可做世界级摘要（谁在哪块大陆） |
| **文明** | 文明范围无界 ⇒ 遗迹密度必须人为抑制，且与"文明活动范围"语义冲突 | 文明范围自然收敛（大陆 + 活动半径） |
| **遗迹** | 无法回答"为什么这里没有遗迹"：无限空间中密度只是参数 | 可回答：超出所有文明活动范围 ⇒ 无遗迹（因果可解释） |
| 探索体验 | 无终点、重复感强 | 有"已知世界"边界；跨海发现新大陆是自然的探索目标 |
| 确定性 / 存档 | 都可行 | 都可行；有限更容易做世界级摘要 |
| 性能 | 局部求值 | 局部求值（同） |
| 实现复杂度 | 低 | 中（多一层大陆掩码/骨架函数） |
| **与既有实现的一致性** | **完全一致**（这就是今天的行为） | 必须保证**不引入水平世界边界**才能零修改 |

### 7.3 推荐方案：**无限海洋 + 有限大陆**

**推荐 B 的一个特定形态**：

```
水平世界：保持无限（Chunk 空间无边界 —— 与今天的流式行为完全一致）
垂直世界：沿用既有 WorldHeight（不改变）
陆地：    由"大陆函数"限定的有限块（大陆 A / 大陆 B / …）
大陆之外：海洋（Elevation < SeaLevel），可无限延伸
```

**理由**

1. **历史/文明/遗迹需要"有界舞台"**：没有边界，事件与文明的活动范围就没有语义（§7.2）；
2. **探索动机**：大陆之间由海洋隔离 ⇒ "出海发现新大陆"是天然目标（讨论中的"大陆 A = 玩家区域，大陆 B = 其他文明"）；
3. **零修改兼容**：水平世界**不引入硬边界**，因此 Streaming / Runtime / Chunk 坐标语义**完全不需要改动**（§7.5）；
4. **仍可纯函数化**：大陆只是"掩码/骨架函数"，与"世界是连续函数"的模型同构（地质规范 §2.1）；
5. **可退化**：大陆掩码退化为"全部陆地"时，世界回到今天的无限地形（与 §5.8 同一种退化纪律）。

**参数设计（显式，不实现）**

| 参数 | 含义 |
|---|---|
| `ContinentCount` | 大陆数量（有限，显式） |
| `ContinentCenters` | 各大陆中心（由 `Seed` 确定性决定） |
| `ContinentRadius` / `ContinentShape` | 大陆规模与形状（显式参数） |
| `SeaLevel` | 海平面（海洋判定阈值，§1.3） |
| `OceanGap` | 大陆之间的**最小**海洋间隔（保证"隔离"语义） |

**大陆语义（设计）**

| 大陆 | 语义 |
|---|---|
| **大陆 A** | 玩家起始区域（较小、较安全，群系与能量场受控） |

## 附录 A：落地顺序与验收不变量（设计，不实现）

> 本附录只是**未来的落地顺序设计**，本轮不实现任何一项。
> 任何实现必须另立实现规范（例如 `WorldState_Implementation.md`），并在其中给出类型 / 接口 / 参数结构。
> 本文档**不含任何代码与接口草案**。

### A.1 建议的落地顺序

| 阶段 | 内容 | 关键约束 |
|---|---|---|
| **WS-A** | Physical 环境参数（5 项） | `Elevation` **必须复用**既有 `SurfaceHeight`；`Fertility`/`Ocean` 为派生的纯属性 |
| **WS-B** | 三个 Energy 场（源 + 静态场） | 紧支撑、单调、边界连续、无时间维度 |
| **WS-C** | 群系规则表（环境向量 → Biome） | 必须满足 §5.8 的退化兼容 |
| **WS-D** | 历史 / 文明 / 遗迹资格查询 | 只产出只读候选，不生成对象 |
| **WS-E** | 大陆骨架（可选，最后） | 掩码叠加，不得替换既有高度场 |

**顺序理由**：先参数（WS-A/B）、再分类（WS-C）、再归因（WS-D）、最后才是世界尺度（WS-E）；
每一步都必须能独立验证，且**关闭即退回**既有行为。

### A.2 验收不变量

| # | 不变量 | 验证方法 |
|---|---|---|
| **WS1** | **纯函数性**：同一 `(Seed, 参数, 坐标)` 重复求值结果恒等 | 同坐标重复求值 N 次逐值比较 |
| **WS2** | **Seed 决定性**：同 `Seed` ⇒ 同结果；不同 `Seed` ⇒ 至少一个参数不同（反例保护） | 双世界对照 + 非平凡性断言 |
| **WS3** | **Chunk 边界连续**：跨 Chunk 相邻列的参数差值有界，无逐点跳变 | 边界列差分上界断言 |
| **WS4** | **静态场无时序依赖**：场值与加载顺序 / 帧序 / tick 次数无关 | 不同加载顺序下重算并比较 |
| **WS5** | **源叠加正确性**：源中心处显著高于 `Base`；`Radius` 外恒等于 `Base`；距离越远不增大 | 沿半径采样比对（含反例保护） |
| **WS6** | **有界与钳制**：所有参数恒在 `[0,1]`（`Elevation` 除外） | 全域采样值域检查 |
| **WS7** | **属性不改密度**：开关 Energy / Fertility 不影响任何体素状态（除既有的地表材料规则） | 两次生成体素快照逐体素比较（差异集合 ⊆ 允许集合） |
| **WS8** | **因果可解释性**：每个特殊生态/遗迹判定都能回溯到某个来源；不存在"结果 → 原因"的规则 | 结构扫描（规则读取顺序）+ 判定链问答（附录 C） |
| **WS9** | **不新增 VoxelType / 不改 VoxelCore** | 结构性检查（类型集合冻结、无新写入语义） |
| **WS10** | **零修改既有实现**：VoxelCore / WorldGeneration / 地质实现 / Mesh / View / Runtime / Streaming / Bootstrap 的 SHA 不变 | 文件哈希比对（既有验证入口做法） |
| **WS11** | **退化兼容**：Energy = 0 且扩展参数关闭 ⇒ 世界与今天逐体素一致 | 与 Stage 1/Stage C 基线对照（逐体素 + 内容哈希） |
| **WS12** | **确定性证据**：同 `Seed` + 坐标 ⇒ 体素快照与派生 Mesh 内容哈希完全一致 | 内容哈希比较 |

## 附录 C：可解释性（判定链问答）

**C.1 "为什么这里是魔法森林？"**

```
① 该坐标附近存在魔力源（AncientMagicSite / MagicCrystalDeposit / …）   ← 原因
② 静态场叠加 ⇒ MagicDensity 显著高于 Base（§3.4）                      ← 世界状态
③ 群系规则第 4 条命中（魔力高 + 温度适宜 + 湿度高）                     ← 分类
⇒ 结论：魔法森林
```

**C.2 "为什么这里是腐化荒地？"**

```
① 附近存在腐化来源（墓地 / 邪恶遗迹 / 死亡事件 / 污染区域）             ← 原因
② CorruptionInfluence 高（且 Balance 负向主导，§4.6）                   ← 世界状态
③ Fertility 低（§1.3 派生属性）                                        ← 世界状态
④ 群系规则第 2 条命中                                                  ← 分类
⇒ 结论：腐化荒地
```

**C.3 "为什么这里有一座矮人工坊遗迹候选？"**

```
① 历史事件：该区域在历史序位中存在矮人活动（§6.2）                     ← 原因
② 文明偏好命中：高 Elevation（山脉）+ DepositZone ≠ None（矿产丰富）    ← 活动范围
③ 遗迹资格：范围内地形/环境条件满足（非 Ocean、坡度/高度条件由显式规则给出） ← 资格
⇒ 结论：矮人工坊遗迹候选（实际放置由未来 Structure/Entity 系统决定）
```

**C.4 为什么禁止"因为这里是魔法森林，所以魔力高"？**

| 问题 | 说明 |
|---|---|
| 循环 | 群系由环境参数决定（§5.1），环境参数不能反过来由群系决定 |
| 不可复现 | 判定顺序不同 ⇒ 结果不同（违反纯函数性 WS1/WS4） |
| 不可验证 | 无法机械检查"到底是谁决定了谁"（违反 WS8） |
| 破坏可解释性 | 无法回答"这个群系为什么在这里" |

## 附录 D：术语表

| 术语 | 含义 |
|---|---|
| **World State（世界状态）** | 一个区域拥有的**环境参数集合**（§1.3）；描述"环境如何"，不是"有什么东西" |
| **Region（区域）** | 由世界状态判定结果定义的空间范围（§1.2）；**不是**容器、不是存档单位 |
| **Physical 参数** | `Temperature` / `Moisture` / `Elevation` / `Fertility` / `Ocean` |
| **Energy 参数** | `MagicDensity` / `HolyInfluence` / `CorruptionInfluence`（世界力量） |
| **MagicSource（魔力源）** | 魔力场的原因记录：`Position` / `Strength` / `Radius` / `Type`（§2.3）；**不是 Entity** |
| **静态场（Static Field）** | 场值只是坐标的纯函数，无时间维度（§3.3） |
| **动态扩散（Dynamic Diffusion）** | 场随时间演化/传播的方案（V1 不采用，§3.1） |
| **Balance** | `HolyInfluence − CorruptionInfluence`（§4.4）；V1 中的只读派生量 |
| **Contested（争夺带）** | `\|Balance\|` 落在 `(ε, θ)` 的分类结果；**不代表**正在战斗（§4.6） |
| **Biome（群系）** | 由环境参数向量经显式规则表判定的**离散结果**（§5）；不是随机选择 |
| **Eligibility（资格）** | "允许出现"的声明；世界状态只产生资格，不产生对象（§1.4） |
| **历史事件** | 发生在特定位置/类型/序位的世界级事件（§6.2），是遗迹的原因 |
| **大陆（Continent）** | 由大陆函数限定的有限陆块（§7.3）；大陆之外为海洋 |
| **退化兼容** | 关闭新层后世界与既有行为逐体素一致（§5.8 / WS11） |
