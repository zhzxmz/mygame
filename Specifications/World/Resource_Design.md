## 1. Resource 定位

### 1.1 定义

> **资源是世界条件产生的结果。**

| 问题 | Resource 的回答 |
|---|---|
| 这里存在什么资源？ | 资源的**判定结果**（类别 / 判定等级 / 丰度倾向） |
| 为什么存在？ | 可解释的原因链（地质 + 环境 + 区域/历史） |
| 以什么形态存在？ | 形态**资格**（对象形态属未来系统，§4.4） |

### 1.2 Resource **不是**随机物品生成

| Resource **不是** | 说明 |
|---|---|
| **不是掉落表 / 战利品表** | 不定义掉落概率、不定义物品、不定义数量随机 |
| **不是随机刷矿** | 不存在"按概率撒矿"、不存在"按 Chunk 撒矿" |
| **不是物品生成器** | 不生成 Item、不生成实体、不写体素 |
| **不是群系的产物** | **禁止 `Biome → Resource`**（§3） |
| **不是独立噪声** | 资源判定必须由**有原因的世界条件**推导，不允许"凭空噪声资源" |
| **不是地形修改器** | 不得修改 `Density` / `VoxelType` / `Terrain`（§4.3） |

### 1.3 判定等级（语义）

| 等级 | 含义 | 消费者 |
|---|---|---|
| **None** | 该坐标不存在该资源，且无形成条件 | — |
| **Substrate（载体资格）** | 介质/环境**允许**该资源形成，但尚未满足全部条件（或缺决定性证据） | 未来系统、Ecology（生物资源载体） |
| **Present（存在）** | 全部必需原因成立 ⇒ **资源存在**（判定为真） | Mining、未来 Entity/Item 系统、Ecology |

> 三个等级都是**只读判定结果**，不是对象，也不是物品。

### 1.4 硬性规则

| # | 规则 |
|---|---|
| **RK1** | 资源判定必须由**世界条件**推导：`Environment + Geology + History + Region`（§3.1） |
| **RK2** | 每个资源类别**必须**给出**必需原因**（缺一不可的条件集合，§2.2） |
| **RK3** | **禁止无原因资源**：不得存在"只有随机数、没有条件"的资源 |
| **RK4** | Resource **不改变世界状态**：不写环境参数、不写 Region、不写 `DepositZone`、不写 Voxel、不创建 Chunk |
| **RK5** | Resource **不新增 `VoxelType`**：V1 体素状态仍冻结为 Air/Grass/Dirt/Stone |
| **RK6** | Resource 必须**可局部求值**：任意世界坐标可独立求出资源判定，无需遍历全世界（`Pipeline` PG5） |
| **RK7** | Resource 必须**可解释**：任意判定都能回溯"地质 → 环境 → 区域/历史"的完整原因链 |
| **RK8** | Resource 必须**可关闭**：关闭后世界与今天**逐体素一致**（判定层不产生任何副作用） |

### 1.5 在管线中的位置（旁路层）

> `WorldGeneration_Pipeline_Design.md` 的 Phase 0–7 描述的是**体素生成链**（终点 = Voxel Output）。
> Resource 与 Ecology 一样，是**位于 Phase 6 之后的旁路判定层**：读取上游产物，但**不被 Phase 6/7 读取**。

| # | 规则 |
|---|---|
| **RK9** | Resource **不新增 Pipeline 阶段**、不改变 Phase 顺序、不改写任何 Phase 的产出 |
| **RK10** | Resource 的输入**只能**是：上游层产物（世界坐标 + 地质判定 + 环境参数 + 区域/历史只读信息 + 显式资源参数） |

## 2. Resource 分类

### 2.1 分类总表（V1）

| 类别 | 资源 | 主要成因层 | 判定输出 |
|---|---|---|---|
| **普通矿物** | **Iron** | 地质（矿藏 + 地层） | 存在性 + 丰度倾向 |
| **普通矿物** | **Copper** | 地质（矿藏 + 地层） | 存在性 + 丰度倾向 |
| **普通矿物** | **Gold** | 地质（矿藏 + 深层地层） | 存在性 + 丰度倾向（更稀有） |
| **魔法资源** | **Magic Crystal** | 环境（高 `MagicDensity`）+ 纪元跨度 + 介质 | 存在性 + 形态资格 |
| **魔法资源** | **Mana Ore** | 环境（高 `MagicDensity`）+ 纪元跨度 + 介质（矿体） | 存在性 + 形态资格 |
| **圣性资源** | **Holy Crystal** | 环境（高 `HolyInfluence`）+ 纪元跨度 + 介质 | 存在性 + 形态资格 |
| **腐化资源** | **Corrupted Material** | 环境（高 `CorruptionInfluence`）+ 纪元跨度 + 介质 | 存在性 + 形态资格 |
| **生物资源** | **Wood** | **载体资格**（Resource） + 实际存在性（Ecology） | 载体资格（非最终存在性） |
| **生物资源** | **Plant** | 同上 | 载体资格 |
| **生物资源** | **Animal Material** | 同上（依赖动物生态条件） | 载体资格 |

### 2.2 必需原因（每类的硬性条件）

| 资源 | 必需原因（缺一不可） | 禁止的形式 |
|---|---|---|
| **Iron / Copper / Gold** | ① 地质矿藏判定成立（`DepositZone` 类，**Geology 权威**）② 地层/深度条件满足（既有地质规则） | 禁止由 Biome、禁止由噪声单独决定 |
| **Magic Crystal / Mana Ore** | ① `MagicDensity` **高** ② **纪元跨度**足够（时间积累，§5.3）③ **合适介质**（地层/矿体，只读地质条件） | 禁止由 Biome（含"魔法森林"）决定 |
| **Holy Crystal** | ① `HolyInfluence` **高** ② 纪元跨度足够 ③ 合适介质 | 同上 |
| **Corrupted Material** | ① `CorruptionInfluence` **高** ② 纪元跨度足够 ③ 合适介质 | 同上 |
| **Wood / Plant** | ① **载体资格**：`Fertility` / `Moisture` / `Temperature` 条件 + 非 `Ocean` ② 实际**存在性由 Ecology 决定**（植被候选） | 禁止由 Biome 名称决定；禁止 Resource 替代 Ecology |
| **Animal Material** | ① 载体资格：动物生态条件（植被/气候/非极端高程）② 实际**存在性由 Ecology 决定** | 同上 |

### 2.3 硬性规则

| # | 规则 |
|---|---|
| **RQ1** | 每个资源**必须**属于 §2.1 的类别之一；新增资源必须显式登记并给出必需原因 |
| **RQ2** | 每个资源的判定**必须**能展开为显式条件（阈值 + 组合关系），不得存在隐式条件 |
| **RQ3** | **禁止 Biome 作为判定输入**（§3.2） |
| **RQ4** | **生物资源采用两级模型**：Resource 只给**载体资格**；**实际存在性由 Ecology 决定**（避免与生态层争权威） |
| **RQ5** | 圣性/腐化/魔法资源**必须**绑定力量来源所导致的环境参数，不得由"区域名/群系名"决定 |
| **RQ6** | 资源的丰度必须**有界**且由显式参数限定（不得出现无限富集） |
| **RQ7** | 资源不得改变 `Density` / `Material` / `CaveDensity` / `Terrain` / `VoxelType`（§4.3） |
| **RQ8** | 资源的**对象形态**（晶簇、矿脉节点、可拾取物）属于**未来 Entity / Item 系统**（ADR-001）；Resource 只给资格与判定 |
| **RQ9** | 资源的判定不得依赖任何**消费侧**状态（玩家是否采集过、背包、任务、已挖矿统计） |
| **RQ10** | 资源判定的**位置分布必须可局部枚举**：给定范围可求出范围内的资源判定，不需要遍历全世界 |

## 3. 因果链

### 3.1 唯一允许的因果链

```
Environment（WorldState 参数）
      +
Geology（地质矿藏 / 地层 / 介质）
      +
History（历史事实：只读归因）
      +
Region（来源 / 修正 / 标签）
              ↓
          Resource
```

| # | 规则 |
|---|---|
| **RN1** | 四个输入都是**上游只读**；Resource 不得读取任何下游（Ecology 候选、Mining 状态、物品、玩家） |
| **RN2** | 判定必须**同时**考虑四条输入中存在的那部分：**地质成因资源**必须由地质条件支撑；**环境成因资源**必须由环境参数支撑 |
| **RN3** | 每条判定必须可解释到"**为什么**"（哪个条件成立） |
| **RN4** | 同一坐标的多个资源判定**叠加成立**（不互相删除）；判定之间**不得互相读取** |
| **RN5** | 资源判定不得被任何上游读取（不得成为 Region/WorldState/Geology 的输入） |
| **RN6** | 资源判定不得被 Phase 6/7 读取（不参与体素生成链） |

### 3.2 禁止 `Biome → Resource`（硬性）

> **禁止**：因为是魔法森林，所以生成魔晶。
> **正确**：因为这里存在高魔源，所以形成魔晶。

| # | 规则 |
|---|---|
| **RN7** | **Biome 不得作为资源判定的输入**：不得出现 `Biome == MagicForest ⇒ Magic Crystal` 这类规则 |
| **RN8** | 正确形式：使用 **Environment 参数**（`MagicDensity` / `HolyInfluence` / `CorruptionInfluence` / `Fertility` / `Moisture` / `Temperature`）+ 地质条件 + 纪元跨度 |
| **RN9** | 理由：Biome 是**环境向量的压缩结果**（`WorldState_Design.md` §5），资源必须直接挂在**原因**（参数与地质）上，否则无法区分"同为魔法森林但魔力强度不同"的两处 |
| **RN10** | 同理禁止：`RegionType → Resource`（区域类型是解释标签，无规则权；`Region_Design.md` RTY2） |

### 3.3 反例对照表

| 禁止（错误形式） | 必须（正确形式） |
|---|---|
| 因为是**魔法森林**，所以生成魔晶 | 因为**存在高魔源**（→ `MagicDensity` 高）+ 纪元跨度 + 介质，所以形成魔晶 |
| 因为是**腐化荒地**，所以生成腐化材料 | 因为**腐化来源**导致 `CorruptionInfluence` 高 + 纪元跨度 + 介质 |
| 因为是**圣洁森林**，所以生成圣晶 | 因为**圣性来源**导致 `HolyInfluence` 高 + 纪元跨度 + 介质 |
| 因为是**森林**，所以有木材 | 因为 `Fertility`/`Moisture`/`Temperature` 满足**载体条件**（且非 `Ocean`），实际存在性由 **Ecology** 判定 |
| 因为**区域叫矿区**，所以有铁矿 | 因为**地质矿藏判定成立**（`DepositZone`，Geology 权威）+ 地层条件 |

### 3.4 依赖方向矩阵（Resource 视角）

| 对象 | 是否可读 | 说明 |
|---|---|---|
| 世界坐标 / `Seed` / 显式资源参数 | ✅ | 确定性输入 |
| `WorldState` 的 8 个参数（`FinalState`） | ✅ | 环境原因（含 `MagicDensity` / `HolyInfluence` / `CorruptionInfluence`） |
| Geology：地质矿藏判定、地层/深度、材料**类别**（不读体素） | ✅ | 地质原因与介质条件 |
| Region：来源类别、修正、`HistoryTags`（只读） | ✅ | 归因与区域条件 |
| History：`HistoryTags`（只读事实） | ✅（**仅归因**） | **不得作为判定条件**（§6.2） |
| **Biome** | ❌ | 禁止（`RN7`） |
| `RegionType` / `RegionView` | ❌ | 无规则权 / 结果侧 |
| Ecology 候选（植被/动物是否存在） | ❌ | Resource 在 Ecology 之前求值；生物资源只给**载体资格**（`RQ4`） |
| Mining / 物品 / 玩家状态 / 已生成内容 / Chunk 状态 | ❌ | 消费侧与调度层 |

## 4. 与 Geology 的关系

### 4.1 职责划分

| 层 | 负责 |
|---|---|
| **Geology** | **岩石 / 密度 / 地下结构**：`Density`（实体/空）、`Material`（材料）、`CaveDensity`（洞穴）、地层（Surface/Depth/Deep）、**地质矿藏分布（`DepositZone`，属性层）** |
| **Resource** | **资源判定**：在地质基础之上，结合环境参数、历史与区域信息、纪元跨度与介质条件，给出**资源存在性裁决**与**载体资格** |

### 4.2 两层"存在性"的归属澄清（重要）

`WorldGeneration_Geology.md` §6.1 已把 `DepositZone` 定义为"**哪里存在资源**"（**地质成因**的属性层）。
本文档**不推翻**该定义，而是把它视为**第一层（地质基础层）**：

| 层 | 名称 | 归属（唯一权威） | 含义 |
|---|---|---|---|
| **第一层** | **地质矿藏（Geological Deposit）** | **Geology**（`DepositZone` 属性层，不是体素类型） | 地质成因的资源**基础分布**（"这里的地质条件是否具备"） |
| **第二层** | **资源判定（Resource）** | **本文档** | 在基础分布之上叠加**环境 / 历史 / 介质 / 纪元跨度**，给出最终**资源存在性裁决**与**载体资格** |

```
地质基础层（Geology）   环境/历史/区域层（WorldState / History / Region）
        └──────────────┬──────────────┘
                       ▼
              资源判定层（Resource，本文档）
                       ▼
        Mining / Ecology / 未来 Entity / Item 系统（只读消费）
```

| # | 规则 |
|---|---|
| **RU1** | `DepositZone` 的定义、产生与修改**只属于 Geology**；Resource **不得**定义、修改或扩展它 |
| **RU2** | Resource 的判定是**只读消费 + 上层裁决**（"基础 ∧ 条件"），不是"重新定义资源分布" |
| **RU3** | 两层都必须满足**可解释性**：任何"存在"结论都能分别回答"地质条件是否具备"与"环境/历史条件是否具备" |

### 4.3 禁止事项（用户要求）

| # | 禁止 Resource 修改 | 说明 |
|---|---|---|
| **RU4** | **`Density`** | 实体/空判定属地质优先级链（P0–P3），资源不得参与 |
| **RU5** | **`VoxelType`** | 不新增体素类型、不改变体素状态集合（V1 冻结为 Air/Grass/Dirt/Stone） |
| **RU6** | **`Terrain`**（高度 / 地层 / 洞穴 / 材料） | 资源不是地形的一部分；不得挖洞、不得放置方块、不得改变地层 |
| **RU7** | `DepositZone` | 不得修改（`RU1`） |
| **RU8** | 生成链的任何阶段产出（Region / WorldState / Biome / Geology / Voxel） | 资源是**终端判定**，不得回写任何上游 |

### 4.4 对象形态的归属

| 问题 | 归属 |
|---|---|
| 这里的地质条件是否具备矿藏？ | **Geology**（`DepositZone`） |
| 这里的资源判定是什么？ | **Resource**（本文档） |

## 5. 魔法资源规则

### 5.1 世界观：魔力的来源

> **本项目的世界观设定：魔法来源是"光子状态的改变"。**

| # | 规则 |
|---|---|
| **RY1** | "光子状态的改变"是魔力的**物理层解释**（世界观设定） |
| **RY2** | 本文档**不重新定义**魔力来源体系：世界中的具体魔力来源仍由 `Region_Design.md` §3.2 的 6 类来源表达（AncientMagicSite / MagicCrystalDeposit / AncientBattle / PowerfulCreatureDeath / MagicSeal / ArtificialMagicDevice） |
| **RY3** | 该设定在本文档中的**唯一作用**：解释"为什么魔法资源需要**积累**与**介质**"（魔力必须在物质中固定下来，才能形成资源） |
| **RY4** | 不得由该设定直接推导资源（必须先有来源 → 环境参数 → 资源判定，`RN1`） |

### 5.2 魔法资源的形成条件（硬性）

```
MagicDensity 高（环境）
      +
时间积累（纪元跨度）
      +
合适介质（地质条件）
            ↓
      魔法资源形成
```

| # | 规则 |
|---|---|
| **RY5** | 三个条件**缺一不可**；任一条件不成立 ⇒ 判定不得为 **Present**（最多为 **Substrate** 或 **None**） |
| **RY6** | `MagicDensity` 必须取**地表/目标点**的 `FinalState` 值（`WorldState_Design.md` §1.3 规则 4） |
| **RY7** | 阈值必须**显式参数化**，不得硬编码隐式魔法数字 |
| **RY8** | 形成的资源为 **Magic Crystal**（晶体形态）与 **Mana Ore**（矿体形态）：判定其**存在性与形态资格**，不创建对象 |
| **RY9** | 魔法资源的丰度必须随"环境强度 × 纪元跨度 × 介质质量"单调不减（且**有界**，`RQ6`） |
| **RY10** | 禁止负值、禁止无限富集、禁止"越深处无限强" |

### 5.3 "时间积累"的确定性表达（关键）

| # | 规则 |
|---|---|
| **RY11** | "时间积累"**必须**表达为 **纪元跨度（Epoch Span）**：由 `WorldHistory_Design.md` 的 **`Epoch`（纪元段）+ `Ordinal`（序位）** 体系确定性派生 |
| **RY12** | **禁止**使用 `Time` / `DateTime` / 时间戳 / 真实时长 / tick 计数 / 帧数（`WorldHistory_Design.md` HD7/HD8、`Pipeline` PD4） |
| **RY13** | 纪元跨度必须由 `(Seed, Domain, Position)` 唯一确定，且**与历史事件序位一致**（不得出现"历史说该区域 1000 年前就有高魔，但资源说只有 10 年积累"） |
| **RY14** | 不得依赖加载顺序、玩家是否在场、玩家停留时长（"玩家等的越久资源越多"一律禁止） |

### 5.4 "合适介质"的表达

| # | 规则 |
|---|---|
| **RY15** | 介质条件**只能**读取 Geology 的**只读**输出：地层（Surface/Depth/Deep）、材料类别、地质矿藏判定 |
| **RY16** | 禁止新增体素类型来表达介质；禁止新增"魔法岩层"等新的地形概念（如需则属 Geology 规范的变更） |
| **RY17** | 介质质量必须由**显式参数**与地质判定推导，不得随机 |
| **RY18** | 介质条件不得读取 Biome、不得读取生态候选 |

### 5.5 禁止魔法植物作为魔力来源（再次声明）

| # | 规则 |
|---|---|
| **RY19** | **禁止**：魔法植物（魔法树等）作为魔力来源；禁止其产生、增强或维持 `MagicDensity` |
| **RY20** | 依据：`Ecology_Design.md` §3.2 EP1–EP4（魔法树不是魔力来源）与本文档 `RY4`：魔力的原因只能是**来源**（Region §3.2 的 6 类） |

## 6. 历史影响

### 6.1 历史影响资源的唯一路径（用户要求）

```
History（事件：原因）
   ↓
Region Source（来源候选 → 由 Region 层采纳）
   ↓
WorldState（环境参数：Role → Modifier → FinalState）
   ↓
Resource（资源判定）
```

| # | 规则 |
|---|---|
| **RZ1** | **历史对资源的影响必须通过 WorldState 参数体现**：资源判定只能读**参数**，不能读"历史事件"本身作为判定条件 |
| **RZ2** | `HistoryTags` 可以**只读**，但**只能用于归因与可解释性**（"为什么这里高魔"），**不得参与判定** |
| **RZ3** | 理由：若允许"事件 → 资源"直连，就等于绕过 Region/WorldState，破坏 `Pipeline` 的单向因果链与 `WorldState_Design.md` §1.5 的倒因为果禁令 |
| **RZ4** | 禁止"由资源反推历史"（例如"这里有魔晶 ⇒ 这里打过魔法战争"）；反推是被禁止的方向 |

### 6.2 示例：魔法战争区域

| 步骤 | 内容 | 归属层 |
|---|---|---|
| ① 发生魔法战争 | 历史事件（类型 = 战争 / 魔法实验；纪元 + 序位；参与文明） | **History** |
| ② 产生魔法伤痕来源候选 | 来源候选（类别 = 魔法；强度/尺度倾向） | **History → Region** |
| ③ 区域修正生效 | `RegionModifier`：`MagicDensity` ↑ | **Region** |
| ④ 环境成立 | `FinalState.MagicDensity` 高 | **WorldState** |
| ⑤ 形成魔晶判定 | `MagicDensity` 高 + 纪元跨度（与①的纪元一致）+ 合适介质 ⇒ **Magic Crystal 判定 = Present** | **Resource** |
| ⑥ 对象化（未来） | 晶簇/矿脉节点的实际创建 | **未来 Entity / Item 系统** |

> **禁止的写法**：`if (该区域有魔法战争事件) ⇒ 生成魔晶`（跳过 ②③④）。

### 6.3 硬性规则

| # | 规则 |
|---|---|
| **RZ5** | 历史影响必须是**确定性**的（同 `Seed` 同结果），且与 `WorldHistory_Design.md` 的纪元体系一致 |
| **RZ6** | 不得引入"历史战争进行中"这类**动态状态**（V1 历史是静态事实集合） |
| **RZ7** | 历史影响**不得**产生对象：历史只能通过环境参数影响"资源是否存在"，不能"生成资源对象" |
| **RZ8** | 资源判定不得成为历史/区域的输入（不得反向） |

### 8.2 关键接触点详解

**① 资源存在性 vs `DepositZone`（归属澄清，非冲突）**

* Geology 规范把 `DepositZone` 定义为"哪里存在资源"（**地质成因**，属性层）；
* 本文档把资源判定定义为"**地质基础 ∧ 环境/历史/介质/纪元条件**"的**上层裁决**；
* 两者是**两层**关系（§4.2），唯一权威分别为 **Geology** 与**本文档**；Resource 不改 `DepositZone`。

**② `Biome → Resource` 被禁止（与上游一致）**

* `WorldState_Design.md` §5 已规定 Biome 是**环境结果**；`Region_Design.md` RB3 规定群系解析只有一套权威；
* 本文档进一步禁止把 Biome 作为资源判定输入（`RN7`/`RQ3`），迫使资源直接挂在**原因**（参数 / 地质）上。

**③ Resource 与 Ecology 的顺序与依赖（口径澄清，非冲突）**

| 方面 | 结论 |
|---|---|
| **求值顺序** | Resource **在 Ecology 之前**（与用户给定架构一致：`Geology → Resource → Ecology`） |
| **依赖关系** | **不强制**：`Ecology_Design.md` §1.3 EA2 已冻结 Ecology 的输入集合（WorldState + Biome + Region Tags）。因此本文档**不要求** Ecology 必须读取 Resource |
| **可选只读消费** | 未来若 Ecology 需要消费"生物资源载体资格"，必须作为 `Ecology_Design.md` 的**显式变更（升版本）**；本文档只登记该选项，**不改变**它 |
| **权威划分** | 生物资源的**实际存在性**归 **Ecology**；Resource 只给**载体资格**（`RQ4`）— **不争权威** |

**④ "时间积累" 与确定性（一致性确认）**

`RY11`–`RY14` 与 `WorldHistory_Design.md`（HE1–HE6、HD7/HD8）完全一致：时间 = **纪元 + 序位**，不是真实时间。

**⑤ Resource 不在 Pipeline 的 Phase 0–7 中（定位说明）**

本文档与 `Ecology_Design.md` §1.5 同构：Resource 是 **Phase 6 之后的旁路判定层**（`RK9`），
不改变 Phase 顺序，也不被 Phase 6/7 读取（因此不会改变任何体素）。

**⑥ 历史影响必须经 WorldState（用户要求 6 的落地）**

`RZ1`–`RZ4` 已把"`History → Region Source → WorldState → Resource`"写成硬性条款；
`HistoryTags` 只允许用于**归因**，防止绕过环境层。

|---|---|

| **RL10** | **历史影响必经 WorldState**：不存在"事件 → 资源"的直连路径；`HistoryTags` 只用于归因 | 结构扫描（事件作为判定条件 = 0） |
| **RL11** | **无原因资源 = 0**：每个 Present 判定都能给出完整原因链 | 判定链问答 |
| **RL12** | **魔法植物不是来源**：无"魔法植物 → `MagicDensity`"路径 | 结构扫描 |

### 10.3 与 Geology 的边界（用户要求 4）

### A.2 魔法资源判定链（示例）

| 提问 | 判定链 |
|---|---|
| "为什么这里有魔晶？" | ① 历史：魔法战争（纪元 + 序位）→ ② Region Source（魔法伤痕）→ ③ `RegionModifier` ⇒ `MagicDensity` ↑ → ④ 环境成立 → ⑤ `MagicDensity` 高 **且** 纪元跨度足够 **且** 介质合适 ⇒ **Magic Crystal = Present** |
| "为什么这里没有魔晶？" | 三条件中**至少一项不成立**（可具体指认：环境不足 / 积累不足 / 介质不足）— 给出**可解释的"没有"** |
| "为什么这里有铁矿？" | 地质矿藏判定成立（`DepositZone`，Geology）**且** 地层/深度条件满足（介质） |
| "为什么这里有木材（载体资格）？" | `Fertility` / `Moisture` / `Temperature` 满足载体条件且非 `Ocean` ⇒ **Substrate**；实际是否存在植被由 **Ecology** 判定 |
| "为什么这里没有圣晶？" | 该处 `HolyInfluence` 不足（无圣性来源）⇒ 条件不成立 ⇒ `None` |

## 附录 C：禁止反向依赖列表

| # | 禁止的反向依赖 | 反例（必须判为缺陷） | 机械可验证形式 |
|---|---|---|---|
| **RX-1** | **Biome → Resource** | "因为是魔法森林，所以生成魔晶" | 结构扫描：Biome 作为资源判定输入 = 0 |
| **RX-2** | **`RegionType` → Resource** | "因为这里是 `MagicForest` 区域，所以有魔晶" | 结构扫描：类型标签不作判定条件 |
| **RX-3** | **Resource → 上游**（写回） | 由资源判定修正 `MagicDensity` 或 `DepositZone` | 结构扫描：判定层无上游写入点 |
| **RX-4** | **Resource → Voxel / Terrain** | 由资源判定加方块、挖洞、改材料 | 结构扫描：无体素写入路径（`RL13`） |
| **RX-5** | **Resource → Biome / Region** | 由资源反推群系或创建区域 | 结构扫描：无反向写路径 |
| **RX-6** | **History 事件 → Resource（直连）** | `if (魔法战争) 生成魔晶` | 结构扫描：事件不作判定条件（`RZ1`） |
| **RX-7** | **Resource → History** | 由资源反推历史事件 | 结构扫描：历史产出路径不得引用 Resource |
| **RX-8** | **Ecology 候选 → Resource 判定** | 由"这里已有树"推导木材判定 | 结构扫描：资源判定不得读生态候选 |
| **RX-9** | **玩家状态 → Resource** | 由玩家位置/进度决定资源 | 结构扫描：无玩家状态输入（`RD8`） |
| **RX-10** | **时间/帧序 → Resource** | 用 `Time`/`DateTime` 计算"积累时长" | 结构扫描：无非确定性来源（`RD9`/`RY12`） |
| **RX-11** | **加载顺序 / Chunk 状态 → Resource** | 由是否已加载决定资源判定 | 结构扫描：无调度层输入 |
| **RX-12** | **Resource → Phase 6/7** | 让资源参与 `Density`/材料/体素判定 | 依赖矩阵校验（`RN6`/`RL17`） |

| **RX-14** | **无原因资源 / 随机撒矿** | 按概率或按 Chunk 撒布资源 | 结构扫描：每个判定必须绑定条件（`RQ2`/`RL11`） |

**共同判据**：任何一条被违反，都会同时破坏**确定性**（§7）、**因果正确性**（§3/§6）与**既有验收**（`RF1`）。

## 附录 D：未来扩展方向

> 本附录只列**方向与前提**，本轮不实现任何一项。

| 方向 | 说明 | 前提（硬性） |
|---|---|---|
| **D-1 资源对象化** | 晶簇 / 矿脉节点 / 可拾取物由 Entity / Item 系统创建 | 只能**只读**消费资源判定；不得回写（`RQ8`、ADR-001） |
| **D-2 开采与掉落** | 开采行为、产出、工具需求 | 属未来 Mining 规范；不得修改 `VoxelWorld_Mining.md`（`RF4`） |
| **D-3 更多资源类别** | 新增矿物 / 圣性 / 腐化 / 生物资源 | 必须显式登记必需原因（`RQ1`/`RQ2`）；不得新增体素类型 |
| **D-4 资源品质 / 纯度分级** | 同一资源的品质维度 | 必须显式参数化、确定性、有界（`RQ6`） |
| **D-5 资源再生 / 动态变化** | 资源随时间恢复或枯竭 | 属**独立规范**；必须确定性、**可关闭**、不得使用真实时间（`RY12`） |
| **D-6 介质条件细化** | 更精细的地层/岩性介质 | 只能读取 Geology 的只读输出（`RY15`）；如需新地层概念，须由 Geology 规范变更 |
| **D-7 资源与文明/经济联动** | 文明对资源的使用偏好 | 只能通过**只读**查询；不得回写历史或区域（`RX-7`） |
| **D-8 可解释性工具化** | 导出资源判定链与原因 | 只读工具；不得改变任何判定结果 |

**共同前提（所有扩展）**

1. 遵守 `RK1`–`RK10`（世界条件驱动、有原因、只读、可局部求值、可关闭）；
2. 保持 `RL1`–`RL18` 全部成立（确定性、因果正确、边界正确、无反向依赖、零修改）；
3. 不得新增 `VoxelType`、不得修改 VoxelCore / Geology / History / Region / WorldState / Ecology 的既有条款；
4. 若必须触及被 SHA 冻结的文件，走**显式授权 + 级联重钉**流程（`RF2`）；
5. 更新本文档的附录 B/C 并在实现规范中登记。
