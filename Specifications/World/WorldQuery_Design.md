# World Query System Design Specification V1

> **文档性质**：**设计规范（Design Specification）**。本文档只定义**查询语义**（概念 / 数据关系 / 规则 / 约束 / 验收标准）。
> **仅创建 Markdown**；**不修改任何代码**；**不创建 class / interface / struct**；**不设计具体实现**。
>
> **目标（一句话）**：
>
> > **给定 `Seed` 与**世界坐标**，如何查询该位置"完整的世界状态"。**
>
> **定位**：World Query 是**世界解释入口（World Explanation Entry）**——它是"读世界"的唯一入口，
> 不生成世界、不缓存世界、不划分世界、不拥有对象。

## 1. World Query 的定位

### 1.1 定义

> **World Query = 世界解释入口。**
>
> 输入：`Seed` + **世界坐标**（一个点，或一个显式的点集合）
> 输出：**World Explanation**（该位置的完整世界状态解释，只读）

| 要素 | 内容 |
|---|---|
| 输入单位 | **世界坐标点**（不是 Chunk、不是区域、不是屏幕像素） |
| 输出内容 | 该点的：骨架事实 / 历史事实 / 区域归属与修正 / 8 个环境参数 / 群系结论 / 地形真值 / 生态候选 / 资源判定 **+ 判定链** |
| 输出性质 | **只读解释结果**：不是世界数据、不是对象、不是指令 |
| 是否产生副作用 | **零副作用**（不写 Voxel、不建 Chunk、不生成对象、不改任何上游） |

### 1.2 World Query **不是**什么

| 不是 | 说明 |
|---|---|
| **不是生成器** | 不产生 Chunk / Voxel / Mesh / 对象；生成链的终点仍是 Phase 7 Voxel Output（`WorldGeneration_Pipeline_Design.md`） |
| **不是缓存** | 缓存是**实现细节**，不是它的身份。查询语义必须**在没有缓存时同样成立**（缓存不得成为权威、不得改变输出） |
| **不是 Chunk** | Chunk 是**管理/调度单位**（ADR-001），查询以**世界坐标**为单位；任意点可查，且不要求任何 Chunk 已加载 |
| **不是 Entity** | 不是对象、没有生命周期、没有状态、不参与所有权体系 |
| **不是第二套世界模型** | 查询必须**复用生成所用的同一套规则**（§1.3）；禁止为查询定义简化的第二套规则 |
| **不是规则权威** | 本文档不定义任何层的规则，只定义"怎么问、能问什么、结果的权限" |

### 1.3 核心原则：同一规则、只读求值

| # | 规则 |
|---|---|
| **WQ1** | 查询链中的每一层**必须**使用该层规范定义的**同一套规则**（生成用什么规则，查询就用什么规则） |
| **WQ2** | **禁止**为查询定义第二套规则、第二套阈值、第二套简化模型（否则"查询结论 ≠ 生成结论"必然出现） |
| **WQ3** | 查询与生成的区别**只有两点**：① 查询**不写**任何产物（体素 / 状态 / 对象）；② 查询以**解释**为目的，必须附带判定链 |
| **WQ4** | 查询结果是**消费者**：**不得**成为任何生成阶段（Phase 1–7）的输入（否则形成环） |
| **WQ5** | 查询必须**无副作用**：不改变任何层的求值结果，也不改变世界的可再次查询性 |
| **WQ6** | 查询**不拥有状态**：不要求"世界实例"存活，不要求跨帧存在（§5） |

### 1.4 一次查询的结果构成（概念）

| 组 | 内容 | 权威规范 |
|---|---|---|
| **骨架** | 陆地/海洋、高程带、气候带、水系倾向 | 上游骨架规范（`Pipeline` Phase 1） |
| **历史** | 与**该位置相关**的事件事实、纪元序位、`HistoryTags` | `WorldHistory_Design.md` |
| **区域** | 影响该位置的来源类别、合成后的修正、只读标签 | `Region_Design.md` |
| **环境** | 8 个参数（`FinalState`） | `WorldState_Design.md` |
| **群系** | Biome 结论 | `WorldState_Design.md` §5.3 |
| **地形** | `Density` / `Material` / 地层 / `CaveDensity` / 地质矿藏判定 | `WorldGeneration_Geology*.md` |
| **生态** | 该位置允许的生态候选（植物/动物/资源载体/窝点） | `Ecology_Design.md` |
| **资源** | 该位置的资源判定（类别 / 等级 / 形态资格） | `Resource_Design.md` |
| **解释** | 上述每一项的**判定链**（原因 → 条件 → 结论） | 本文档 §6 |

## 2. 完整查询链

### 2.1 查询链（唯一顺序）

```
Position + Seed
      ↓
 0. 输入归一化（世界坐标；与 Chunk 无关）
      ↓
 1. World Skeleton Query          （陆地/海洋、高程带、气候带、水系倾向）
      ↓
 2. History Query                 （与该位置相关的事件事实、纪元序位、历史标签）
      ↓
 3. Region Query                  （影响该位置的来源、修正、标签）
      ↓
 4. WorldState Evaluation         （FinalState = Base + RegionModifier，8 个参数）
      ↓
 5. Biome Resolution              （Biome 结论）
      ↓
 6. Geology Evaluation            （地形真值：Density / Material / 地层 / CaveDensity / 地质矿藏）
      ↓
 7. Ecology Candidate  ∥  Resource Candidate   （两个并列分支，互不依赖）
      ↓
World Explanation（只读解释结果 + 判定链）
```

### 2.2 各步的输入 / 输出 / 权威

| 步 | 层 | 输入（只能读这些） | 输出 | 权威规范 |
|---|---|---|---|---|
| 0 | 输入归一化 | `Seed` + 世界坐标 | 规范化查询点（世界坐标） | `VoxelWorld_Core.md` §3（坐标规则） |
| 1 | World Skeleton Query | `Seed` + 显式世界参数 | 骨架事实（大陆/海洋/高程带/气候带/水系倾向） | `Pipeline` §2.3 / 骨架规则 |
| 2 | History Query | `Seed` + 骨架事实 | 与**该位置相关**的事件事实 + 纪元序位 + `HistoryTags` | `WorldHistory_Design.md` |
| 3 | Region Query | `Seed` + 历史事实 + 骨架事实 + 自然规则 | 影响该点的来源集合、合成修正、区域标签 | `Region_Design.md` |
| 4 | WorldState Evaluation | `BaseWorldState`（骨架提供）+ `RegionModifier` | `FinalState`（8 个参数） | `WorldState_Design.md` |
| 5 | Biome Resolution | `FinalState`（只读） | Biome | `WorldState_Design.md` §5.3 |
| 6 | Geology Evaluation | 世界坐标 + 显式地质参数 + Biome（**仅用于 P3 地表材料**） | `Density` / `Material` / 地层 / `CaveDensity` / 地质矿藏判定 | `WorldGeneration_Geology*.md` |
| 7a | Ecology Candidate | `FinalState` + Biome + 区域标签（只读）+ 地质地形（只读，用于地形庇护） | 生态候选（植物/动物/资源载体/窝点） | `Ecology_Design.md` |
| 7b | Resource Candidate | `FinalState` + 地质判定（介质/矿藏）+ 区域信息 + 历史标签（**仅归因**） | 资源判定（None / Substrate / Present） | `Resource_Design.md` |

### 2.3 硬性规则

| # | 规则 |
|---|---|
| **WN1** | 链是**单向**的：每一步只能读取**上游**（含自身输入），**禁止**读取下游 |
| **WN2** | **禁止跳过**中间层：例如"直接由历史事实推出资源"是禁止的（必须经环境参数，`Resource_Design.md` RZ1） |
| **WN3** | **7a 与 7b 互不依赖**：生态候选不得读取资源判定；资源判定不得读取生态候选（`Ecology_Design.md` `EB-*`、`Resource_Design.md` `RX-8`） |
| **WN4** | **7a / 7b 的顺序不影响结果**（可交换、可并行、可分别调用）；本文档的展示顺序为 Ecology → Resource（与目标链一致），而 `Resource_Design.md` §8.2 表述为 Resource 在前；两者**语义一致**，因为两者**无依赖**（见 §7.3 接触点②） |
| **WN5** | 查询**不得**产生任何生成产物（体素 / Chunk / Mesh / 对象） |
| **WN6** | 查询**不得**建立"世界级"中间集合（不得枚举全部 Region / 全部 Biome / 全部事件，§5） |
| **WN7** | 查询的每一步都必须可**独立重复求值**（同输入同输出） |
| **WN8** | 查询链**不新增 Pipeline 阶段**：1–6 与 Phase 1–6 使用同一套规则，7a/7b 是 Phase 6 之后的旁路判定层 |
| **WN9** | 查询结果必须与**各层规范的结论一致**（交叉比对是验收项，§9 `WA17`） |
| **WN10** | **Geology 必须显式列入查询链**（第 6 步）：完整世界状态包含地形真值，且 Resource（介质/矿藏）与 Ecology（地形庇护）都依赖它 |

### 2.4 关于 Geology 在链中的位置（口径说明）

| 说明 | 内容 |
|---|---|
| 目标链未显式列出 Geology | Geology 是**地形真值**（可以理解为"世界的实体事实"而非"解释"），因此目标链把它隐含在环境/群系之后 |
| 本文档的处理 | **显式**列入第 6 步（`WN10`）：因为①"完整世界状态"必须包含地形真值；②`Resource` 需要地质**介质与矿藏**条件；③`Ecology` 需要地质**地形庇护**条件（`Ecology_Design.md` EN2/EN4） |
| 与生成链的关系 | 使用**同一套** Geology 规则（`WQ1`）；区别只是查询**不写体素** |

## 3. 各层权限（可读 / 禁止读）

### 3.1 权限总表

| 层 | **可以读取** | **禁止读取** |
|---|---|---|
| **0 输入归一化** | `Seed`、世界坐标 | 一切其它 |
| **1 Skeleton** | `Seed`、显式世界参数 | History / Region / WorldState / Biome / Geology / Ecology / Resource / Voxel / Chunk |
| **2 History** | `Seed`、骨架事实、显式历史参数 | Region / WorldState / Biome / Geology / Ecology / Resource / **`DepositZone`** / Voxel / 玩家状态 |
| **3 Region** | `Seed`、历史事实（只读）、骨架事实、自然规则、地形派生量（`Elevation` / `Ocean` 只读） | WorldState 结果 / Biome / Geology 细节 / Ecology / Resource / 已生成内容 / Chunk 状态 |
| **4 WorldState** | `BaseWorldState`（骨架）、`RegionModifier` | `HistoryTags` / Biome / 生态 / 资源 / 对象 / Voxel |
| **5 Biome** | `FinalState`（只读） | Region 内部属性 / 来源列表 / 生态 / 资源 / Geology / Voxel |
| **6 Geology** | 世界坐标、显式地质参数、Biome（**仅 P3 地表材料**） | History / Region / WorldState 语义 / Ecology / Resource / Voxel 写入 |
| **7a Ecology** | `FinalState`、Biome、区域只读标签（`HistoryTags` / 来源类别 / 区域级资格）、地质地形（只读：洞穴/高程，用于地形庇护） | **`RegionType`** / `RegionView` / **Resource 判定** / 玩家状态 / 已生成内容 |
| **7b Resource** | `FinalState`、地质判定（介质/矿藏/地层）、区域信息、`HistoryTags`（**仅归因，不作判定条件**） | **Biome** / **`RegionType`** / **Ecology 候选** / 玩家状态 / 时间源 / 已生成内容 |

### 3.2 硬性规则

| # | 规则 |
|---|---|
| **WP1** | 每层的输入集合是**封闭的**（表外不读） |
| **WP2** | **禁止越权读取下游**：任何层读取其下游产物即为缺陷（`Pipeline` RB-·） |
| **WP3** | **禁止读取结果侧标签作为规则输入**：`RegionType`（无规则权，`Region_Design.md` RTY2）、`RegionView`（结果侧，RT6）一律禁止 |
| **WP4** | **禁止读取消费侧状态**：玩家、背包、任务、已采集统计、已加载 Chunk、帧序、tick |
| **WP5** | **禁止写入任何东西**：查询全链**零写入**（不写 Voxel / 不写参数 / 不写标签 / 不建 Chunk / 不生成对象） |
| **WP6** | 查询**不得**要求"先初始化世界"或"先建立全局索引"（§5） |

## 4. 确定性

### 4.1 定义

> **同一个 `Seed` + 同一个 `Position` ⇒ 完全一致的查询结果。**

| # | 规则 |
|---|---|
| **WD1** | 结果一致的范围包括：骨架事实 / 历史事实 / 区域归属与修正 / 8 个参数 / Biome / 地形真值 / 生态候选 / 资源判定 / **判定链** |
| **WD2** | 一致性必须对**任意时刻、任意顺序、任意机器状态**成立（`WorldGeneration_Core.md` §2、`Pipeline` PG1） |
| **WD3** | **反例保护**：不同 `Seed`（或不同显式参数）必须能产生**至少一处**不同结果——否则"一致"是恒真断言，不可信 |
| **WD4** | 机械证据：结果必须可用**逐项比较**（字段级）与**内容哈希**两种方式验证 |

### 4.2 域分离（查询层同样适用）

| # | 规则 |
|---|---|
| **WD5** | 每一层的求值必须由 `(Seed, Domain, Position)` 唯一确定（`Pipeline` §3.3 PE1–PE7） |
| **WD6** | 各层**不得共享随机序列**；查询过程不得引入"跨层共享状态"（`Pipeline` PG6） |
| **WD7** | 查询**不改变**任何层的域标签与域参数（新增层只能新增域） |

### 4.3 禁止事项

| # | 禁止 |
|---|---|
| **WD8** | `Random()` / `UnityEngine.Random` / `System.Random` / 任何有状态伪随机源 |
| **WD9** | **时间**：`Time` / `DateTime` / 时间戳 / 真实时长 / tick / 帧序 / `Guid`（"时间积累"只能按 `WorldHistory_Design.md` 的**纪元跨度**表达，`Resource_Design.md` RY11–RY14） |
| **WD10** | **玩家状态**、加载顺序、已加载 Chunk 集合、查询顺序、遍历顺序、世界级中间态 |
| **WD11** | 由**下游结果**反推上游（Biome→Region、资源→历史、生态→环境 等一切反向推出，`Pipeline` RB-·） |
| **WD12** | **查询缓存污染结果**：缓存（若实现）不得改变输出，不得成为权威，不得跨 `Seed`/参数复用（§5.3） |

## 5. 局部求值（Local Evaluation）

### 5.1 定义

> **必须支持：只查询一个点。**

| # | 规则 |
|---|---|
| **WL1** | 单点查询必须能**独立完成**：不依赖任何"世界级"前置步骤 |
| **WL2** | 单点查询的结果不得需要"已生成整个世界"才能得出 |

### 5.2 禁止事项（用户明确要求）

| # | 禁止 |
|---|---|
| **WL3** | **禁止生成整个世界**（不得为了回答一个点而枚举全世界） |
| **WL4** | **禁止保存所有 Region**（不得要求"先建立全局 Region 表"） |
| **WL5** | **禁止保存所有 Biome**（不得要求"先划分全世界群系"） |
| **WL6** | 禁止建立全局注册表/全局索引/全局事件表作为查询前置条件 |
| **WL7** | 禁止要求"连接所有大陆"或"生成所有历史"才能回答单点 |
| **WL8** | 禁止依赖邻域是否已查询过（不得出现"先查邻居才能查这里"） |

### 5.3 缓存（允许，但必须透明）

| # | 规则 |
|---|---|
| **WL9** | 允许缓存，但缓存**必须**：① 由 `(Seed, 参数, 世界坐标, 域标签)` 索引；② **不改变输出**；③ 可随时清空而结果不变；④ 不成为权威（权威永远是各层规范） |
| **WL10** | **禁止**跨 `Seed` / 跨参数复用缓存；**禁止**缓存成为"世界状态" |

### 5.4 成本与复杂度（语义要求，不是实现要求）

| # | 规则 |
|---|---|
| **WL11** | 单点查询的成本必须与**该点相关的来源/事实数量**相关，而不是与**世界总量**相关（`WorldHistory_Design.md` HN12、`Resource_Design.md` RK6） |
| **WL12** | 查询必须**可乱序**：任意查询顺序（含并发）都必须得到相同结果 |
| **WL13** | 查询必须**不要求**任何跨帧存活对象；连续两次查询之间不需要"世界实例"（`WQ6`） |

## 6. 解释能力（Explanation）

### 6.1 必须支持的问答

| # | 问题 | 必须能回答的内容 |
|---|---|---|
| 1 | **"为什么这里是森林？"** | 群系结论 ← 命中的规则表分支 ← `FinalState` 具体参数值与阈值 ← 区域修正来源 ← 骨架气候带 |
| 2 | **"为什么这里有魔晶？"** | 资源判定 = Present ← 三条件（`MagicDensity` 高 + 纪元跨度 + 合适介质）的**具体成立情况** ← 魔力来源（经 Region）← 历史事件（纪元/序位） |
| 3 | **"为什么这里腐化？"** | `CorruptionInfluence` 高 ← 腐化来源 ← 历史事实（灾难/邪恶遗迹/污染）经 Region Source → RegionModifier ← 环境参数 |
| 4 | **"为什么这里没有 X？"** | **必须支持"可解释的没有"**：指出**哪一条必需条件不成立**（而非"没有原因"） |

### 6.2 解释的结构（只读、确定性）

| # | 规则 |
|---|---|
| **WE1** | 每条解释必须包含四要素：**结论**（哪个层给出什么值/分类）、**直接条件**（参数值与阈值）、**所在层**、**上游原因**（来源/事件/骨架） |
| **WE2** | 解释必须按**因果方向**组织：`原因 → 条件 → 结论`（`WorldState_Design.md` §1.5 C1–C4） |
| **WE3** | **禁止由结果反推原因**：不得出现"因为是森林，所以湿润"这类解释；解释只能沿链向上回溯**已存在的原因** |
| **WE4** | 解释必须**确定性**：同一查询点的解释内容与顺序完全一致（可重复求值） |
| **WE5** | 解释必须**只读**：查询解释不得改变任何层的求值结果 |
| **WE6** | 解释必须**可定位到条件**："某个参数为 0.62，阈值 0.55，故命中"（而不是"因为世界规则"这类空泛表述） |
| **WE7** | 解释的粒度**到层与条件为止**：对象细节（具体结构、掉落、个体）不属于查询结果（对象不存在于世界状态中） |
| **WE8** | 解释必须覆盖链上**每一层的贡献**：即使某层贡献为 0（无来源、无修正），也必须显式说明"该层无影响" |

### 6.3 示例（形态说明，不是实现）

| 问题 | 解释链（上游 → 下游） |
|---|---|
| 为什么这里是森林？ | 骨架气候带（湿度带高、温度带中）→ 无关键区域修正 → `Moisture` 高 / `Temperature` 中 → 群系规则分支"温度中等 + 湿度高"命中 → **Forest** |
| 为什么这里有魔晶？ | 历史事件（魔法战争，纪元 = 千年段，序位 = 该段第 n 位）→ Region Source（魔法伤痕）采纳 → `RegionModifier`：`MagicDensity` ↑ → `MagicDensity` = 0.81（阈值 0.60）→ 纪元跨度 = 该纪元至今（足够）→ 介质：Deep 层矿体条件成立 → **Magic Crystal = Present** |
| 为什么这里腐化？ | 历史事实（亡灵灾难）→ 腐化来源候选 → Region 采纳 → `CorruptionInfluence` = 0.72（阈值 0.55）→ 群系分支"腐化高 + 肥力低"命中 → **CorruptedLand** |
| 为什么这里没有魔晶？ | 三条件中"纪元跨度"不成立（该处魔力来源出现较晚，积累不足）→ **判定 = Substrate（有介质与环境的资格，但未满足全部条件）** |

### 7.3 两个接触点详解

**接触点①：Geology 在查询链中的位置**

目标链未显式列出 Geology。本文档**显式**把它列为第 6 步（`WN10`），理由是
"完整世界状态"必须包含地形真值，且 `Resource`（介质/矿藏）与 `Ecology`（地形庇护）都需要它。
处理：查询与生成**共用同一套** Geology 规则；查询**只读**、写零副作用。→ **不冲突**（补全，不是改写）。

**接触点②：Ecology 与 Resource 的顺序表述差异**

| 处 | 表述 |
|---|---|
| 本文档查询链（目标链） | `Ecology Candidate → Resource Candidate` |
| `Resource_Design.md` §8.2③ | "求值顺序：Resource 在 Ecology 之前" |

处理：**两者无依赖关系**（`WN3`：生态不读资源、资源不读生态），因此**顺序不影响任何结果**。
本文档采用**可交换性条款**（`WN4`）对齐：
① 两个分支必须**互不读取**；② 任意顺序（含并行）结果必须**逐项一致**（§9 `WA12`）。
因此该差异是**展示顺序差异**，不是语义冲突。→ **不冲突**（已对齐）。

## 9. 验收规则

### 9.1 确定性

| # | 不变量 | 验证方法 |
|---|---|---|
| **WA1** | 同 `Seed` + 同 `Position` ⇒ **完全一致**（含判定链） | 双次/双世界逐项比较 |
| **WA2** | 不同 `Seed` ⇒ 至少一处不同（**反例保护**） | 差异断言 |
| **WA3** | 域分离：`(Seed, Domain, Position)` 唯一确定各层输出 | 分域对照 |
| **WA4** | 与加载顺序 / 帧序 / tick / 玩家状态 / 查询顺序无关 | 多顺序与并发顺序对照 |
| **WA5** | 重复查询恒等；查询无副作用（查询前后各层结果不变） | 前后快照比较 |
| **WA6** | 无非确定性来源（`Random()` / `Time` / `DateTime` / `Guid` / 真实时长） | 结构扫描 |

### 9.2 局部求值

| # | 不变量 | 验证方法 |
|---|---|---|
| **WA7** | 单点查询**不产生**世界级产物（全量 Region 集合 / 全量 Biome 集合 / 全量事件集合 = 0） | 结构性检查（无世界级前置产物） |
| **WA8** | 单点查询成本与"该点相关来源数"相关，而不是世界总量 | 求值范围检查 |
| **WA9** | 查询不依赖邻域是否已查询、不要求“先初始化世界” | 单点独立查询对照 |
| **WA10** | 缓存可清空且结果不变（透明缓存） | 清缓存前后对照 |
| **WA11** | 查询不要求跨帧存活对象（两次查询之间无世界实例） | 结构性检查 |

### 9.3 权限与因果

| # | 不变量 | 验证方法 |
|---|---|---|
| **WA12** | **7a / 7b 可交换**：任意顺序（含并行）结果逐项一致，且二者互不读取 | 顺序打乱对照 + 结构扫描 |
| **WA13** | 每层读取集合封闭；越权读取 = 0（含 `RegionType` / `RegionView` / 下游产物 / 玩家状态） | 权限矩阵校验 + 结构扫描 |
| **WA14** | 沿链**无跳过**（无"事件 → 资源"直连等短路） | 结构扫描 + 判定链检查 |
| **WA15** | 解释按**因果方向**组织，无结果反推原因 | 判定链问答 + 结构扫描 |
| **WA16** | 解释必须包含四要素（结论 / 直接条件 / 所在层 / 上游原因），且能解释"**没有**" | 问答检查（附录 D 模板） |
| **WA17** | **一致性**：查询结论与各层规范的结论**逐项一致**（同 Seed、同坐标、同参数） | 交叉比对（查询 vs 各层独立求值） |

### 9.4 无副作用 · 零修改 · 不新增权威

| # | 不变量 | 验证方法 |
|---|---|---|
| **WA18** | 查询不写 Voxel / 不建 Chunk / 不生成对象；开关查询 ⇒ 体素**逐体素一致** | 两态体素快照比较（差异 = 0） |
| **WA19** | 不新增 `VoxelType`；既有实现与既有规范 SHA 不变 | 结构性检查 + 文件哈希比对 |
| **WA20** | 无第二套规则/阈值：查询与生成使用同一套（可机械比对条件集合） | 条件集合比对 |

| **WX-4** | 查询产生对象 | 查询时生成 Entity / 结构 / 物品 | 结构扫描：无对象产出 |
| **WX-5** | 世界级前置 | "先枚举所有 Region / 所有 Biome / 所有事件" | 结构扫描：无全量集合（`WA7`） |
| **WX-6** | 生成整个世界 | 为了回答一个点而生成整个世界 | 求值范围检查 |
| **WX-7** | 越权读下游 | Region 读 WorldState 结果；Biome 读 Region 属性；Resource 读 Biome | 权限矩阵校验（`WA13`） |
| **WX-8** | 结果侧标签作输入 | `RegionType == MagicForest ⇒ …` | 结构扫描（类型标签不作条件） |
| **WX-9** | 短路 | 历史事件 → 资源判定（跳过 WorldState） | 判定链检查（`WA14`） |
| **WX-10** | 结果反推原因 | "因为是森林，所以湿润" | 判定链问答（`WA15`） |
| **WX-11** | 非确定性来源 | `Random()` / `Time` / `DateTime` / 玩家状态 | 结构扫描（`WA6`） |
| **WX-12** | 查询顺序影响结果 | 先查邻居后查本点结果不同 | 乱序/并发对照（`WA4`/`WA12`） |
| **WX-13** | 查询反馈生成 | 生成阶段读取查询结果 | 依赖方向检查（`WQ4`） |
| **WX-14** | 第二套规则 | 查询另有一套阈值/简化判定 | 条件集合比对（`WA20`） |

## 附录 D：解释问答模板与未来扩展

### D.1 解释问答模板（每条解释必须能填满）

| 要素 | 内容 |
|---|---|
| **问** | 为什么这里 <X>？（或：为什么这里没有 <X>？） |
| **结论** | 哪一层给出什么结论（值 / 分类 / 判定等级） |
| **直接条件** | 具体参数值 + 阈值 + 命中/未命中的条件 |
| **所在层** | 该结论由哪一层规则产生 |
| **上游原因** | 来源 / 历史事件 / 骨架事实（经链条传递） |
| **无影响的层** | 显式说明"某层贡献为 0"（`WE8`） |
| **未满足条件**（用于"没有"） | 指出**哪一条必需条件不成立**（`WE4`/§6.1 第 4 项） |

### D.2 未来扩展方向

| 方向 | 说明 | 前提（硬性） |
|---|---|---|
| **E-1 批量 / 区域查询** | 一次查询一个范围 | 仍必须满足 `WL1`–`WL13`（不得因此引入世界级前置）；属未来规范 |
| **E-2 查询工具与可视化** | 调试面板、解释导出 | 只读工具；不得改变查询结果 |
| **E-3 解释模板与本地化** | 解释文本化 | 文本只是**展示**；不得由文本反推判定 |
| **E-4 查询级缓存策略** | 透明缓存参数的工程化 | 必须满足 `WL9`/`WL10` |
| **E-5 对象与内容查询** | "这里有什么生物/结构" | 属未来 Entity / Structure 系统；查询只回答资格 |
| **E-6 时间切片查询** | "100 年前这里是什么样" | 需要**独立规范**定义世界时间语义（V1 无"现在"概念，`WorldHistory_Design.md` HE3） |

**共同前提（所有扩展）**

1. 遵守 `WQ1`–`WQ6`（同一规则、只读求值、无副作用、无状态、不反馈生成）；
2. 保持 `WA1`–`WA20` 全部成立；
3. 不新增 `VoxelType`、不修改 VoxelCore、不修改任何既有规范与既有实现；
4. 查询不得接触 Runtime / Chunk / Mesh / Entity 的实现；
5. 若必须触及被 SHA 冻结的文件，走**显式授权 + 级联重钉**流程（`WF3`）。
