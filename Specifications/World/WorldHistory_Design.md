# World History Design Specification V1

> **文档性质**：**世界历史规则设计规范**。本文档定义 History 的概念、数据关系、生成规则、约束与验收标准；它本身不承担运行时代码实现。
> 原始起草轮次中“仅创建 Markdown / 不修改 Assets / 不创建代码”的要求只描述当时任务范围，不是当前开发的永久限制。实现应由对应实现任务与规范决定，并遵守本文定义的职责与因果边界。
>
> **定位**：History 层位于 **World Skeleton 之后、Region 之前**，是**所有世界状态变化的原因来源**。
>
> **既有的世界架构（本文档必须与之一致）**：
>
> ```
> Seed
>  ↓
> World Skeleton
>  ↓
> History            ← 本文档
>  ↓
> Region Source
>  ↓
> Region Modifier
>  ↓
> WorldState
>  ↓
> Biome
>  ↓
> Geology            （Phase 6：只经 Biome 的 P3 地表材料受上游影响）
>  ↓
> Ecology            （Phase 5 之后的旁路层，见 `Ecology_Design.md` §1.5）
> ```
>
> **必须兼容的上游规范**：
>
> | 规范 | 与本 History 的关系 |
> |---|---|
> | `Specifications/World/WorldState_Design.md` | §1.5 倒因为果禁令（C1–C4）、§6 世界历史与遗迹（HR1–HR5）、§6.2 因果链、§6.3 文明偏好、§6.4 遗迹位置规则、§7.3 世界尺度（无限海洋 + 有限大陆） |

## 1. History 的定位

### 1.1 定义

> **History 是 `Seed` 决定的"世界过去状态"。**

| 问题 | History 的回答 |
|---|---|
| 这个世界过去发生过什么？ | 事件集合（类型 / 时间序位 / 地点 / 参与文明） |
| 谁在这片土地上活动过？ | 文明活动（活动范围 / 活动类型 / 纪元序位） |
| 这些过去留下了什么可读的事实？ | Historical Tags |
| 哪些过去是"世界状态变化"的原因？ | Region Source 候选 |

### 1.2 History **不是**剧情系统

| History **不是** | 说明 |
|---|---|
| **NPC 行为记录** | 不记录个体、不记录队伍、不记录人物关系；没有 NPC |
| **实时模拟** | 没有世界时钟、没有"每隔 N 年推进一次"、没有随时间演化的历史状态（`Pipeline` PH1） |
| **Quest 系统** | 不定义任务、目标、奖励、触发条件 |
| **文本故事生成** | 不生成叙事文本、不生成对白、不生成传说条目；只产出**结构化事实**与标签 |
| **人口 / 经济模拟** | 不模拟人口、资源消耗、贸易、生产 |
| **对象生成器** | 不生成 Entity / NPC / Structure / Quest（`Pipeline` PJ1–PJ3） |

### 1.3 输出（只有四类）

| # | 输出 | 含义 | 消费者 |
|---|---|---|---|
| 1 | **History Event** | 历史事件：原因记录（类型 / 时间序位 / 地点 / 参与文明） | Region 层（经来源候选）、未来系统（只读） |
| 2 | **Civilization Activity** | 文明活动：活动范围 + 活动类型 + 纪元序位 | 遗迹候选推导（本文档 §5）、未来系统（只读） |
| 3 | **Historical Tags** | 只读历史事实标签（纪元 / 事件类别 / 参与文明 / 结果类别） | Region 层（`Region_Design.md` RH2）、Ecology（`Ecology_Design.md` EG4）、未来系统（只读） |
| 4 | **Region Source Candidates** | 区域来源候选（位置 / 类别 / 强度倾向 / 尺度倾向 / 原因链） | **Region 层采纳**（`Pipeline` PI1、`Region_Design.md` RS1） |

### 1.4 禁止：History 直接生成

| # | 禁止 | 理由 |
|---|---|---|
| **HS1** | 直接生成 **Entity** | 对象属未来 Entity 系统（ADR-001） |
| **HS2** | 直接生成 **NPC** | 同上；History 不包含个体 |
| **HS3** | 直接生成 **Structure**（建筑 / 城市 / 道路 / 遗迹结构） | 结构属未来 Structure 系统；History 只产出候选区域 |
| **HS4** | 直接生成 **Quest** | 任务属未来 Quest 系统 |
| **HS5** | 直接写 Voxel、创建 Chunk、置脏、生成 Mesh | 违反"真值由 Geology 判定链产生"的唯一权威 |
| **HS6** | 直接创建 Region / 修改 `RegionModifier` | Region 是 Region 层的产出（`Region_Design.md` EG3） |
| **HS7** | 直接修改环境参数（`WorldState`） | 参数只能来自 `Base + RegionModifier`（`RM5`） |
| **HS8** | 实时推进历史（事件随时间发生 / 扩散 / 结束） | V1 为静态事实（§7 / §9） |

### 1.5 与 Pipeline 的关系

| # | 规则 |
|---|---|
| **HS9** | History = Pipeline 的 **Phase 2**（`WorldGeneration_Pipeline_Design.md` §2.1）；本文档**不新增阶段**、不改变 Phase 顺序 |
| **HS10** | History 的输入**封闭**：只有 `Seed` + 世界骨架（只读）+ 显式历史参数（`Pipeline` PA1/§4.1 PH4） |
| **HS11** | History 的产出**只被下游读取**；History 自身**不得读取任何下游产物**（§4 / §8） |
| **HS12** | History 必须**可局部查询**：给定世界坐标或范围，可独立求出该处的历史事实与来源候选，不需要遍历全世界（`Pipeline` PG5） |

## 2. 历史事件模型

### 2.1 定义

> **`Event = Cause`**（事件即原因）
>
> 每个历史事件都是一条**原因记录**：它解释"为什么某个世界状态变化存在"。

### 2.2 事件属性（必需）

| 属性 | 含义 | 约束 |
|---|---|---|
| **Time（时间）** | 事件的相对时间（纪元 + 序位） | **相对序位**，不是真实时间（§2.3） |
| **Location（地点）** | 事件发生的世界位置/区域 | 由世界规则决定（§2.4），不得随机 |
| **Civilizations（参与文明）** | 参与或受影响的一方或多方 | 从文明集合中取值（§2.5） |
| **Type（事件类型）** | 事件类别（§2.6，至少 6 类） | 显式枚举 |
| **Magnitude（尺度）** | 事件的强度/影响范围倾向 | 显式参数；决定来源候选的强度/半径倾向 |

### 2.3 时间：相对序位（不是真实时间）

**时间取值形态（示例）**：

| 称谓 | 语义 |
|---|---|
| **远古时代** | 最早的纪元段 |
| **1000 年前** | 千年量级的纪元段 |
| **100 年前** | 百年量级的纪元段 |

| # | 规则 |
|---|---|
| **HE1** | 时间必须表示为 **`Epoch`（纪元段）+ `Ordinal`（段内序位）**，二者都由 `Seed` 确定性派生 |
| **HE2** | **禁止**绝对日期、时间戳、世界时钟、`Time` / `DateTime` / `Guid`（`Pipeline` PD4） |
| **HE3** | **不存在"现在"**：历史是固定的过去事实集合；世界的"当下"就是 History 的终点 |
| **HE4** | 时间**只用于**：① 排序与归因；② 决定后续活动是否存在（例如文明衰落后不再扩展活动范围）；③ 可解释性表述 |
| **HE5** | 时间**不得**引入覆盖语义（"后来的覆盖先前的"）、衰减语义、胜负演化——否则会破坏 Region 叠加的**交换律**（`Region_Design.md` RO1）与"无放大反馈"（RO5） |
| **HE6** | 同一位置可以存在多个纪元的多个事件；它们**同时成立**并**叠加**（不互相删除） |

### 2.4 地点：由世界规则决定

```
Location(Event) = f（世界骨架, 文明偏好, 事件类型, 显式参数, Seed, Domain=History.*）
```

**可读的骨架量（白名单，只读）**

| 骨架量 | 说明 |
|---|---|
| 陆地 / 海洋框架 | 大陆掩码、海岸线、（骨架级）海陆判定 |
| 基础高度框架 | 高地 / 山脉带 / 平原（来自既有 `HeightFunction` 的高程带） |
| 基础气候带 | 温度带 / 湿度带基线 |
| 水系倾向 | 由高程与湿度基线派生的河流 / 河谷倾向（骨架级，可选） |

| # | 规则 |
|---|---|
| **HE7** | 事件地点必须由**世界规则**推导，且必须**可解释**（"为什么事件发生在这里"） |
| **HE8** | 地点必须**可局部枚举**：给定范围可求出该范围内的事件；给定坐标可判定是否在某事件影响范围内 |
| **HE9** | **禁止**随机撒点、禁止按 Chunk 分配事件、禁止"每 N 个 Chunk 放一个事件" |
| **HE10** | `Ocean == true` 的坐标只能承载**显式的海上/水下事件类型**；陆地类事件不得落在海洋 |
| **HE11** | 事件地点不得依赖任何下游产物（不得读 `DepositZone` / `CaveDensity` / Biome / `MagicDensity` / 体素数据） |

### 2.5 参与文明

| 文明 | 说明 |
|---|---|
| **Human** | 人类 |
| **Elf** | 精灵 |
| **Dwarf** | 矮人 |
| **Demon** | 恶魔（腐化侧） |
| **Ancient Civilization** | 远古文明（更早纪元、更少事件、更强影响倾向） |

| # | 规则 |
|---|---|
| **HE12** | 文明集合是**显式枚举**（V1 至少包含上表 5 项）；新增文明必须显式登记 |
| **HE13** | 每个文明必须给出**偏好条件**（§3.2）与**活动类型**（§3.3）；偏好必须能映射到**骨架级白名单量**（§2.4）或**本层自产候选** |
| **HE14** | 文明之间**不得互相读取状态**（除**显式**的互动事件类型，例如战争、圣恶冲突） |

### 2.6 事件类型（至少 6 类）与来源候选映射

| 事件类型 | 语义 | 典型产生的 Region Source 候选 |
|---|---|---|
| **战争** | 文明冲突 / 魔法战争 | 魔法伤痕（MagicScar）、腐化（战场与死亡）、圣恶对抗痕迹 |
| **魔法实验** | 法师实验 / 仪式（含失败） | 高强小半径魔力源、封印（MagicSeal）、魔力水晶倾向 |
| **灾难** | 亡灵灾难 / 污染 / 大范围破坏 | 腐化区域、污染区域 |
| **文明兴衰** | 兴起 / 覆灭 / 迁徙 | 文明活动范围、遗迹候选（§5） |
| **圣恶冲突** | 圣性与腐化的对抗 | 圣地、腐化区（可形成"争夺带"） |
| **发现与开采** | 矿脉发现 / 大规模开采 | 矿业活动区记录、工坊遗迹候选 |

| # | 规则 |
|---|---|
| **HE15** | 事件类型是**显式枚举**；每类必须给出：允许的纪元范围、参与文明约束、地点约束、来源候选类别 |
| **HE16** | **禁止**"结果型事件"：事件类型不得由下游产物命名/触发（例如"因为这里是魔法森林，所以发生魔法战争"） |
| **HE17** | 事件必须**有参与者**（至少一个文明，或显式的自然事件标记）；不得存在"无原因事件" |

## 3. 文明模型

### 3.1 定义

> **文明 = 偏好 + 活动范围 + 产物倾向。**

| 组成 | 含义 | 是否产出对象 |
|---|---|---|
| **偏好（Preference）** | 文明倾向占据的环境条件（骨架级白名单量 / 本层自产候选） | ❌ |
| **活动范围（Activity Extent）** | 偏好条件在世界中的满足区域（确定性、可查询） | ❌ |
| **活动类型（Activity Kind）** | 该文明在此范围内做过什么（开采 / 建造 / 研究 / 战争 / 迁徙） | ❌ |
| **产物倾向（Product Tendency）** | 该文明活动可能留下的**遗迹候选类别** | ❌（候选 ≠ 对象） |

### 3.2 文明偏好表（示例，V1 设计）

| 文明 | 偏好（骨架级条件） | 典型活动范围 | 产物倾向（**遗迹候选类别**） |
|---|---|---|---|
| **Dwarf（矮人）** | 山脉 / 高地（高程带高）、山体规模大、湿度低；**地下倾向用高程带代理**（不得读取洞穴信息） | 山地 / 高地 / 山体内部倾向 | 矿坑、城市遗迹、**工坊** |
| **Elf（精灵）** | 森林倾向（湿度带高 + 温度带适宜）+ **本层自产的魔法来源候选** | 森林带 | 古树区域、**魔法遗迹** |
| **Human（人类）** | 河流 / 平原（低高程带 + 水系倾向 + 湿度中以上）；交通便利倾向（平原 + 水系 + 海岸组合） | 平原 / 河谷 / 海岸 | 城镇、道路、战场 |
| **Demon（恶魔）** | 腐化倾向（**本层自产的腐化来源候选**）+ 极端/荒芜地形倾向 | 腐化区 / 荒地 | 祭坛、魔物据点遗迹 |
| **Ancient Civilization（远古文明）** | 大型水系 / 海岸 + 远古地标倾向（本层自产的高强来源候选）；不受后世文明偏好约束 | 早期宜居带 | 巨型遗迹、封印构造倾向 |

> 上表是**规则示例**，不是实现清单；所有条件必须表达为**显式参数 + 骨架级白名单量**。

### 3.3 活动类型（记录，不是模拟）

| 活动类型 | 语义 | 可能留下的候选 |
|---|---|---|
| **开采** | 大规模采集/挖掘 | 矿坑、工坊（§5） |
| **建造** | 聚落与设施建设 | 城镇遗迹、道路遗迹 |
| **研究** | 魔法/技术活动 | 魔法遗迹、封印 |
| **战争** | 冲突与破坏 | 战场遗迹、魔法伤痕 |
| **迁徙** | 范围迁移与废弃 | 废弃聚落、废弃道路 |

| # | 规则 |
|---|---|
| **HC1** | 活动是**记录**："在某纪元段、在某范围内、发生过某类活动" |
| **HC2** | **禁止**人口模拟、经济模拟、个体行为、时间推进（`Pipeline` PJ1–PJ4、本文档 §9） |
| **HC3** | 活动范围必须由偏好条件**推导**，不得随机撒布 |
| **HC4** | 活动必须可解释：`偏好条件 → 活动范围 → 活动类型 → 候选` |
| **HC5** | 文明不得读取其它文明的活动/范围状态；互动只能通过**显式事件类型**（战争 / 圣恶冲突）表达 |
| **HC6** | 活动的产物**只能是候选**；具体结构、对象、存档属未来系统 |
| **HC7** | 文明偏好**不得读取下游产物**：`DepositZone`、洞穴、Biome、`MagicityDensity` 等一律不可读（§4.4 / §8.3） |
| **HC8** | 当"矿产丰富"这类偏好无法用骨架级量表达时，V1 使用**地形代理条件**（山脉 + 高地），并把"矿业驱动"登记为**上游待扩展依赖**（§8.4） |

## 4. 因果规则

### 4.1 唯一允许的因果链

```
Event（原因：历史事件）
   ↓
Region Source（区域来源候选 → 由 Region 层采纳）
   ↓
World Modifier（Region 对环境的修正）
   ↓
Biome（环境表现）
   ↓
Ecology（生态解释，旁路）
```

| # | 规则 |
|---|---|
| **HG1** | 因果链**只有一个方向**：从上到下；任何一级都不得跳过（`Ecology_Design.md` `E-2` 不短路） |
| **HG2** | 事件是**原因**；世界状态、群系、生态都是**结果**；结果不得成为原因（`WorldState_Design.md` §1.5 C1–C4） |
| **HG3** | 事件**只**通过 `Region Source 候选 → RegionModifier` 影响世界；History 不得直接写参数（`HS7`） |
| **HG4** | 同一位置的多条因果链**叠加**，不得互相覆盖（`HE5`、`Region_Design.md` RO1） |

### 4.2 禁止反向因果（含用户点名示例）

| 禁止（错误方向） | 必须（正确方向） |
|---|---|
| **`Biome → History`** | `History → Region Source → … → Biome` |
| **"生成魔法森林，所以创造魔法战争"** | **"发生魔法战争，所以产生魔法森林"** |
| "看到腐化区域，所以补写亡灵灾难" | "发生亡灵灾难，所以产生腐化区域" |
| "这里有精灵遗迹，所以这里应该是森林" | "这里气候适宜森林，精灵活动过，所以留下遗迹候选" |
| "有个巨坑，所以这里打过仗" | "这里发生过战争，所以留下了巨坑候选（对象化由未来系统决定）" |

### 4.3 因果规则（硬性）

| # | 规则 |
|---|---|
| **HG5** | **禁止反向读取**：History 不得读取 Region / RegionModifier / WorldState / Biome / Geology / Ecology / Voxel 产物 |
| **HG6** | **禁止由结果命名原因**：事件类型不得由"想要的世界形态"反推（禁止"我想要魔法森林，所以编一个魔法战争"） |
| **HG7** | **禁止结果回写**：任何下游产物（标签、候选、对象）都不得被写回事件集合 |
| **HG8** | 事件与候选必须是 `Seed + Domain + Position` 的确定性函数（§7） |
| **HG9** | **禁止短路**：不得由"来源候选"直接推出生态或群系形态；必须走完环境层（`Region_Design.md` RB1–RB3） |
| **HG10** | 事件不得依赖玩家状态、进度、加载集合、帧序、tick（§7.3） |
| **HG11** | 历史产物不得成为 Phase 6（Geology）/ Phase 7（Voxel）的输入；对 Geology 的唯一影响路径是 `Biome → P3 地表材料` |
| **HG12** | 历史事实必须**可解释**：每个事实都能回答"为什么会发生、在哪里、何时（序位）、谁参与" |
| **HG13** | 历史产物必须**可枚举且有界**：给定范围可求出事实子集；全量事实必须由显式参数限定规模（§6.3） |
| **HG14** | 不得存在"孤立事实"（无法回溯到事件或文明活动的事实） |

### 4.4 依赖方向矩阵（History 视角）

| 对象 | History 是否可读 | 说明 |
|---|---|---|
| `Seed` | ✅ | 确定性的唯一来源 |
| 世界骨架（陆地/海洋 / 高程带 / 气候带 / 水系倾向） | ✅ | Phase 1 产物，只读 |
| 显式历史参数 | ✅ | 事件密度、文明数量、纪元划分等 |
| **本层自产候选**（来源候选、活动范围、标签） | ✅ | 同阶段内部使用（例如精灵偏好"魔力来源候选"） |
| Region / `RegionModifier` / `RegionView` | ❌ | 下游 |
| `WorldState`（`FinalState` 与 `Base` 参数值） | ❌ | 下游（含 `MagicDensity` / `HolyInfluence` / `CorruptionInfluence` / `Fertility`） |
| Biome / Ecology 候选 | ❌ | 下游 |
| Geology（`Density` / `Material` / `CaveDensity` / **`DepositZone`**） | ❌ | 下游（Phase 6） |
| Voxel 数据 / Chunk 状态 / 已生成内容 | ❌ | 真值层与调度层 |

## 5. 历史与遗迹

### 5.1 定义

> **遗迹必须来自：文明活动 + 历史事件。**

```
文明（偏好）
   ↓
活动范围（偏好条件满足的区域）
   ↓
历史事件（在活动范围内的具体事件）
   ↓
遗迹候选区域
```

| # | 规则 |
|---|---|
| **HV1** | 每个遗迹候选**必须**能同时回溯到**一个文明活动**与**一个历史事件**；缺一不可 |
| **HV2** | **禁止随机放遗迹**；禁止按网格/Chunk 撒点；禁止"每 N 个 Chunk 一个" |
| **HV3** | 遗迹的密度与间距必须是**显式参数**，且必须与"活动范围"绑定（无活动 ⇒ 无候选） |
| **HV4** | 候选的粒度是**区域（空间范围）**；区域内的具体落点、朝向、结构、战利品、存档属未来 **Structure / Entity** 系统（`Region_Design.md` RR7） |
| **HV5** | 遗迹候选不得改变地形（不得挖洞、不得放置方块、不得写体素） |
| **HV6** | 禁止"结果型遗迹"：不得由"想要某处有遗迹"反推事件/文明（`HG6`） |
| **HV7** | 遗迹候选不得违反地形常识：`Ocean == true` 处不产生陆地遗迹（除非显式的海上/水下遗迹倾向） |
| **HV8** | 遗迹候选必须可解释：能回答"哪一次事件、哪一段活动、为什么是这一类型" |

### 5.2 示例（用户示例的完整展开）

**矮人工坊**

```
矮人文明（Dwarf）
   + 偏好条件成立：山脉 / 高地（骨架级高程带）
   + 活动类型：开采（矿区活动）
   + 历史事件：发现与开采（纪元段 + 序位）
   ↓
遗迹候选区域：矮人工坊
   ↓
（未来）Structure 系统决定具体落点与结构；History 不放置任何方块
```

**其它对照**

| 文明 | 活动类型 | 事件 | 遗迹候选 |
|---|---|---|---|
| Dwarf | 开采 / 建造 | 发现与开采 / 文明兴衰 | 矿坑、工坊、城市遗迹 |
| Elf | 建造 / 研究 | 魔法实验 / 文明兴衰 | 古树区域、魔法遗迹 |
| Human | 建造 / 战争 | 战争 / 文明兴衰 | 城镇、道路、战场 |
| Demon | 战争 / 建造 | 圣恶冲突 / 灾难 | 祭坛、魔物据点遗迹 |
| Ancient Civilization | 研究 / 建造 | 魔法实验 / 灾难 | 巨型遗迹、封印构造倾向 |

## 6. 历史规模

### 6.1 世界尺度前提

> **无限海洋 + 有限大陆**（`WorldState_Design.md` §7.3、`Region_Design.md` §10.3、`WorldGeneration_Pipeline_Design.md` §10）。

```
水平世界：无限（Chunk 空间无边界 —— 既有流式行为不变）
垂直世界：沿用既有 WorldHeight
陆地：    有限块（大陆 A / 大陆 B / …）
大陆之外：海洋（可无限延伸；不承载文明历史）
```

### 6.2 大陆历史独立性（定义）

| # | 规则 |
|---|---|
| **HN1** | **每块大陆拥有独立的历史序列**：自己的文明集合、纪元划分、事件集合、活动范围 |
| **HN2** | **大陆之间默认不共享任何历史事实**：大陆 A 的事件不引用大陆 B 的文明、地点或事实 |
| **HN3** | 跨大陆事件必须**显式声明**（显式事件类型 + 显式参数）：例如"跨海战争""远航发现"；未显式声明时不得发生 |
| **HN4** | 大陆之间的**海洋隔离语义**由显式参数保证（大陆间隔 ≥ 最小值，沿用 `Region_Design.md` RW3/WC4） |
| **HN5** | 独立性必须**可验证**：修改大陆 B 的历史参数（文明集合 / 事件密度 / 纪元划分）⇒ 大陆 A 的历史事实与来源候选**逐项不变** |
| **HN6** | 海洋与无主区域**没有文明历史**；只有显式的海上事件（这是**可解释的"没有"**） |
| **HN7** | 水平世界**不引入硬边界**：大陆之外没有历史定义，但这不改变任何调度/坐标语义（`RW2`） |
| **HN8** | 大陆归属属于骨架/历史标签（`HistoryTags` 同族），**不是** Chunk 数据、不是 Region 容器 |

### 6.3 历史规模限制（硬性）

| # | 限制 |
|---|---|
| **HN9** | 事件总数、每纪元事件数、每大陆文明数、活动范围尺度、影响半径、遗迹候选密度上限**都必须显式参数化** |
| **HN10** | 规模限制的**理由**：无限世界里"世界级历史"没有意义（`WorldState_Design.md` §7.2）；有界规模才能保证可枚举、可验证、可解释 |
| **HN11** | 事件的**影响范围必须有界**（紧支撑，沿用 `WorldState_Design.md` §3.5 CF1–CF3 的纪律） |
| **HN12** | 给定坐标求值的复杂度必须与"该处相关的事件数"相关，而不是与"世界事件总数"相关（保证可局部求值） |

## 7. 历史确定性

### 7.1 同 `Seed` ⇒ 同历史

| 确定性产物 | 说明 |
|---|---|
| 事件集合（类型 / 纪元 / 序位 / 地点 / 参与文明 / 尺度） | 完全一致 |
| 文明集合与活动范围 | 完全一致 |
| **Historical Tags** | 完全一致 |
| **Region Source 候选** | 完全一致（位置 / 类别 / 强度倾向 / 尺度倾向） |
| 遗迹候选区域 | 完全一致 |
| 时间的相对序位关系 | 完全一致（不是绝对时间） |

| # | 规则 |
|---|---|
| **HD1** | 同一 `(Seed, 显式参数)` ⇒ **同一个历史**；任意时刻、任意顺序、任意机器状态一致（`Pipeline` PG1） |
| **HD2** | 历史必须**可独立重复求值**（同输入同输出，无副作用） |
| **HD3** | 历史必须**可局部查询**：给定坐标/范围可求出该处事实与候选（`HS12`） |

### 7.2 域分离（本层的确定性机制）

> 每个系统的输出必须由 `(Seed, Domain, Position)` 唯一确定（`Pipeline` §3.3 PE1–PE7）。

| 历史域标签（概念） | 覆盖内容 |
|---|---|
| `History.Civilization` | 文明存在、偏好归属、活动范围 |
| `History.War` | 战争类事件 |
| `History.Magic` | 魔法实验 / 仪式类事件 |
| `History.Disaster` | 灾难类事件 |
| `History.HolyCorruption` | 圣恶冲突类事件 |
| `History.Resource` | 发现与开采类事件 |
| （`History` 时间序位） | 纪元划分与序位分配 |

| # | 规则 |
|---|---|
| **HD4** | 各域**互不共享随机序列**；改变一个域的参数不得影响其它域的输出 |
| **HD5** | 新增域只能**新增标签**；不得修改既有域（尤其不得修改既有地形/地质域） |
| **HD6** | 域标签必须与**空间位置**共同参与；仅由 `Seed` 产生的常量不构成世界分布 |

### 7.3 禁止事项

| # | 禁止 | 说明 |
|---|---|---|
| **HD7** | `UnityEngine.Random` / `System.Random` / 任何有状态伪随机源（含 `Random()`） | 状态会被调用顺序影响 |
| **HD8** | `Time` / `DateTime` / `Guid` / 帧序 / tick / 世界时钟 | 非确定性来源（`Pipeline` PD4） |
| **HD9** | **玩家状态**（位置、进度、物品、任务、已探索区域） | 世界历史不得依赖玩家 |
| **HD10** | 加载顺序、邻居是否已求值、已加载 Chunk 集合、世界级中间态 | 违反可局部求值（`Pipeline` PB1–PB3） |
| **HD11** | 依赖 `Dictionary` / `HashSet` 遍历顺序 | 若顺序影响结果，即为缺陷 |
| **HD12** | 由下游产物反推（Biome / Region / 生态 / 体素） | §4.2 反向因果禁令 |
