# Region Contribution Aggregation Decision（Phase 3.1.1 · 窄范围决策审查）

> **文档性质**：**窄范围决策审查（Decision Review）**。针对 Phase 3.1.0 审查登记的"唯一关键阻塞点"——**单坐标的 Region Contribution 集合与聚合语义**——做一次只读、只登记、不裁决的核查。
>
> **本轮边界（已遵守）**：只读 + 仅新增本文件；**不修改任何代码 / 契约 / 测试 / Scene / Prefab / `.meta`**；不修改 `Assets/Scripts/World/V2`；不触碰 Legacy Terrain 与历史工作区变更；不实现任何聚合或合成逻辑；**不裁决任何未决项**。
>
> **标签体系（全文只用这五类）**：
> `【契约明确规定】` 有条款 + 行号可核 · `【代码现状】` 有文件 + 行号可核 · `【审查推断】` 由前两者推导 · `【候选设计】` 仅供设计方选择、无既定效力 · `【未决问题】` 契约未定义、须设计方裁决。
>
> **一句话结论**：
> **聚合算子（逐分量加法 + 钳制）【契约明确规定】；聚合的"输入集合"（单点影响集合如何枚举、上限多少）与其接口形状【未决问题】。因此：语义不缺，缺的是"集合怎么来"。**

## §0 结论摘要

| # | 结论 | 类别 |
|---|---|---|
| **S-1** | "一个坐标归属哪个 Region"与"一个坐标受到哪些 Region 影响"**不是同一概念**；契约操作性语义是**影响场**（连续、可叠加），"归属"式表述仅出现在身份层问题抽象中，且其输出基数未定义 | 【契约明确规定】+【未决问题】 |

## §2 Q1：单坐标的 Region 身份与 Region 贡献是否同一概念？

### 2.1 契约中的四个不同概念

| 概念 | 契约定义位置 | 职责（原文要点） | 是否"单区域"粒度 |
|---|---|---|---|
| **Region Identity**（`RegionIdentity`） | `Region_Architecture_Contract.md` §2.2/§2.3（`RA9`–`RA13`）；`Region_Identity_Determination_Contract.md` `RID40`–`RID44` | 身份键与身份值：`RegionKey` = `(DomainId, Epoch, Ordinal, CanonicalPosition)`；身份一经确定不得改变 | **是**（一个身份 = 一个区域） |
| **Region Source**（`RegionSource` / `RegionSourceCandidate`） | `Region_Architecture_Contract.md` §3（`RA21`–`RA30`）；`Region_Design.md` §3.2；`RG-A` | **原因记录**："无源不成区"；候选必须来自 ≥1 个来源 | **是** |
| **Region Context**（`RegionContext`） | `Region_Runtime_Data_Contract.md` `RRD21`–`RRD25`（**L86–L90**） | 解释层：身份信息 / 来源解释 / 标签 / 只读引用 / 资格声明 | **是**（承载 1 个身份） |
| **Region Modifier**（`RegionModifier`） | `Region_Runtime_Data_Contract.md` `RRD26`（**L96**）；`RA67`（**L284**） | 修正贡献：**恰好 6 个分量**（T/M/F/Magic/Holy/Corruption） | **是**（单个区域的贡献） |

【契约明确规定】：上述四者职责互不相同，且**不可互相替代**（`RA67`、`RRD26`、`RRD21`–`RRD25`、`RA9`–`RA13`）。

### 2.2 "归属"与"影响"不是同一件事

| 视角 | 契约依据（含行号） | 原文要点 |
|---|---|---|
| **影响场（V1 选择的语义）** | `Region_Design.md` §2.2（**L153–L160**） | "影响是**连续的**、随距离衰减"；"**多来源自然叠加**（§9）"；"修正量回答'改变了多少'" |
| **硬性规则** | `Region_Design.md` §2.2 `RM1`–`RM6`（**L166–L171**） | `RM1` 纯函数；`RM2` 有界 + 钳制；`RM3` 零修正显式；`RM4` 只作用 6 个参数；`RM5` 唯一权威路径 `Base + RegionModifier`；`RM6` 不得依赖结果 |
| **一点受多个区域影响** | `Region_Architecture_Contract.md` `RA17`（**L138**） | "任意世界坐标必须能**独立**求出'该点受**哪些 Region** 影响、**各修正多少**'" |
| **一点的影响集合可枚举** | 同文档 `RA128`（**L446**） | "给定世界坐标 `p`，必须能**确定性枚举**'**影响 `p` 的 Region 集合**'，且代价与该处相关 Region 数量相关" |
| **归属式表述** | `Region_Identity_Determination_Contract.md` `RID2`（§1）与 `RID60`（**L159**） | 身份只回答"这个位置属于哪个世界解释区域"；其**输出基数**（唯一主导 vs 集合）**未定义** |

| # | 结论 | 类别 |
|---|---|---|
| **Q1-1** | **契约明确规定**：Region 是**影响场**；贡献是"**每个区域**在该点产生多少修正"；修正量是**逐区域**的量 | 【契约明确规定】 |
| **Q1-2** | **契约明确规定**：`Identity` / `Source` / `Context` / `Modifier` 是四种不同职责的数据，不能互换或合并 | 【契约明确规定】 |
| **Q1-3** | **未决**：**"归属（membership）"与"影响（influence）"的关系**——契约**没有**把"归属"定义为聚合的前提；`RA128` 使用的是"影响集合"，而 `RID60` 讨论的是"判定输出基数"。两者是否指同一集合、是否需要"主导区域"概念，**契约未定义** | 【未决问题】 |
| **Q1-4** | **审查推断**：现有代码（`RegionPipeline.ResolveContext` → 单个 `RegionContext`）表达的是**单区域**形态；它既未表达"影响集合"，也未表达"归属" | 【审查推断】（【代码现状】见 Phase 3.1.0 报告 §1） |

| # | 问题 | 判定 | 依据 |
|---|---|---|---|
| **Q2-1** | "同一点" = 多个**空间采样点**吗？ | **否**。原文用词是"**在同一点**"（L513），且 `RA63` 讨论的是"**Region 遍历顺序**"，`RA65`/`RO7` 讨论的是"**单点参与合成的 Region 数量**" —— 遍历与计数的对象都是 **Region**，不是空间点 | 【契约明确规定】 |

| **Q2-5** | 多 Region 的贡献上限如何？ | **必须显式**（`RA65` L270、`RA130` L448、`RO7` L541），但**上限值未定**（`Region_Architecture_Contract.md` §13.2 第 3 项：上限值属实现规范） | 【契约明确规定】+【未决问题】 |
| **Q2-6** | Phase 3.1.0 报告写的"多点求和"是否准确？ | **不准确**：应读作"**同一坐标上多个 Region（源）的贡献求和**"。报告正文 `C-12` 行引用了正确原文，但摘要措辞失当 | 【审查推断】（更正登记见附录 B） |

## §4 Q3：当前缺失的最小契约决策（四项逐条核对）

> **首先明确：这四项不是同一个问题。**
> `RID60` = **身份判定输出基数**（一处登记） · `RA65`/`RA130`/`RO7` = **同一要求（单点参与数量的显式上限）在三个文档中的三处条款** · `B-3` = **参数三态物理存储位置**（与前三者无关的另一个登记项）。
> 本节按"原始问题 / 是否阻塞 / 已排除的错误方案 / 仍需决定什么 / 不解决的具体歧义"五问逐项记录。

### 4.1 `RID60`（身份判定输出基数）

| # | 五问 | 内容 |
|---|---|---|
| 1 | **原始问题与状态** | `Region_Identity_Determination_Contract.md` **L159**：「**Q4 输出基数**：单点判定的输出是"**唯一主导区域**"还是"**区域集合**（多值）"？ —— 现状："未定义；`RID53` 只保证多区域可同时影响，未定义身份输出的基数"」 |
| 2 | **是否阻塞接入** | **阻塞"完整形态"的接口形状**（决定"单点如何取得多个贡献"这一 API 是"单值 + 枚举"还是"集合返回"）；**不阻塞**"单区域退化形态" |

## §5 Q4：候选架构（**不替设计方做选择**）

> 以下三种均为【候选设计】，**只列出有契约依据的形态**；未获批准的算子/优先级/新字段一律不提出（见 §5.4 禁止清单）。

### 5.1 候选 A：单区域退化接线（最小可执行）

| 维度 | 内容 |
|---|---|
| **单坐标如何获得贡献** | 直接走现有链路：`RegionPipeline.ResolveContext(seed, position)` → 1 个 `RegionContext` → `RegionModifierDetermination.Determine(context)` → 1 个 `RegionModifier` |
| **是否需要枚举多个源** | **不需要**（这正是它的局限） |
| **确定性** | 已满足：全链纯函数（`RM1` L166；`WSC21` L128；Phase 3.0 实测 1000 组 + 跨进程一致） |
| **对现有类型的影响** | `RegionIdentity`/`RegionContext`/`RegionModifier`/`RegionPipeline`/`RegionModifierDetermination` **均不需要改动** |
| **如何交给 `Compose`** | 由 WorldState 层新增 1 个合成入口，把 `RegionModifier` **作为数据入参**传入，内部复用既有 `WorldParameterEvaluator.Compose`（Phase 3.1.0 §4.1 方案 A） |

### 5.2 候选 B：影响集合枚举 + 逐分量求和（契约目标形态）

| 维度 | 内容 |
|---|---|
| **单坐标如何获得贡献** | 先**枚举**"影响 `p` 的 Region 集合"（`RA128` L446），对集合内每个 Region 各得一个 `RegionModifier`，再**逐分量相加后钳制**（`Region_Design.md` §9.2 L513；`RA62`/`RA63`/`RA64` L267–269） |

| **如何交给 `Compose`** | 聚合结果（6 分量之和）作为**单个数据入参**传给 WorldState 层合成入口，内部仍由 `WorldParameterEvaluator.Compose` 执行 `clamp01(Base + Modifier)`（`RA76` L309；`PC20`） |
| **新增状态/缓存/跨层依赖/契约负担** | 无必需状态；缓存可选且必须透明（`RA138` L466）；跨层依赖 = WorldState 读 Region 产物（契约允许：`RA76`/`PC20`）；契约负担 = 需要**补上限数值/来源**与**枚举规则的登记**，并解决 `RID60` |
| **兼容性与风险** | 兼容：`RA17`/`RA63`/`RA65`/`RA128`–`RA130`、`RO1`/`RO4`/`RO7`、`WSC9`/`WSC12`、`RM2`/`RM5`。风险：① 枚举入口若实现为"全量扫描"违反 `RA131`/`RA132`（L454/L455）；② 上限未定会导致跨实现数值不一致；③ `RID60` 未决会导致接口形状返工 |
