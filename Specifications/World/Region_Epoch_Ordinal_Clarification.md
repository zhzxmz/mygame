## §3 六问逐答

### 3.1 `Epoch` 的准确语义

| 项 | 内容 | 等级 |
|---|---|---|
| **定义** | **纪元段**（"`Epoch`（纪元段）"）：时间轴的**段标识**，不是段内位置 | 【原文事实】`HE1` **L160**；`WPC` **L214**（单位列 = "纪元段（标识）"） |
| **类型 / 范围 / 默认** | 整数（`int`）；`[0, EpochCount-1]`（`EpochCount` 默认 `3`，属配置）；默认 `0`（最早纪元） | 【原文事实】`WPC` **L214** / **L241** |
| **来源与 Owner** | History（`Seed` + 显式纪元划分）；Owner = History | 【原文事实】`WPC` **L214** / **L635** |
| **不是什么** | 不是绝对日期 / 时间戳 / 世界时钟 / `Guid`（`HE2` **L161**）；不存在"现在"（`HE3` **L162**）；是**相对序位**而非真实时间（**L142**/**L148**） | 【原文事实】 |
| **保留值** | 自然来源若不含纪元信息，**必须**使用显式保留值（例如 `Epoch = EpochCount` = "非历史纪元"），**不得省略** | 【原文事实】`RA11` **L127** |

### 3.4 两者是否需要独立存储？

| 项 | 结论 | 等级 |
|---|---|---|
| **契约要求的是什么** | 契约要求：① 键的**分量**存在且**整数可比**（`RA9` **L125**、`RA37` **L203**、`RA44` **L215**）；② 两分量**独立登记**为参数序 10/11（`WPC` **L635**/**L636**）；③ 自然来源必须给出**显式保留值**、**不得省略**（`RA11` **L127**） | 【原文事实】 |
| **契约没有要求什么** | **没有**任何条款规定候选必须以"两个独立成员"**存储**；`RA21`（**L171**）明确候选是 `(Seed, Domain, Position)` 的**确定性函数** ⇒ **推导**（而非存储）在契约上**未被禁止** | 【原文事实】（条款缺失） |
| **因此** | 「**可分别取值**」是硬要求；「**独立存储**」是最小、最直接的满足方式，但**并非唯一**（推导 + 登记推导规则亦可） | 【证据支持的推断】 |

### 3.5 如果合并或只存储其中一个，会违反哪一条明确契约？

| 情形 | 后果 | 被破坏的**明确**条款 | 等级 |

## 附：一句话交付

> **`Epoch`（纪元段）与 `Ordinal`（段内序位）是两个**独立登记、独立定义**的分量（`WPC` 序 10/11、`HE1` `L160`），并且**同时出现在候选阶段的去重键（`RA37` `L203`）与全序键（`RA44` `L215`）中** → 因此"合并为一个不可分量"会**直接破坏** `RA37`/`RA44`（键不可构造）与 `RAV5`（唯一性不可验证）。**
> **但"候选必须以两个整数成员存储"并非明文规定**（`RA21` `L171` 允许由 `(Seed, Domain, Position)` 推导）→ **推荐最小表示：该槽位承载 `Epoch` + `Ordinal` 两个 `int` 分量，概念字段数仍为 8**，其余（位宽、保留值编码、存储形态细节、键实现）保持未决。**
