# Region Source Data Carrier Field Decisions（Phase 3.1.5 · M-1 字段编码裁决准备）

> **文档性质**：**字段级裁决准备（Field-level Decision Preparation）**。把 M-1「Region 来源数据载体」的字段编码问题分成四类，供设计者裁决。
>
> **本轮边界（已遵守）**：只新增本文件；**不修改**任何 `.cs` / `.meta` / 测试 / 场景 / Prefab / 配置 / 现有契约；**不修改** Phase 3.1.0–3.1.4 文档；**不新增**接口 / 类 / 方法 / 字段；**不实现**候选生成、采纳、枚举、索引、缓存、贡献计算或参数合成；**不裁决** `RID57`–`RID63`；**不确定**上限 A/B 数值；不触碰 Legacy Terrain；不清理历史工作区。
>
> **分类体系（全文只用这四类）**：
> `【契约直接确定】`无需另行批准 · `【建议批准】`给出推荐 + 备选 + 代价 · `【依赖未决语义】`须等其它契约/未决项 · `【证据不足】`现有文档与代码均无法推出。
>
> **一句话结论**：
> **8 个概念字段全部【契约直接确定】（§3.2 `L158`–`L165`），但其"底层类型/编码"没有任何一项被契约冻结；因此"8 字段载体"在概念层完整、在实现层不可冻结。最小阻塞项只有一个：`Radius / Scale` 是 1 个槽位还是 2 个槽位（B-3）——它决定字段数量本身。**

## §2 B-1 … B-11 逐项裁决准备（交付 2）

> 每项固定七问：契约证据 / 代码证据 / 分类 / 推荐结论 / 推荐理由 / 其他方案代价 / 是否阻塞 M-1 类型实现。

### B-1 载体类型形态与可变性

| 项 | 内容 |
|---|---|
| **契约证据** | §3.2 标题"必需字段（**概念**）"（`L154`）→ **契约只定义概念字段，未规定承载形态**；`RA13` `L129`（键不变）与 `RA25` `L175`（不得依赖时间/参数状态）间接要求"值一旦构造即稳定" |
| **代码证据** | V2 现有形态：`public readonly struct` ×6（`WorldSeed` / `WorldCoordinate` / `RegionIdentity` / `RegionContext` / `RegionModifier` / `WorldParameterValue`）；`public sealed class` ×1（`WorldParameterState.cs`，容器，持数组）；`public static class` ×8；`public enum` ×1（`WorldParameterCompositionKind`） |
| **分类** | **【建议批准】** |
| **推荐结论** | 推荐 **`readonly struct`**（值语义、无身份、无生命周期）；备选 **`sealed class`**（若未来需要引用语义/大量字段/集合承载——但集合已由 B-10 排除） |
| **推荐理由** | 数据型值对象在 V2 中一致采用 `readonly struct`（6 例）；候选是无身份的一次性求值输入（`RA16` `L137` 同族：Region 不是跨帧存活对象），不需要引用相等 |
| **其他方案代价** | `sealed class`：每次构造产生堆分配（枚举路径是热点）、需要自行定义值相等、易被误当"可变对象"持有；`struct`（非 readonly）：字段可写，与 `RA13`/`RA25` 的稳定性诉求相悖，且易被误改 |
| **是否阻塞** | **阻塞类型冻结**（形态决定声明），但风险低（两方案差异有限）；**不阻塞字段清单** |
| **附加说明（不可变 ≠ 免校验）** | 不可变性只约束"构造后不可改"；**校验是否发生**是另一问题。§3.2 `L161` 把 `Strength` 的"范围"归给 **Region 规则**声明 → **推断**：构造期校验不属于载体；若未来要求构造期拒绝非法值，需先定义**错误语义**（属 M-7 未决）→ **会把不确定性转移到 M-7** |

### B-2 数值类型与宽度

| 项 | 内容 |
|---|---|
| **契约证据** | `Position`"世界坐标；不得 Chunk 局部"（`L160`）；`Strength`"显式标量"（`L161`）；`Radius / Scale`"世界单位；必须 `> 0`"（`L162`）；`Epoch / Ordinal`"时间序位；来自 History"（`L163`）+ `RA9` `L125`"**整数可比**的量"+ `RA11` `L127`（保留值）；`DomainId`（`L159`）+ `PZ10` `L398`"**显式整数标识（32 位无符号）**"；`Kind`（`L158`）；`OriginRef`/`ReasonChainRef`（`L164`/`L165`） |
| **代码证据** | 既有先例：`WorldCoordinate` 用 `int` ×3（`L29–L31`）；`RegionIdentity` 用 `long`（id/引用句柄，`L36`/`L38`/`L39`）+ `int`（域/标签，`L37`/`L40`）；`RegionContext` 用 `int`（标签/掩码/版本，`L43–L45`）+ `long`（引用，`L42`）；`RegionModifier` 用 `float` ×6（`L38–L43`）；`WorldParameterValue` 用 `int` + `float` ×3 |
| **分类** | **`Epoch`/`Ordinal`/`DomainId` 的"整数域"=【契约直接确定】；其余"类型与宽度"=【建议批准】** |
| **推荐结论（逐字段）** | ① `Position`：**复用 `WorldCoordinate`**（int×3，见 B-6）；② `Epoch`/`Ordinal`：**整数**（宽度待批准，建议与 `RA9`"整数可比"一致）；③ `DomainId`：**整数**（`PZ10` 已给"32 位"；有符号性待批准 → 与既有 `RegionIdentity.RegionDomain`（`int`）保持一致为推荐）；④ `Strength`：**`float`**（连续标量；与 `RegionModifier` 的连续分量先例一致）；⑤ `Radius / Scale`：**待 B-3 裁决后定**（单位已知为"世界单位"，类型未定）；⑥ `Kind`：**整数码**（见 B-4）；⑦ `OriginRef`/`ReasonChainRef`：**整数句柄**（见 B-5） |
| **推荐理由** | ①③⑥⑦ 与 V2 既有承载习惯一致（整数标识/句柄：`RegionIdentity` 5 字段全部为 `int`/`long`）；④ 与连续量先例一致（`RegionModifier` 6 个 `float`）；① 见 B-6 |
| **代价 / 风险（精度·溢出·确定性·内存·序列化·跨平台）** | **精度**：`Strength`/`Radius` 若用 `float`，精度受限（相对误差约 1e-7）；契约未给量级 → **不得虚构取值范围**；**溢出**：`Position` 用 `int` 时坐标范围受限于 32 位（既有 `WorldCoordinate` 即如此，属既有事实而非本设计新增约束）；**确定性**：浮点参与"必须确定性"的链路时不得依赖平台浮点路径差异（`PS7` `L332`）；既有代码给出可用做法（`RegionModifierDetermination` 以精确 2 的幂缩放构造定点式浮点，并记录"与平台浮点路径无关"）；**内存**：8 字段全 `int`/`long` 约 32–48 字节，全 `float` 混合约 40 字节量级（**仅量级说明，不构成裁决**）；**序列化**：**契约未定义候选的序列化形态**（`RA16` 同族：候选是可重算的求值结果，不是存档单位）→ 若需要持久化，属【证据不足】；**跨平台**：整数路径天然一致；浮点需按 `PS7` 约束 |
| **是否阻塞** | **阻塞类型冻结**（宽度未定则字段声明不可写）；但可**整批批准**（B-1+B-2+B-8 同一次裁决）以降低往返 |

### B-3 `Radius / Scale` 的单字段或双字段

| 项 | 内容 |
|---|---|
| **契约证据（原文）** | §3.2 该行：字段名写为 **`Radius / Scale`**，含义列只有一个词"**影响尺度**"，约束列"世界单位；必须 `> 0`"（`L162`）。**同一行同时出现两个名称、却只有一个含义与一组约束** |
| **概念 vs 数据字段** | 概念层：**1 个概念**（"影响尺度"）；数据层：**1 个还是 2 个槽位 → 未定** |
| **代码证据** | V2 中不存在该字段的任何承载（`Radius`/`Scale` 数据字段命中 **0**；`Scale` 的 2 处命中是 `RegionModifierDetermination.cs` 的数值缩放常量 `PlaceholderScale`，**非空间尺度**） |
| **分类** | **【证据不足】/ 保持未决**（契约既未声明二者同义，也未声明二者是两个必需量） |
| **推荐结论** | **不推荐任选其一**；建议由设计者裁决下列之一：① **单槽位**（认定 `Radius` 与 `Scale` 是同一尺度的两种叫法）；② **双槽位**（认定是两个不同必需量，需分别命名与定义）；③ **升版本澄清**（在 `Region_Architecture_Contract.md` §3.2 把写法改为单一名称或拆成两行） |
| **推荐理由** | 单行单含义更像"同一概念的两名"；但 `> 0` 只对"半径"类量天然成立，"尺度"可能是无量纲缩放 → 两种读法都自洽，**证据不足以断定** |
| **其他方案代价** | 选①：若未来确需两个量，则载体字段数变更（破坏性）；选②：若二者同义，则引入冗余字段并违反"字段最小化"；选③：需要契约升版本（本轮禁止），但一次性消除歧义 |
| **是否阻塞** | **阻塞类型冻结**（决定字段数量），且**不能**用"不透明句柄"绕过（见 §5 Q6）：把它做成一个句柄会同时丢掉"尺度"数值语义，等于换一种裁决 |

### B-6 `Position` 是否复用 `WorldCoordinate`

| 项 | 内容 |
|---|---|
| **契约证据** | `Position`"锚点世界坐标"；"必须是世界坐标；**不得是 Chunk 局部坐标**"（`L160`）。`RA12` `L128`：`CanonicalPosition = Quantize(Position, QuantumVoxels)`（`QuantumVoxels` 显式参数，默认 `1`）→ **锚点与量化结果是两个量** |
| **代码证据（只读核实 `WorldCoordinate.cs`）** | `public readonly struct WorldCoordinate`；字段 `int x/y/z`（`L29–L31`）；属性 `X/Y/Z`（`L40`/`L45`/`L50`）；`Origin`（`L56`）；`Offset(...)`（`L62`）；类文档明文"**不提供任何坐标换算**（Chunk ↔ 世界、Chunk 局部坐标等一律不在此类型内）"（`L15`），并声明换算权威为 `ChunkSize = 16；world = chunk × 16 + local；负数使用 floor 语义`（`L17`） |

## §5 实现就绪度与最小阻塞项（交付 5）

### 5.1 六问直答

| # | 问题 | 回答 |
|---|---|---|
| **Q1** | 哪些字段已足够明确，可以进入类型设计？ | **概念层：8/8 全部明确**（§3.2）。**语义层**：`DomainId`、`Position`、`Epoch`/`Ordinal` 较明确（3–4 项）；`Kind`、`Strength`、`Radius / Scale`、`OriginRef`、`ReasonChainRef` 为"部分明确"。**类型层：0/8 被契约冻结** → **没有任何字段可以单独进入"类型冻结"**，但概念与语义层面足够支撑**设计稿**（非实现） |
| **Q2** | 哪些字段必须先获得设计者批准？ | B-1（形态）· B-2（宽度）· **B-3（单/双）** · B-4（`Kind` 编码）· B-5（句柄形态）· B-6（是否复用）· B-7（有符号性/注册表）· B-8（命名/可见性）——共 8 项；其中 B-1/B-2/B-8 可打包一次批准 |
| **Q3** | 哪些字段必须等待空间语义或其他契约？ | **没有字段的编码依赖 `RID57`–`RID63`**（那些未决项只影响"完整性/枚举"）。真正需要等待**其他契约**的是：B-5（解释链契约）+ B-11（`RA22` 澄清）+ B-4 的映射表 |
| **Q4** | 能否在不引入临时语义的情况下实现**完整的 8 字段载体**？ | **不能**：B-3 决定字段数量（8 或 9）；B-1/B-2/B-8 决定声明形态；B-4/B-5 决定 `Kind` 与两个引用字段的编码。任何实现都会在**这些点上做出裁决**，即"引入未批准的语义" |
| **Q5** | 最小阻塞项是什么？ | **B-3（`Radius / Scale` 单/双）** —— 唯一**直接决定字段数量**的一项，且**无法用不透明类型绕过**（见 Q6）。其次的最小组合是 **B-1 + B-2 + B-8**（形态/宽度/命名，可一次批准） |
| **Q6** | 能否用不透明句柄或暂定类型绕过阻塞？ | **部分可以，但必须同时登记"不确定性转移到哪一层、由谁、何时关闭"**（详见 5.2）——**不得**仅以"技术上可编译"宣称设计完成 |

### 5.2 绕过评估（逐字段）

| 字段 | 可否用不透明/暂定类型先承载 | 代价：不确定性转移到何处 | 结论 |
|---|---|---|---|
| `OriginRef` | ✔ 可用整数句柄 | 转移到**解释层**："必须可解析"（`L164`）无法验收；`WE*` 实现前不可兑现 | 可承载、不可验收（须登记） |
| `ReasonChainRef` | ✔ 同上 | 同上 + 与 `OriginRef` 的关系未定 | 可承载、不可验收 |
| `Kind` | ✔ 可用整数码 | 转移到**规则/映射层**：谁负责"码 → 类别"的判定与合法性校验 | 可承载、语义待补 |
| `DomainId` | ✔ 可用 `int` | 转移到**校验层**："未登记域不得使用"（`RA10` `L126`）的校验责任与时机未定 | 可承载 |
| `Strength` | ✘ 无绕过：宽度必须选（`float`/`double`/整数） | —— 选任一即裁决 | **必须先批准** |
| `Radius / Scale` | ✘ **不可绕过**：单槽位或双槽位是**字段数量**问题，不是编码问题 | —— | **硬阻塞** |
| `Epoch` / `Ordinal` | ◐ 可用两个整数；但"是否应为一个复合量"未定 | 若未来需复合，需改字段数 | 可承载（风险登记） |
| `Position` | ✔ 复用既有 `WorldCoordinate`（语义已核实匹配） | 无需转移（B-6 批准即可） | 可承载 |
