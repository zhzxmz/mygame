# Ecology System Design Specification V1

> **文档性质**：**设计规范（Design Specification）**。本文档只描述 **概念 / 数据关系 / 规则 / 约束 / 验收标准**。
> **不创建 `.cs`**；**不修改任何已有文件**；**不定义接口 / class / struct**；**不设计任何具体 Entity 实现**（无 AI、无行为、无生命周期）。
>
> **定位**：Ecology 位于 **Biome 之后、Entity 之前**，是"环境允许什么"的**解释与候选层**。
>
> **核心原则（一句话）**：
>
> > **生态是结果，不是原因。**
>
> **禁止**：生成魔法森林 → 创建魔力源。
> **允许**：魔力源 → `MagicDensity` → 魔法森林条件 → 魔法植物。

## 目标数据流（本文档要定义的对象）

```
WorldState
 +
Biome
 +
Region Tags
      ↓
Ecology Rules
      ↓
Spawn Candidates
```

**核心原则（三条）**

| # | 原则 | 含义 |
|---|---|---|
| **E-1** | **生态是结果** | 生态形态只能由**环境条件**解释；禁止由生态结果反推原因（禁止"生成魔法森林 → 创建魔力源"） |
| **E-2** | **不短路** | 必须走完 `Source → Environment → Ecology`；**禁止**从"来源存在"直接跳到"生态形态" |
| **E-3** | **不改世界** | Ecology **不改变** `WorldState`、不改变 Region、不改变 History、不改变 Biome、不改变 Geology、不写 Voxel、不创建对象 |

## §1 Ecology 定位

### 1.1 定义

> **Ecology = 位于 Biome 之后、Entity 之前的解释层**：
> 把"环境允许什么"（`WorldState` + `Biome` + Region Tags）解释为**具体的生成候选**（Spawn Candidates）。

| 层 | 回答的问题 | 在因果链中的位置 |
|---|---|---|
| **WorldState** | 环境参数是多少？ | 参数（原因侧结果） |
| **Biome** | 这片空间在生态上属于哪一类？ | 分类结果 |
| **Ecology（本文档）** | 这类环境**允许**什么出现？在哪里、以什么类别？ | **解释结果 + 候选** |
| **Entity（未来）** | 具体生成什么对象、如何行为、如何存档？ | 对象（消费者） |

### 1.2 数据流

```
WorldState（FinalState：8 个环境参数）
        +
Biome（生态分类结果）
        +
Region Tags（只读的原因侧标签）
        ↓
Ecology Rules（生态规则：显式、确定性、只读）
        ↓
Spawn Candidates（生成候选：资格，不是对象）
```

### 1.3 硬性规则

| # | 规则 |
|---|---|
| **EA1** | **Ecology 不改变 `WorldState`**：不写参数、不写修正量、不新增参数 |
| **EA2** | Ecology 的输入**只有**：`FinalState`（只读）、`Biome`（只读）、Region Tags（只读）、显式生态参数 |
| **EA3** | Ecology 的产出**只有** `Spawn Candidates`：它是"允许存在"的资格集合，**不是对象、不是指令** |
| **EA4** | **候选 ≠ 生成**：Ecology 不创建任何对象、不写 Voxel、不创建 Chunk、不置脏、不生成 Mesh |
| **EA5** | Ecology 必须**可关闭**：关闭后世界与今天**逐体素一致**（不产生任何副作用） |
| **EA6** | Ecology 必须**可局部求值**：任意世界坐标可独立求出"此处允许什么"，不需要遍历全世界（继承 `Pipeline` `PG5`） |
| **EA7** | Ecology 的产出**不得**成为 Phase 6（Geology）/ Phase 7（Voxel）的输入（见 §1.5） |

### 1.4 与既有 `EcologyRules`（Region 侧）的归属对齐

`Region_Design.md` §4.4 已在 **Region Layer** 下登记过 `EcologyRules`。两者**不是同一个东西**，必须按下表区分（本文档**不修改**该规范，只做归属澄清）：

| 名称 | 归属 | 粒度 | 内容 | 是否生成对象 |
|---|---|---|---|---|
| **Region.EcologyRules** | Region Layer（`Region_Design.md`） | 区域级 | 区域给出的**资格声明**（"本区域允许什么类别"） | ❌ 不生成 |
| **Ecology.SpawnCandidates** | Ecology（本文档） | 位置级 | 由环境 + 群系 + 区域标签解释出的**具体候选**（类别 / 类型 / 位置范围 / 条件与原因链） | ❌ 不生成 |

**方向**：`Region.EcologyRules`（原因侧声明） → **Ecology Rules** → `SpawnCandidates`（结果侧候选）。
**禁止反向**：Ecology 不得创建/修改 Region，也不得回写 `Region.EcologyRules`。

### 1.5 在 World Generation Pipeline 中的位置（旁路，不是新阶段）

```
Pipeline（上游规范，不得修改）
  Phase 3 Region ──┐
  Phase 4 WorldState ──┤（只读）
  Phase 5 Biome ──┘
                     │
                     ├──► Phase 6 Geology ──► Phase 7 Voxel Output        （地形链，与 Ecology 无关）
                     │
                     └──► Ecology（本文档，旁路）
                                │
                                └──► Spawn Candidates ──► 未来 Entity / Creature / Structure 系统
```

| # | 规则 |
|---|---|
| **EB1** | Ecology 是 Pipeline 的**旁路（side branch）**：它读取 Phase 3/4/5 的产出，但**不被** Phase 6/7 读取 |
| **EB2** | Ecology **不新增 Pipeline 阶段**、不改变 Phase 顺序、不改写任何 Phase 的产出（Pipeline 规范仍是层间数据流的唯一权威） |
| **EB3** | 必须满足"关闭 Ecology ⇒ 世界与今天逐体素一致"（`EA5`） |
| **EB4** | Ecology 的确定性机制与 Pipeline 完全一致：`(Seed, Domain, Position)` + 域分离（§10.1） |

### 1.6 与"环境允许"的直接对应

`WorldState_Design.md` §1.4 已规定"参数高 = 允许"：

| 环境状态（上游） | 允许（上游声明） | 本文档的落实形态 |
|---|---|---|
| `MagicDensity` 高 | 魔法植物**可以**出现 / 魔法生物**可以**生存 / 魔法资源**可以**生成 | 产出对应的 `Spawn Candidate`（类别 = 植物 / 生物 / 资源） |
| `CorruptionInfluence` 高 | 腐化生态**可以**出现 | 产出腐化类候选 |
| `HolyInfluence` 高 | 圣性生态**可以**出现 | 产出圣性类候选 |
| `Fertility` 高 | 植被**可以**繁茂 | 影响植物候选的密度倾向 |
| `Ocean = true` | 陆生生态**被排除**（除海洋生态） | 抑制陆生候选、允许海洋候选 |

**硬性**：Ecology **只能**把上游的"允许"**具体化**，不得**扩大**它（不得在参数不足时产出候选）。

## §2 环境与生态关系

### 2.1 参与判定的环境参数（只读）

| 参数 | 在 Ecology 中的作用 | 是否可被 Ecology 修改 |
|---|---|---|
| **Temperature** | 决定适生区间（冻原 / 温带 / 热带形态） | ❌ |
| **Moisture** | 决定植被密度与形态（旱生 / 湿生） | ❌ |
| **Elevation** | 决定垂直带（低地 / 山地 / 高山）、庇护条件 | ❌ |
| **Fertility** | 决定植被繁茂度与动物承载倾向 | ❌ |
| **MagicDensity** | 决定魔法类生态的**资格** | ❌ |
| **HolyInfluence** | 决定圣性类生态的**资格** | ❌ |
| **CorruptionInfluence** | 决定腐化类生态的**资格** | ❌ |
| （派生）**Ocean** | 决定陆生／水生生态的分支（**短路**） | ❌ |

### 2.2 影响的生态类别

| 生态类别 | 主要依赖参数 | 产出形态（候选） |
|---|---|---|
| **植物** | `Temperature`、`Moisture`、`Fertility`、`MagicDensity`、`HolyInfluence`、`CorruptionInfluence` | 植物候选（类别 + 类型 + 位置范围 + 密度倾向） |
| **动物** | 植被条件、`Temperature`、`Elevation`、三类力量参数 | 动物候选（类别 + 类型 + 活动条件） |
| **资源** | `DepositZone`（地质原因）+ 力量参数 | 资源对象候选（**存在性由地质决定**，§5） |
| **危险生物** | `CorruptionInfluence`、`MagicDensity`、地形庇护、资源可用性 | 危险生物候选（类别 + 威胁来源 + 出现条件） |

### 2.3 硬性规则

| # | 规则 |
|---|---|
| **EE1** | 生态规则**只能**读取 §2.1 的 8 个参数、`Biome`、Region Tags 与显式生态参数 |
| **EE2** | 每个生态候选**必须**能展开为显式的**参数条件**（阈值 + 组合关系），不得存在"无条件的候选" |
| **EE3** | **禁止短路**（`E-2`）：不得由"来源存在"直接判定生态形态，必须经由环境参数（与 `Biome`） |
| **EE4** | 同一参数组合 ⇒ 同一候选集合（纯函数性）；叠加与遍历顺序无关 |
| **EE5** | 阈值与密度参数必须**显式**，不得硬编码隐式魔法数字 |
| **EE6** | 不得读取任何**结果侧**信息（对象是否存在、已生成内容、Chunk 状态） |
| **EE7** | `Ocean == true` 时必须**短路**为水生生态分支（陆生候选被抑制） |
| **EE8** | 生态类别之间不得互相读取（不得"因为这里已有狼窝所以生成狼"——那是对象侧的行为，属未来系统的内部逻辑） |

## §3 植物生态

### 3.1 类别

| 类别 | 环境条件（必要性） | 说明 |
|---|---|---|
| **普通树** | `Temperature` 适中、`Moisture` 高、`Fertility` 中以上、`Ocean == false` | 与 `Forest` 群系对应 |
| **魔法树** | 普通树的全部条件 **+** `MagicDensity` 高 | 与 `MagicForest` 群系对应 |
| **腐化植物** | `CorruptionInfluence` 高（`Fertility` 可低） | 与 `CorruptedLand` 群系对应 |
| **圣洁植物** | `HolyInfluence` 高 **+** `Fertility` 高 | 与 `HolyLand` 群系对应 |

### 3.2 重点：**魔法树不是魔力来源**

| # | 规则 |
|---|---|
| **EP1** | 魔法树的**存在**不得产生、增强或维持 `MagicDensity` |
| **EP2** | 魔法树的**存在**不得产生新的 `MagicSource`，不得被 Region 层采纳为来源 |
| **EP3** | 魔法树的**存在**不得改变 `MagicDensity` 的求值结果（参数求值不得读取生态候选；`Region_Design.md` §6.4 RH3） |
| **EP4** | 若未来希望"魔法植物本身成为小范围魔力源"，必须作为**新的来源类型**在**上游规范**中定义（= 新增原因），**不得**由 Ecology 回写环境参数 |

### 3.3 必须遵守的因果链

```
Magic Source（原因，上游）
      ↓
MagicDensity（环境参数，Phase 4）
      ↓
Magic Forest 条件（群系 / 生态规则，Phase 5 → Ecology）
      ↓
魔法植物（候选 → 未来实体系统）
```

| # | 规则 |
|---|---|
| **EP5** | **必须**走完 `Source → Environment → Plant` 三级；任何一级缺失都不得产出候选 |
| **EP6** | **禁止**由群系结论或生态结论反推原因（例如"这里有魔法树，所以这里应该有魔力源"） |
| **EP7** | 不得由来源**直接**判定植物类别（`EE3` 禁止短路）：来源只通过环境参数起作用 |
| **EP8** | 植物候选必须可解释：每个候选都能给出"哪几个参数的哪几个条件被满足" |

### 3.4 与群系边界的关系

植物候选的**表现边界**仍受既有 Geology 规则约束：群系在 V1 中只影响**地表层材料**（`{Grass, Dirt, Stone}`，仅 `y == SurfaceHeight`）。
Ecology **不得**要求新的体素类型、不得要求新的地表材料、不得改变地形。

## §4 动物生态

### 4.1 类别

| 类别 | 环境条件（必要性） | 出现原因（Why） |
|---|---|---|
| **普通动物** | 植被条件满足（有食物）、`Temperature` 适中、非极端 `Elevation` | 环境能供养 |
| **魔法生物** | `MagicDensity` 高（且普通生存条件不极端） | 高魔力环境允许其存在 |
| **腐化生物** | `CorruptionInfluence` 高 | 腐化环境允许其存在 |
| **圣生物** | `HolyInfluence` 高 | 圣性环境允许其存在 |

### 4.2 只设计"为什么出现"

> **本文档不设计任何 AI、行为、种群、生命周期、战斗与掉落。**

| # | 规则 |
|---|---|
| **EW1** | 动物候选只回答"**为什么这里允许出现**"，不回答"它做什么" |
| **EW2** | 每个类别必须给出**必要性条件**（缺一不可的参数条件）与**排除条件** |
| **EW3** | 类别之间**不得互相读取**（不建立食物链、不做捕食关系；食物关系只作为"植被条件"这一**参数条件**出现） |
| **EW4** | 不得由动物候选反推环境（禁止"有大象 ⇒ 这里湿润"）。反推是禁止的方向 |
| **EW5** | 危险生物（§2.2）必须由**显式原因**决定威胁来源（腐化 / 魔力 / 地形庇护），不得随机赋予 |
| **EW6** | 海洋分支（`Ocean == true`）与陆地分支互斥；不得在同一坐标产出两类动物候选 |
| **EW7** | 迁移、群聚、领地等**行为**一律不属于本文档（§8） |

### 4.3 与"来源"的关系（禁止短路）

| 情形 | 是否允许 | 理由 |
|---|---|---|
| 来源存在 + 环境参数达到阈值 ⇒ 动物候选 | ✅ | 走完三级因果链 |
| 来源存在 ⇒ 动物候选（**跳过环境参数**） | ❌ | `EE3` 禁止短路 |
| 群系名称 ⇒ 动物候选（跳过参数条件） | ⚠️ 仅当该群系条件**可展开**为参数条件时允许（`Biome` 是环境向量的压缩形式） | 可解释性要求 |

## §5 资源生态

### 5.1 类别与"原因"要求

| 类别 | **必须**的原因 | 说明 |
|---|---|---|
| **普通矿** | **地质原因**：`DepositZone ≠ None`（唯一权威，Geology） | 存在性由地质规则决定，Ecology 只解释"能否出现可采集形态" |
| **魔法矿** | **地质原因** + **环境原因**：`DepositZone` 命中 **且** `MagicDensity` 高 | 双重原因，缺一不可 |
| **晶体** | **地质原因** + **暴露条件**（`DepositZone == CrystalZone` 且地表/洞壁暴露） | **晶体属于 Entity**（`WorldGeneration_Geology.md` §6.2、ADR-001）；Ecology **不**决定其生成 |
| **特殊资源** | **原因侧标签**（历史 / 区域来源）+ 环境条件 | 例如与历史事件、圣恶来源相关的资源 |

### 5.2 硬性规则

| # | 规则 |
|---|---|
| **ER1** | **资源必须有地质/环境原因**：禁止"无原因资源"、禁止按 Chunk 撒布 |
| **ER2** | **资源存在性属于 Geology**：Ecology **不得**定义、修改或扩展 `DepositZone` |
| **ER3** | **不得新增资源体素类型**：V1 的体素状态仍冻结为 Air/Grass/Dirt/Stone；资源是**属性 + 对象**，不是体素 |
| **ER4** | **V1 允许"候选为零"**：若某类资源在 V1 中没有对象形态，Ecology 可以直接不产出，**不得**为了让资源"看起来存在"而新增体素类型或标记 |
| **ER5** | 晶体等对象的存在性由未来 **Entity 系统**决定；Ecology 只提供只读的候选与原因链 |
| **ER6** | 资源候选不得写回 Geology、不得改变 `Density` / `Material` / `CaveDensity` |
| **ER7** | 资源候选必须可解释到"地质原因 + 环境原因"，不允许仅由环境参数产出资源 |
| **ER8** | 不得由"资源出现过"反推地形或环境（禁止反向依赖） |

### 5.3 与既有 Geology 的边界（复述，便于实现者对照）

| 问题 | 归属 |
|---|---|
| 这个坐标存在什么资源？ | **Geology**（`DepositZone`，属性层） |
| 这个坐标是否允许出现一个资源**对象/节点**？ | **Ecology**（候选，本文档） |
| 这个对象是什么、有多少、何时生成、如何存档？ | **未来 Entity 系统** |
| 资源的体素表现（纹理/面/矿物方块） | **V1 不存在**（不新增体素类型） |

## §6 窝点与区域

### 6.1 设计目标

解释**为什么某些区域有**：狼窝、兽穴、魔物巢穴——**禁止随机散布**。

### 6.2 窝点出现的原因（必要条件）

| 原因类别 | 含义 | 示例条件 |
|---|---|---|
| **生态条件** | 该物种在此环境可生存 | 植被/猎物条件、`Temperature` 区间、非极端 `Elevation` |
| **地形庇护** | 有可用的遮蔽结构 | 洞穴存在（`CaveDensity` 命中）、山体/高地（`Elevation` 高）、非 `Ocean` |
| **资源可用性** | 附近有可依赖的资源 | 植被密集、`DepositZone` 命中、水源（`Moisture` 高） |
| **区域标签** | 原因侧标签允许此类生态 | 腐化区域 ⇒ 魔物巢穴；圣性区域 ⇒ 圣性生物的聚落 |
| **间距约束** | 避免过度密集 | **显式**最小间距参数（禁止"处处都是巢穴"） |

### 6.3 硬性规则

| # | 规则 |
|---|---|
| **EN1** | 每个窝点候选**必须**有至少一个**原因类别**成立；不得"无原因出现" |
| **EN2** | **禁止随机散布**：不得按网格/Chunk 撒点，不得"每 N 个 Chunk 放一个" |
| **EN3** | 间距与密度必须是**显式参数**，且必须与"生态条件"绑定（无生态条件 ⇒ 无窝点） |
| **EN4** | 窝点候选**不得**改变地形（不得挖洞、不得放置方块）——地形庇护只能**读取**既有洞穴/地形 |
| **EN5** | 窝点候选的位置必须在**可生存范围内**（不得出现在 `Ocean` 水面、不得出现在不适生区间） |
| **EN6** | 窝点候选是**位置与类别的资格**，其对象化（结构、生物群体、生命期、AI）属未来系统（§9） |
| **EN7** | 窝点候选不得由其它候选反推（不得"因为这里有魔物所以这里有巢穴"） |
| **EN8** | 同一坐标允许同时存在多个类别的候选，但必须满足各自的必要条件且不违反互斥规则（例如陆生/水生互斥） |

## §7 生态与 Region 关系

### 7.1 职责划分

> **Region 提供环境条件。Ecology 解释结果。**

```
Region（原因：来源 + Modifier + 标签 + 区域级资格声明 Region.EcologyRules）
      ↓  （只读）
Ecology（解释：把"允许什么"具体化为候选）
      ↓
Spawn Candidates
```

| # | 规则 |
|---|---|
| **EG1** | Region 是**原因侧**：提供来源、修正、区域级资格声明 |
| **EG2** | Ecology 是**结果侧**：只解释、只产出候选 |
| **EG3** | **禁止：Ecology 创建 Region**（也不得修改、扩展、合并 Region 或 `Region.EcologyRules`） |
| **EG4** | Ecology 读取的"Region Tags"一律指**只读的原因侧标签**：`HistoryTags`（`Region_Design.md` §4.4 / §6.4 RH2 允许资格规则读取）与来源类别 |
| **EG5** | **禁止**把 `RegionType`（`MagicForest` / `CorruptedLand` 等**解释标签**）当作规则输入（`Region_Design.md` RTY2：类型无规则权） |
| **EG6** | Ecology 的产出不得被 Region 读取（禁止反向：生态结果不得影响区域修正量、类型或资格声明） |
| **EG7** | Ecology 不得读 `RegionView` 并据此回写任何东西（`Region_Design.md` RT6） |

### 7.2 允许读取的"Region Tags"白名单

| 标签 | 是否允许 | 用途 |
|---|---|---|
| `HistoryTags`（历史事实标签） | ✅ | 生态资格与归因（例如"该区域有亡灵灾难事实 ⇒ 允许腐化类候选"） |
| 来源类别（自然 / 魔法 / 圣 / 腐化） | ✅ | 只作为**可解释性归因**；**不得**短路判定生态形态（`EE3`） |
| 区域级资格声明（`Region.EcologyRules`） | ✅ | 作为粗粒度约束（区域禁止的类别，位置级也不得允许） |
| `RegionType`（解释标签） | ❌ | 无规则权（`EG5`） |
| `RegionView`（结果侧空间范围） | ❌ | 结果侧，禁止作为输入（`EG7`） |
| `RegionModifier` 的原始分量 | ⚠️ 不直接读 | 应读取**已合成的** `FinalState`（`Base + Modifier`），避免绕过环境层（`EE3`） |

## §8 动态变化

### 8.1 V1：静态生成

| # | 规则 |
|---|---|
| **ED1** | **V1 为静态生成**：生态候选在"求值时刻"一次性确定，不存在随时间演化的生态状态 |
| **ED2** | 生态候选与加载顺序、帧序、tick 次数、玩家行为**完全无关** |
| **ED3** | 不存在"世界生态时钟"，不存在"每隔 N 年推进一次" |
| **ED4** | 生态层不为 Runtime 提供任何回调或更新时机（不接触 Runtime） |

| # | 不实现 | 说明 |
|---|---|---|
| 1 | **生态演化** | 不存在群落演替、植被扩张、生态崩溃 |
| 2 | **物种进化** | 不存在适应、变异、新物种产生 |
| 3 | **迁徙模拟** | 不存在动物迁移、种群移动、季节性迁徙 |

### 8.3 未来动态化的前提（若提出）

| # | 要求 |
|---|---|
| **ED5** | 任何动态化提案必须**独立成规范**（不得直接改写本文档语义），且必须证明：① 确定性不受影响；② 既有验收全部 PASS；③ **可关闭**（关闭后与静态 V1 一致） |
| **ED6** | 动态系统**不得**回写环境参数、Region、History、Biome 或 Voxel（否则会破坏 `E-3` 与 Pipeline 的因果方向） |

## §9 与未来 Entity 系统关系

### 9.1 允许的读取（只读）

| 未来系统 | 可读 | 用途 |
|---|---|---|
| **Entity** | `Biome`、`Ecology`（候选）、Region（只读） | 决定"实际生成什么对象、在哪里" |
| **Creature** | `Biome`、`Ecology`（候选）、`WorldState`（只读） | 决定"什么生物可以在这里存在" |
| **Structure** | Region（遗迹候选区域）、`Biome`、`Ecology`（可选） | 决定"放置什么结构" |
| **Quest / NPC** | History（事实）、Region、`Biome`、`Ecology`（可选） | 决定"可发生什么、谁在此活动" |

### 9.2 硬性规则

| # | 规则 |
|---|---|
| **EF1** | **Entity 不能改变生成规则**：不得修改 `WorldState`、Region、History、Biome、Geology、Ecology 规则或任何候选判定 |
| **EF2** | Entity **不得回写** `Spawn Candidates`（候选是只读输入；对象的存在不改变资格） |
| **EF3** | Entity 不得把对象状态写入 Voxel 数据（ADR-001：Entity 不属于 Chunk 所有权体系） |
| **EF4** | Entity 的存在与运行**不得影响**任何上游求值结果（不改确定性） |
| **EF5** | Entity 只能做**局部只读查询**（不得要求"世界级全量状态"） |
| **EF6** | Entity 不得要求 Runtime / Chunk / Mesh 侧为 Ecology 引入特殊处理 |
| **EF7** | Entity 的实际生成策略（数量、密度上限、稀有度、剔除、存档）属于**未来系统自己的规范**；本文档只提供资格与原因链 |

### 9.3 边界图

```
Ecology（本文档）
   │  只读产出：Spawn Candidates（资格 + 原因链）
   ▼
未来系统：Entity / Creature / Structure / Quest / NPC
   ├── 读取：Biome / Ecology / Region / History（只读）
   ├── 产出：对象与内容（不属于本文档）
   └── 禁止：回写世界生成数据、修改生成规则（EF1–EF6）
```

## §10 验收规则

### 10.1 生态确定性

| # | 不变量 | 验证方法 |
|---|---|---|
| **EC1** | 同一 `(Seed, Domain, Position)` ⇒ 同一候选集合（纯函数性） | 同坐标重复求值 N 次逐项比较 |
| **EC2** | **域分离**：Ecology 使用**独立域标签**，不共享上游随机序列（`Pipeline` `PE1`–`PE7`） | 改变其它域的种子/参数 ⇒ 生态输出**逐项不变** |
| **EC3** | Seed 决定性 + 非平凡性：同 `Seed` ⇒ 同结果；不同 `Seed` ⇒ 至少一处候选不同（反例保护） | 双世界对照 + 非平凡性断言 |
| **EC4** | 与加载顺序 / 帧序 / tick 次数无关 | 不同加载顺序与多次求值对照 |
| **EC5** | 叠加与遍历顺序无关（候选集合与判定顺序无关） | 打乱内部遍历顺序后重算比较 |
| **EC6** | 不使用任何非确定性来源（`Random` / `Time` / `DateTime` / `Guid` / 平台相关噪声） | 结构扫描 |

### 10.2 因果正确

| # | 不变量 | 验证方法 |
|---|---|---|
| **EC7** | **无短路**：每个候选都能展开为环境参数条件；不存在"由来源直接判定形态"的规则 | 结构扫描（来源不得作为形态判定条件）+ 规则展开检查 |
| **EC8** | **可解释性**：任意候选都能回溯完整链 `Source → Environment → Biome/Ecology → Candidate` | 判定链问答（附录 A.2 形式） |
| **EC9** | **禁止结果反推原因**：不存在"由生态/群系反推来源、Region、参数"的规则 | 结构扫描（无由 Biome/候选写上游的路径） |
| **EC10** | 魔法植物不得成为魔力来源；生物不得成为力量来源（`EP1`–`EP4`） | 结构性断言（生态产出无"写参数/写来源"路径） |

### 10.3 无反向依赖

| # | 不变量 | 验证方法 |
|---|---|---|
| **EC11** | 附录 C 的 `EB-1`…`EB-14` 全部成立（无任何反向读取） | 结构扫描（反向路径计数 = 0） |
| **EC12** | Ecology 不创建 Region、不改 `Region.EcologyRules`、不改 History（`EG3`） | 结构扫描 + 产出检查 |
| **EC13** | `RegionType` 未被用作规则输入（`EG5`） | 结构扫描（类型标签只出现在标签/调试路径） |
| **EC14** | 候选**不成为** Phase 6（Geology）/ Phase 7（Voxel）的输入（`EA7`/`EB1`） | 依赖矩阵校验（Ecology 的消费者只有未来系统） |

### 10.4 无世界状态修改

| # | 不变量 | 验证方法 |
|---|---|---|
| **EC15** | Ecology **不写** `WorldState` / Region / History / Biome / `Density` / `Material` / `CaveDensity` / `DepositZone` / Voxel / Chunk | 结构扫描（无写入 API 路径）+ 开关对照 |
| **EC16** | **可关闭**：关闭 Ecology ⇒ 世界逐体素与今天一致；开启 Ecology 也**不得**改变任何体素 | 开启/关闭两态体素快照逐体素比较（差异必须为 0） |
| **EC17** | 不新增 `VoxelType`（体素状态集合冻结） | 结构性检查 |
| **EC18** | 零修改：VoxelCore / WorldGeneration / Geology 实现 / Runtime / Streaming / Mesh / View / Bootstrap 的 SHA 不变（若必须改动，走显式授权 + 级联重钉） | 文件哈希比对 |

## 附录 D：未来扩展方向

> 本附录只列**方向与前提**，本轮不实现任何一项。

| 方向 | 说明 | 前提（硬性） |
|---|---|---|
| **D-1 动态生态（演替 / 扩张）** | 群落随"时间"变化 | 独立规范；确定性可证；**可关闭**（回退静态 V1）；不得回写环境参数（`ED5`/`ED6`） |
| **D-2 物种迁移 / 季节** | 生物随季节或周期移动 | 周期必须由**确定性参数**（世界时间戳语义）驱动，不得使用 `Time`/`DateTime`；必须可关闭 |
| **D-3 食物链 / 种群** | 类别之间的依赖与数量约束 | 只能作为**对象侧**（未来系统）的内部逻辑；不得让生态层反向影响参数与群系 |
| **D-4 生态事件** | 灾害、爆发、灭绝等 | 属未来的事件系统；事件若要影响环境，必须作为**新的来源类型**在**上游规范**中定义（`EP4` 同构），不得由生态回写 |
| **D-5 更多生态类别** | 例如真菌、共生、稀有物种 | 只新增**类别与规则**，不得新增体素类型、不得改变既有判定 |
| **D-6 生态与结构联动** | 结构（遗迹/聚落）影响生态 | 结构属未来系统；联动只能是"结构向 Ecology 提供**只读**附加条件"，仍不得回写 |
| **D-7 可解释性工具化** | 导出判定链、可视化候选 | 只读工具；不得改变任何生成结果 |
| **D-8 生态参数外露** | 把阈值/密度参数作为世界创建选项 | 必须显式、确定性、可关闭；默认值必须还原 V1 行为 |

**共同前提（所有扩展）**

1. 遵守 `E-1`–`E-3`（生态是结果 / 不短路 / 不改世界）；
2. 保持 `EC1`–`EC18` 全部成立（确定性、因果正确、无反向依赖、无世界状态修改）；
3. 更新本文档的附录 B/C，并在实现规范中登记；
4. 若必须触及被 SHA 冻结的文件，走**显式授权 + 级联重钉**流程；
5. 不得以"生态需要"为理由新增体素类型、修改 VoxelCore、修改 Geology 实现或修改上游规范。
