# Region Source Candidate Generation — Minimal Design（Phase 3.1.13 · 首次候选生成最小设计）

> **文档性质**：**最小设计申请（Minimal Design Request）**，只读检查 + 最小设计 + 缺口登记。**本轮不写任何代码**。
>
> **已批准的边界（G-1/G-2/G-3）**：① Region 层承担候选生成职责，产物为 `RegionSourceCandidate`；② `Kind` 用整数码，映射须登记在 `Region_Design.md` 指定位置；③ 首次实现**只承诺确定性生成**，**不承诺**完整枚举或有界枚举。`G-4`/`G-5`/`G-6` **本阶段不触发**（不引入上限、达限截断、新失败路径）。
>
> **原始起草轮次的工作范围（历史记录）**：当时只新增本文档，不修改 C#、场景、Prefab 或既有契约。该范围不是永久禁改规则。本文档列出的 `MS-1`–`MS-4` 仍是候选生成具体实现的真实决策门槛；未批准前，不得自行发明 `Kind` 码值、`Epoch`/`Ordinal` 保留值或参数登记语义。后续实现可按任务授权修改现有代码/契约，但不得创建平行参数系统，也必须遵守本文列出的输入边界与确定性要求。
>
> **【历史语境（后续轮次追加，不改本文历史结论）】** §2.2 的「只读代码核查」是 **Phase 3.1.13 时点**的代码状态，其中关于地形派生量的表述现已过时，按**历史记录**保留：`Elevation` 不再是「域标签整数哈希 `Range(seed, 1, ParameterId, position, 128)`」，现为**只读转发** `HeightFunction.GetTerrainHeight(position.X, position.Z, settings)`；`Ocean` 不再是「`Elevation < 64`」，现为 `OceanRule` 严格比较 `elevation < settings.SeaLevel`，其中 `SeaLevel` 是**世界生成配置**（登记默认值 `WorldGenerationSettings.DefaultSeaLevel = 64`）。上文所列 `MS-1`–`MS-4` 决策门槛与 §8 停止声明**仍然有效**，本标注不解除任何约束；§8 停止声明中提及的「`Elevation` 占位哈希」「`SeaLevel` 占位默认值」同样指该时点的占位链，**停止声明继续有效**。

## §1 结论（先给判定，再给依据）

| 问题（本轮任务书） | 判定 |
|---|---|
| 确定性是否可支持？ | **可以**：`Seed` + `Position` + 显式参数的纯函数规则在契约内可直接成立（`RA21` **L171**；`RS2` **L200**；`RA25` **L175**） |
| 是否有现成规则可产生**有意义**的候选数据？ | **不充分**：契约指定的自然来源输入 **`WorldSkeleton`（Phase 1）在代码中不存在**（见 §3.2），History 事实亦未实现 |
| `Kind` 登记是否缺依据？ | **部分缺**：类别名称与语义有原文（§3.2 **L206–L241**）、族→域有原文（`RA116` **L415**）；**整数码值本身无原文**，且 **`Region.Relic`=12 无对应来源类别** |
| 是否**不可避免地**要引入未批准的空间语义 / 半径规则 / 历史派生规则？ | **不需要**（§7 逐项论证）；但需要 4 项**登记/授权**（§8 `MS-1`–`MS-4`） |
| 因此能否进入实现？ | **不能**：按停止条件，先取得 `MS-1`–`MS-4` 的最小决策；**不得**用占位候选、随机数据或未批准的坐标/半径假设制造"可运行实现" |

**一句话**：**确定性在形式上成立，但"有意义"的来源输入（骨架事实）在代码中缺失，`Kind` 码表与 4 项登记亦未落地 → 本轮停止在"设计 + 缺口登记"，不进入实现。**

## §3 现有规则是否足以产生"有意义"的候选（Q2）

### 3.1 已有的、可复用的确定性与派生原语（只读核查，均为代码事实）

| 原语 | 位置 | 用途（首次生成） |
|---|---|---|
| `WorldParameterHash.Hash(seed, domainId, parameterId, position)` → `uint` | `WorldParameterHash.cs` **L44** | 锚点判定 / 选择通道的整数混合 |
| `WorldParameterHash.Unit(...)` → `float [0,1)` | **L62** | 字段带状取值（强度 / 尺度） |
| `WorldParameterHash.Range(...)` → `int [0, exclusiveMax)` | **L71** | 整数选择（类别选择、`Epoch`/`Ordinal` 槽位取值） |
| `WorldParameterHash.SkeletonDomainId = 1` | **L32** | **唯一既有域常量**；注意：`Region.*` 域为 **8–12**（`RA116` **L415**） |
| `RegionSourceCandidate`（9 存储成员，已实现） | `RegionSourceCandidate.cs`（3.1.11） | 输出载体 |
| 域必须参与哈希混合；**禁止复用保留域 `R-1`/`R-2`** | `RA117` **L416** | 规则必须使用**已登记的 Region 域**（8–12） |

> 说明：以上原语**足够**构造"随坐标变化、可跨进程复现、非随机"的候选值；它们**不**提供任何空间/几何语义。

### 3.2 "有意义"的判定（本轮关键）

| 读法 | 判定 | 依据 |
|---|---|---|
| **弱读法**：候选是 `(Seed, Domain, Position, 显式参数)` 的**非平凡确定性函数** | **可满足** | `RA21` **L171**；`RS2` **L200**；原语见 §3.1 |
| **强读法**：自然来源候选**来自骨架事实**（契约指定来源） | **不可满足** | `RA §3.1` **L152**（"自然来源（来自骨架事实）"）；`RABW5` **L139**；`PC125`/`PC127` —— 而 `WorldSkeleton` **无实现**（§2.2） |

**本轮结论**：可给出**弱读法**下的最小规则设计（§5，`【建议·未批准】`），但**不得**把它声称为"自然来源（来自骨架事实）"的合规实现；该差异属**必须由设计方裁决的最小决策**（§8 `MS-1`）。

## §5 确定性的保证方式（Q4）【建议·未批准】

### 5.1 规则形式（**只描述形式，不含算法与数值**）

| 要素 | 形式要求 | 依据 |
|---|---|---|
| 类型 | **纯函数**：`(WorldSeed, WorldCoordinate, 显式参数) → bool（是否锚点）+ 字段值` | `RA21` **L171**、`RS2` **L200** |
| 通道 | 每个用途使用**显式登记的 `parameterId` 通道**；同一域内不同用途**不得共用通道** | `RA117` **L416**（域参与混合）；通道登记见 `MS-4` |
| 域 | 只能使用**已登记的 Region 域 8–12**；**禁止**复用保留域 `R-1`/`R-2` | `RA116` **L415**、`RA117` **L416** |
| 随机性 | **禁止** `Random`/时间/帧序/玩家状态/加载顺序/全局可变状态 | `RA25` **L175**；`RA23` **L173** |
| 输入读取 | **禁止**读下游（Biome/Geology/Voxel/Mesh/Runtime）、`FinalState`、已生成内容 | `PC128` **L128**；`PC62` |
| 输出字段 | 9 个存储成员由输入确定性派生；`OriginRef`/`ReasonChainRef` 为**显式规则引用**（不得用魔法常量） | `RA §3.2` **L164–L165**；3.1.10 `AP-7`/`AP-8` |
| 空间语义 | **不使用**任何 `Extent`/连通性/空洞/边界/锚点-范围关系；`Position` 只作输入与输出锚点 | `RID57`–`RID63` **L156–L162** 保持未决 |
| 完备性 | **不承诺**覆盖完备/有界；不做上限与截断 | `G-3`（已批准）；`RA128` **L446** 不据此声称已满足 |

## §6 不保证完整性的声明方式（Q5）【建议条文·未批准】

建议在实现轮的类型/文件头与交付报告中**逐字**声明（依据 `G-3` 已批准 + `RA129` **L447** 的"覆盖完备"**未**被满足）：

> **本实现只承诺：给定 `(Seed, Domain, Position)` 与显式参数，输出是确定的、可复现的、无随机性的候选数据。**
> **本实现不承诺**：覆盖完备、无遗漏、有界可枚举、单点影响集合的正确规模、上限或截断语义。
> 因此**不得**据此实现或声称满足 `RA17` **L138** / `RA128` **L446** / `RS3` **L201** / `RO7` **L541**；上述条款的验收须等待独立的"Region 枚举契约"。

同时禁止的自我表述：不得把本实现称为"Region Source 枚举""影响集合求值""完整性验证"，也不得让 `RegionPipeline` 的既有语义因此改变（`RA75` **L308**/`RA76` **L309** 不变）。

## §7 是否不可避免地需要未批准的空间语义 / 半径规则 / 历史派生规则（Q6）

| 项 | 是否需要 | 理由 |
|---|---|---|
| **空间语义**（连通性 / 空洞 / 边界突变 / 锚点-范围 / 状态相关性 / 主导区域，`M-8`） | **不需要** | 首次规则只做"点判定 + 字段派生"，不定义 `Extent`、不做范围判定；`RID57`–`RID63` **L156–L162** 保持未决，`RID64` **L163** 禁止单方面裁决 |
| **半径规则**（`RA22` 半径归属 / 衰减形状 / 搜索半径） | **不需要** | `Radius` 仅作为**承载值**（`AP-5` 已批准 `float`，单位/最大值仍未决）；不定义衰减（`RA72` **L294**）、不做空间运算、不解释为搜索半径；`RA22` **L172** 归属继续推迟（3.1.12 `D-4`） |
| **历史派生规则**（事件 → 候选映射） | **不需要** | 首次实现**不**做历史来源；`Epoch`/`Ordinal` 走 `RA11` **L127** 的**显式保留值**（"自然来源不含纪元信息"路径）——但**保留值编码未定** → `MS-3` |
| **骨架事实** | **需要**（契约指定）**但当前不可用** | `RA §3.1` **L152**、`RABW5` **L139**、`PC125`/`PC127`；`WorldSkeleton` 无实现 → `MS-1` |

**净结论**：**不引入**任何未批准的空间语义、半径规则或历史派生规则；**但**"骨架事实"这一契约指定输入缺失，必须由 `MS-1` 裁决。
