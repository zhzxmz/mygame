# Region Source Data Carrier Design（Phase 3.1.4 · M-1 契约核验与设计）

> **文档性质**：**契约核验 + 最小载体设计提案（Design Proposal）**。仅针对 M-1「Region 来源数据载体」。
> **批准状态**：M-1 **已被批准进入本阶段（核验与设计准备）**；**尚未批准新增生产代码或最终类型实现**。
>
> **本轮边界（已遵守）**：**不新增 / 修改 / 删除**任何 `.cs`、`.asmdef`、`.meta`、Scene、Prefab、测试；**不修改**任何契约与 Phase 3.1.0–3.1.3 文档；**不实现**候选生成 / 来源枚举 / 空间索引 / 贡献求和 / 参数合成 / 缓存；**不填写**上限 A/B 数值；**不裁决** `RID57`–`RID63` 等空间语义；**不引入**新的身份字段、参数分量或因果边；**不以临时常量或伪数据冒充真实来源数据**；不触碰 Legacy Terrain 与历史工作区。
>
> **标签体系（全文只用这三类）**：`【契约已冻结】`（条款 + 行号可核） · `【设计提案】`（本轮提出、**尚未生效**） · `【仍需批准】`（须设计方裁决或契约升版本）。

## §1 契约字段逐项映射表（核验内容 1 + 2）

### 1.1 字段存在性与语义（原文取自 §3.2 `L158`–`L165`）

| 契约字段 | 契约原文（含义 / 约束） | 是否【契约已冻结】 | 数据语义是否明确 |
|---|---|---|---|
| **`Kind`** | "来源类别（自然子类 / 魔法子类 / 圣 / 腐化子类）"；约束："`Region_Design.md` §3.2；子类枚举**不得**由本文档新增"（`L158`） | **是**（字段必需） | **部分**：类别**体系**有权威（`Region_Design.md` §3.2，`L206`–`L242`），但**本契约不复制清单**，具体子类集合需引用该文档 |
| **`DomainId`** | "该候选的确定性域"；约束："`WorldParameter_Contract.md` §6.4（8–12）"（`L159`） | **是** | **明确**：必须是已登记的 Region 域（`RA10` `L126`：未登记域不得使用；`RA116`） |
| **`Position`** | "锚点世界坐标"；约束："必须是世界坐标；不得是 Chunk 局部坐标"（`L160`） | **是** | **明确**（世界坐标；与 `RA12` `L128` 的 `CanonicalPosition` 量化关系见 §1.3） |
| **`Strength`** | "强度倾向"；约束："显式标量；范围由 Region 规则声明，且必须落在契约允许域内"（`L161`） | **是** | **部分**：必须显式；**取值范围未冻结**（"由 Region 规则声明"） |
| **`Radius / Scale`** | "影响尺度"；约束："世界单位；必须 `> 0`"（`L162`） | **是** | **部分**：`> 0` 明确；**形状/衰减函数未定义**（`RA72` `L294` 只约束"紧支撑 + 单调不增 + 边界连续趋于 0"） |
| **`Epoch / Ordinal`** | "时间序位"；约束："来自 `History`；自然来源用显式保留值（`RA11`）"（`L163`） | **是** | **明确**：来自纪元体系（`RA11` `L127`：`HE1`–`HE4`；自然来源必须用**显式保留值**，不得省略） |
| **`OriginRef`** | "原因引用（历史事件引用 / 自然规则引用）"；约束："用于解释链（`WE*`）；**必须可解析**"（`L164`） | **是** | **部分**：可解析性是硬要求；**解析目标形态未定义** |
| **`ReasonChainRef`** | "可解释链引用"；约束："供 `WorldQuery_Design.md` §6 解释使用"（`L165`） | **是** | **部分**：用途明确；**形态未定义** |

### 1.2 字段类型 / 依赖 / 空间假设（核验内容 2 的后半）

| 契约字段 | 数据类型是否已由契约明确 | 字段间依赖或引用关系 | 是否隐含**未批准**的空间假设 |
|---|---|---|---|
| **`Kind`** | ✘ **未明确**（枚举？整数码？→【仍需批准】） | 与 `DomainId` 存在**松散对应**（来源类别 ↔ 域，`RA10` `L126`；但契约未规定二者必须一一对应） | **否**（非空间字段） |
| **`DomainId`** | ◐ **基本明确**（整数标识：`PZ10` "32 位整数标识"；登记值 `8`–`12`） | 被 `RegionKey` 复用（`RA9` `L125`：`RegionKey = (DomainId, Epoch, Ordinal, CanonicalPosition)`） | **否** |
| **`Position`** | ✘ **未明确载体类型**（既有代码有 `WorldCoordinate`：整数三元组） | 与 `RA12` `L128` 强相关：`CanonicalPosition = Quantize(Position, QuantumVoxels)`（`QuantumVoxels` 显式参数，默认 `1`） | **弱**：锚点概念本身**已由契约登记**（`RA12`）；但"锚点是否必须落在范围内"**未决**（`RID61` `L160`）→ 载体**只能存锚点，不得据此推断范围** |
| **`Strength`** | ✘ **未明确**（浮点标量？宽度？） | 与规模/上限相关（`RA27` `L177`：候选集合规模须受显式上限约束） | **否**（强度是标量倾向，非空间量） |
| **`Radius / Scale`** | ✘ **未明确**，且**写法歧义**：一个字段（`Radius` 与 `Scale` 同义）还是两个字段？（【仍需批准】） | 与 `RA22` `L172`（"给定世界坐标**与半径**"）相关；与 `RA72` `L294`（贡献形状）相关 | **是（需谨慎）**：语义边界未定（`RA72` 只约束形状性质）→ 载体**不得**把它解释为"已经确定的影响函数"；连通性/空洞未决（`RID57` `L156`/`RID59` `L158`）→ 载体**不得**表达形状 |
| **`Epoch / Ordinal`** | ✘ **未明确**（两个整数字段？复合结构？） | 直接来自 `RA9` `L125` 的键维度；受 `RA11` `L127`（保留值）与 `RA29` `L179`（多纪元候选同时成立、禁止覆盖）约束 | **否** |
| **`OriginRef`** | ✘ **未明确**（句柄形态） | 与解释链（`WE*`）相关；受 `RA28` `L178`（缺失可解释）约束 | **否** |
| **`ReasonChainRef`** | ✘ **未明确** | 供 `WorldQuery_Design.md` §6 解释；与 `OriginRef` 的关系**契约未定义**（【仍需批准】） | **否** |

### 1.3 三类信息的分层（核验内容 3）

| 类别 | 属于该类别的 §3.2 字段 | 说明（含禁止） |
|---|---|---|
| **① 来源自身的数据** | `Kind`、`DomainId`、`Position`（锚点）、`Strength`、`Radius / Scale`、`Epoch / Ordinal` | **仅描述"原因"**：`RA24` `L174` 明文"候选只描述**原因**"，**不得**携带目标结果（如"这里应该长成魔法森林"） |
| **② 影响规则（对空间位置或环境参数的作用方式）** | **无字段**——属 Region 规则层 | 贡献形状由 `RA72` `L294`（紧支撑/单调不增/边界连续）与 `RBD1`/`RBD3` 约束；**具体函数形式未冻结**（"形状本身属 Region 规则"，§2.2 `L116`） |
| **③ 枚举 / 索引 / 缓存 / 性能控制的辅助数据** | **无字段**——**不属于候选** | 规模上限（`RA27` `L177`、`RA47` `L223`）约束的是**集合**而非候选；枚举规则（`RA129` `L447`）、透明缓存（`RA138` `L466`）均属其它职责；`RA26` `L176` 明确"候选在提交时**不做空间合并**"（合并只在采纳阶段 §4.2） |

> **结论**：§3.2 的 8 个字段全部属于类别 ①；**类别 ② 与 ③ 都不是候选字段**（不得塞进载体）。这条界线同时排除了"把上限、搜索半径、排序键、缓存索引写进载体"的做法。

### 1.4 §3.3 硬性约束对载体的直接约束（`RA21`–`RA30`，`L171`–`L180`）

| 条款 | 行号 | 对载体的约束（逐条） |
|---|---|---|
| `RA21` | 171 | 候选是 `(Seed, Domain, Position)` 的**确定性函数** → 载体**不需要** `Seed` 字段（`Seed` 是函数输入，`§3.2` 字段表中亦无此字段） |
| `RA22` | 172 | 候选必须**可局部枚举** → 枚举能力属**规则/入口**，不是载体的字段 |
| `RA23` | 173 | 载体**不得**携带下游产物（Biome / 生态候选 / 资源判定 / 体素值 / Chunk 状态） |
| `RA24` | 174 | 载体**不得**携带"目标结果"（只描述原因，`PT13`/`RC1`） |
| `RA25` | 175 | 载体**不得**依赖玩家状态 / 加载顺序 / 帧序 / 时间 / `Random` → 不得出现"观测时刻""随机种子状态"等字段 |
| `RA26` | 176 | 载体表示**提交阶段**的候选：**不做空间合并**（合并只在采纳阶段发生） |
| `RA27` | 177 | 规模上限约束**集合**（`HN9`/`HN10`；`RO7`）→ 上限**不是**载体字段 |
| `RA28` | 178 | 缺失必须**可解释** → 载体不负责解释；解释能力由解释链（`OriginRef` / `ReasonChainRef`）承载 |
| `RA29` | 179 | 多纪元候选**同时成立**，禁止覆盖 → 载体**不表达**"覆盖/优先级"（也呼应 `RAX-10` `L654` 对覆盖语义的禁令） |
| `RA30` | 180 | 不得由结果反推候选 → 载体**不得**包含任何"结果派生的判别位" |

## §2 现有类型职责对照（核验内容 4）

### 2.1 三个既有 Region 类型（只读核验，代码位置见 §8）

| 现有类型 | 字段（行号） | 语义层级 | 能否承载候选字段 | 判定依据 |
|---|---|---|---|---|
| `RegionIdentity`（`RegionIdentity.cs`） | `regionId`/`regionDomain`/`regionSource`/`regionExtentReference`/`explanationTag`（**L36–L40**） | **采纳后的身份**（`RegionKey` 派生：`RA9` `L125`、`RA13` `L129`） | **不能** | 字段闭集（`RRD14` `L69`、`RRD15` `L70`、`RID45`）；`regionExtentReference` 明确"**只是引用**，不是几何/包围盒/体素范围"（`RID43`）；且候选是**采纳前**数据（`RA26` `L176` 的合并发生在采纳阶段）→ 与身份是**上下游**关系而非同一职责 |
| `RegionContext`（`RegionContext.cs`） | `identity`/`regionSourceReference`/`explanationTag`/`qualificationMask`/`contextVersion`（**L41–L45**） | **一个已成形 Region 的解释层**（`RRD21`–`RRD25` `L86`–`L90`） | **不能** | 上下文承载"身份 + 解释/资格/版本"，字段白名单 = 既有组成的映射（`RRD15` `L70`）；把候选集合塞进去等于改字段闭集 → 需升版本（本轮不主张） |
| `RegionModifier`（`RegionModifier.cs`） | 6 个 `float` 分量（**L38–L43**） | **单个区域的修正贡献**（`RRD26` `L96`；`RA67` `L284`） | **不能**（字段完全不同） | 分量集合封闭；`Elevation`/`Ocean`/`Balance` 不在其中（`RA69` `L286`、`RA70` `L287`） |

### 2.2 职责重叠检查

| 检查项 | 结论 |
|---|---|
| 载体 vs 身份是否重叠？ | **不重叠**：候选是**输入侧**（§3 标题 `L145`；`RA26` `L176`），身份是**采纳后的键**（`RA9`–`RA13` `L125`–`L129`）。二者共享部分键维度（`DomainId` / `Epoch` / `Ordinal`），但那是**数据流上下游**而非职责重复 |
| 载体 vs 上下文是否重叠？ | **不重叠**：上下文解释"已成形 Region"（`RRD21` `L86`）；候选尚未成形 |
| 载体 vs 修正量是否重叠？ | **不重叠**：修正量是区域产生的影响量（`RRD26` `L96`），候选是原因记录（`RA24` `L174` 只描述原因） |
| 现有代码是否已有可复用的"来源"载体？ | **无**：全 V2 目录 `RegionSourceCandidate` / `SourceCandidate` / `IRegionSource` 命中 **0**；`List<` / `IEnumerable` / `HashSet` / 数组 `[` / `foreach` 命中 **0**；`Strength` / `Radius` / `Anchor` / `BoundingBox` 命中 **0**（详见 §8 代码扫描） |
| 现有占位链是否等价于来源数据？ | **否**（明确声明）：`RegionDetermination` 用 `WorldParameterHash.Hash(seed, 占位域 8, 通道, position)` **直接构造身份**（`RegionDetermination.cs:84`），来源引用是常量 `1L`（`:63`）→ 它是**占位身份**，**不是**来源数据，**不得**据以宣称已有来源载体 |

## §3 最小载体候选设计（**仅提案**）

### 3.1 设计原则（逐项依据）

| # | 原则 | 依据 |
|---|---|---|
| **P-1** | **纯数据载体**：只承载 §3.2 的 8 个字段槽位，**无算法** | `RA24` `L174`（只描述原因）；§3.2 标题"**必需字段（概念）**" `L154` |
| **P-2** | **字段零新增**：不添加 `Seed`、上限、搜索半径、排序键、派生哈希 ID、集合、生命周期字段 | §3.2 字段表 `L158`–`L165`；`RA21` `L171`（Seed 为函数输入）；`RA27` `L177`（上限属集合）；`RA15` `L131`（派生标识不得作规则输入/排序键） |
| **P-3** | **不承载集合**：一个载体 = 一个候选；集合/枚举属其它职责 | `RA26` `L176`（提交阶段不做合并）；`RA29` `L179`（多纪元候选并存由集合表达，不由单载体表达） |
| **P-4** | **不表达影响规则**：`Radius / Scale` 仅作为"尺度字段"承载 | `RA72` `L294`（形状性质约束在规则层）；§2.2 `L116`（"形状本身属 Region 规则"） |
| **P-5** | **不表达空间形状/边界/连通性** | `RID57` `L156`（连通性未决）、`RID59` `L158`（空洞未决）、`RID61` `L160`（锚点与范围关系未决） |
| **P-6** | **不表达优先级/覆盖** | `RA29` `L179`；`RAX-10` `L654`（覆盖语义 = 缺陷）；`RA63` `L268`（交换律）、`RA66` `L271`（无放大反馈） |
| **P-7** | **不校验、不钳制、不归一化**（构造只赋值） | 值域由 Region 规则声明（§3.2 `L161`）；钳制属合成侧（`WSC12` `L94`、`RA64` `L269`） |
| **P-8** | **不缓存、无生命周期**：载体不是跨帧状态 | `RA138` `L466`（缓存须透明）；`RA16`（Region/候选不是存活对象，`RRD44` 同族纪律） |
| **P-9** | **不复制来源类别清单、不复制域表** | §3.2 `L158` 备注"子类枚举**不得**由本文档新增"；`RA10` `L126`（域权威 = §6.4）；已登记纪律 `WPS52`/`WPS73`（占位/复制清单的既有禁令） |

## §6 M-1 完成后为什么**仍不能**声称"完整、确定性、有界"的枚举已实现（核验内容 7）

| 属性 | M-1 完成后是否成立 | 原因（条款） |
|---|---|---|
| **确定性** | **形式成立、实质不成立** | 载体本身无算法，不产生结果；而"空集合"的确定性是**恒真**的——契约明确要求防"永远空集"的假通过：`RA126` `L435`"验收必须能证明**采纳确实发生**（防止'永远空集'的假通过）"，`RA125` `L434` 要求非平凡性 |
| **有界** | **不成立** | 上限**不是**载体字段（`RA27` `L177`），且数值未定（`RA47` `L223` 要求显式参数化；数值属实现规范 `§13.2` `L567`）→ 无集合、无上限，谈不上"有界" |
| **完整** | **不成立** | "覆盖完备"判据未定义（`RA129` `L447`），且依赖空间语义未决项（`RID57`–`RID59` `L156`–`L158`、`RID61` `L160`） |
| **枚举本身** | **不存在** | 无生产者（M-2）、无枚举入口（M-3）：Region 侧当前仅 3 个公开方法（`Determine` ×2、`ResolveContext`），全 V2 目录无任何集合与迭代（§8 扫描） |
| **与参数的关系** | **仍为零** | 参数侧 `Modifier` 恒为 `ZeroRegionModifier`（`WorldParameterEvaluator.cs:46`/`:99`），`RegionModifier` 无参数侧消费者；关闭 Region 的退化等价仍成立（`WSC22` `L129`） |

> **一句话**：M-1 只是把"来源长什么样"**写清楚**；它**不生成、不查找、不限制、不合成**。因此 M-1 之后能声称的只有："**候选的数据形状已冻结**"，不能声称"枚举已实现"。
