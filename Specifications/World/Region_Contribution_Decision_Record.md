# Region Contribution Decision Record（Phase 3.1.3 · 决策登记与接口可行性检查）

> **文档性质**：**决策登记记录（Decision Record）+ 接口可行性检查（Feasibility Check）**。把 Phase 3.1.0–3.1.2 的审查成果**分状态登记**，并只读核验"现有代码能否支撑独立的 Region Contribution 枚举职责"。
>
> **本轮边界（已遵守）**：只新增本文件；**不修改**任何已有代码 / 契约 / 测试 / Scene / Prefab / `.meta`；**不修改** Phase 3.1.0/3.1.1/3.1.2 三份文档；**不确定上限数值**；**不新增接口 / 类 / 方法**；**不实现**枚举、求和或参数接线；**不擅自解决**空间范围、连续性、边界、达限策略等未决问题。
>
> **标签体系（全文只用这五类）**：
> `【契约已冻结】`有条款 + 行号可核 · `【代码现状】`有文件 + 行号可核 · `【审查推断】`由前两者推导 · `【推荐方案·未批准】`仅供设计方选择 · `【待裁决】`须批准或升版本。
>
> **一句话结论**：
> **架构方向（身份单值 + 独立枚举职责 + WorldState 合成）可由现有契约直接确认；但"枚举"本身在代码中**完全没有载体**——没有来源类型、没有任何集合或迭代、没有空间尺度数据。缺的不是算法技巧，而是"来源数据载体"这一件纯数据工件（它是唯一不依赖任何未决项的最小缺失项）。**

## §2 现有代码能否支持贡献枚举（只读核验）

### 2.1 六问逐答

#### 问题 1：当前是否存在可枚举的 Region Source 集合？

| 项 | 结论 |
|---|---|
| **【代码现状】** | **不存在**。全 V2 目录扫描：`RegionSourceCandidate` / `SourceCandidate` / `IRegionSource` / `CandidateSet` 命中 **0**；`List<` / `IEnumerable` / `HashSet` / 数组下标 `[` / `foreach` 命中 **0**（**整个 V2 目录没有任何集合类型、也没有任何迭代语句**）。全 `Assets` 范围内也没有名为 `RegionSource` 的类型（命中文件数 **0**） |
| **【契约已冻结】** | 契约**要求**该集合存在：`Region_Architecture_Contract.md` §3.2 给出候选必需字段表（**L158–L165**：`Kind`/`DomainId`/`Position`/`Strength`/`Radius / Scale`/`Epoch / Ordinal`/`OriginRef`/`ReasonChainRef`）；`RA21`–`RA30`（**L171–L180**）给出候选硬性约束；`RS3`（`Region_Design.md` **L201**）要求"`RegionSource` 必须**可局部枚举**：给定任意世界坐标，无需遍历全世界即可确定其影响" |
| **判定** | **"当前代码没有实现"，而不是"契约不允许实现"** |

#### 问题 2：`RegionIdentity` / `RegionContext` 的字段是否足以确定"一个坐标受到哪些来源影响"？

| 项 | 结论 |
|---|---|
| **【代码现状】** | `RegionIdentity` 仅 5 个标量字段：`regionId`（**L36**）、`regionDomain`（**L37**）、`regionSource`（**L38**，`long` 引用句柄）、`regionExtentReference`（**L39**，`long` 引用句柄）、`explanationTag`（**L40**）；`RegionContext` 仅 5 个字段：`identity`（**L41**）、`regionSourceReference`（**L42**）、`explanationTag`（**L43**）、`qualificationMask`（**L44**）、`contextVersion`（**L45**）。二者**没有任何空间尺度或位置数据**：`Strength` / `Radius` / `Anchor` / `BoundingBox` 在 V2 目录命中 **0**（`Scale` 的 2 处命中是 `RegionModifierDetermination.cs` 的**数值缩放常量** `PlaceholderScale`，非空间尺度；`Position` 的 3 处是参数侧 API 的坐标形参） |
| **【契约已冻结】** | 空间数据**不允许**放进这两个类型：`RID43` 明确 `RegionExtentReference` 是"**只是引用**，不是几何/包围盒/体素范围"；`RRD48` 禁止 Voxel 范围数据；`RRD15`（**L70**）要求字段白名单 = 既有组成的映射（**不新增字段**）；`RRD14`（**L69**）声明三类逻辑聚合构成字段闭集 |
| **判定** | **不足以**。身份/上下文只能表达"某区域的引用"，**无法**回答"哪些来源影响该坐标"；所需的几何/尺度数据在契约上属于**候选（§3.2）**，**不允许**塞进身份/上下文 |

#### 问题 3：当前是否存在从坐标反查影响来源的机制？

| 项 | 结论 |
|---|---|
| **【代码现状】** | **不存在**。Region 侧只有 3 个公开入口：`RegionDetermination.Determine`、`RegionModifierDetermination.Determine`、`RegionPipeline.ResolveContext`（均为单区域链，无查询/枚举入口）。`RegionDetermination` 的占位实现**直接由哈希构造身份**：`long regionId = WorldParameterHash.Hash(seed, PlaceholderRegionDomain, IdentityChannel, position);`（**L84**），来源引用是**常量** `PlaceholderSourceReference = 1L`（**L63**）——它**从不查询任何来源** |
| **【契约已冻结】** | 反查机制是**必需能力**：`RA17`（**L138**）"任意世界坐标必须能独立求出'该点受哪些 Region 影响、各修正多少'"；`RA127`–`RA130`（**L445–L448**）；`RS3`（**L201**） |
| **判定** | **"当前代码没有实现"，不是"契约不允许"**；且现状连"单来源的真实反查"都没有（是占位哈希） |

#### 问题 4：若不存在，枚举算法还缺少哪些数据或规则？

| # | 缺失项 | 类别 | 依据（契约 / 代码） |
|---|---|---|---|
| **M-1** | **来源数据载体**（候选类型：`Position` / `Radius` / `Scale` / `Strength` / `DomainId` / `Kind` / `Epoch` / `Ordinal` / 原因引用） | 数据 | 契约字段表 `RA §3.2` **L158–L165**；代码 **0 命中** |
| **M-2** | **候选的产生规则**（自然来源规则 / 历史事件 → 候选映射） | 规则 | `RA §3.1`（**L149–L152**）；`Region_Design.md` §3.2；**代码无实现** |
| **M-3** | **局部枚举规则**（显式、覆盖完备、无重复、确定性） | 规则 | `RA129` **L447**（"例如显式量化网格 + 半径判定"是**示例**，非强制形式）；**代码无实现** |
| **M-4** | **显式上限**（数值与登记位置） | 参数 | `RA47` **L223**、`RA65` **L270**、`RA130` **L448**、`RO7` **L541**；数值属实现规范（`§13.2` 第 3 项 **L567**） |
| **M-5** | **达限策略** | 语义 | `RA45` **L216** 允许"上限截断"作为全序用途，但策略本身未规定 |
| **M-6** | **完整性判据** | 语义 | `RA129` **L447** 要求"覆盖完备"，判据未定义 |
| **M-7** | **失败语义** | 语义 | 契约未定义（`PM33` **L92** 不直接覆盖枚举结果） |
| **M-8** | **空间语义前提**（连通性 / 空洞 / 边界突变 / 锚点位置） | 未决 | `RID57`–`RID59`/`RID61`（**L156–L158/L160**） |

#### 问题 5：能否**在不引入**新的空间范围、锚点、边界或连续性假设的前提下，实现**完整且有界**的枚举？

| # | 判定 | 说明 |
|---|---|---|
| **Q5-a** | **不能（在"完整且有界"的要求下）** | 三个原因：① 完整性判据（M-6）与空间前提（M-8）未定，任何"完整"的定义都需要新假设；② 达限策略（M-5）未定，"有界"与"完整"的冲突无契约解法；③ 候选的产生规则与数值（M-2/M-4）在契约中属实现规范，实现即等于自行决定 |
| **Q5-b** | **可以（在"零空间假设"的退化形态下）** | 今天已存在的**单来源退化路径**（`RegionPipeline.ResolveContext` → `RegionModifierDetermination.Determine`，**L60–L63** / **L69**）不引入任何空间假设（它连 `Extent` 都只是常量引用 `1L`）。但它**不是枚举**，也不满足 `RA17`/`RA128` |
| **Q5-c** | **可以（先做纯数据工件）** | 可先落地 **M-1 来源数据载体**：其字段清单已由 `RA §3.2`（**L158–L165**）冻结、且不依赖任何未决项；它**不含算法**、不引入空间假设（只是承载字段）→ 属【推荐方案·未批准】 |
| **Q5-d** | **明确不成立的一种乐观读法** | 不能把"占位哈希身份"当作"来源枚举"的替代（`RegionDetermination` **L84** 是哈希直接构造，既无来源、也无范围）。这就是 Phase 3.1.0 登记的 `P0-1`（把单区域修正误当该点全部修正） |

#### 问题 6：如果无法实现，最小缺失项是什么？

| 排序 | 最小缺失项 | 为什么是"最小" | 依赖的未决项 |
|---|---|---|---|
| **1** | **M-1 来源数据载体**（纯数据，字段清单已冻结） | 唯一**完全不依赖**未决项的一项：字段由 `RA §3.2` **L158–L165** 定义，且不引入空间假设（值来源另行登记） | **无** |
| **2** | **M-4 上限的数值 + 登记位置** | 无上限则"有界"无法成立（`RA47` **L223** 要求显式参数化） | 需实验（§6）+ 批准（配置 Owner 缺口 `B-2`） |
| **3** | **M-3 枚举规则形式** | 决定"如何找相关来源"；契约只给示例（`RA129` **L447**） | 需批准（形式属实现规范） |
| **4** | **M-5/M-6/M-7 三项语义**（达限 / 完整性 / 失败） | 决定"边界处行为"；三者互相关联，必须一起定 | 需批准；M-6 还依赖 M-8 |

## §3 保留原则（7 条）及其状态
